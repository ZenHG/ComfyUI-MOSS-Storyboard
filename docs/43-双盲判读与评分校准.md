# 43 · 双盲判读与评分校准（G7 的 L4 层）

> 定位：第一轮 G7（历史记录（git 历史））证明了「账本→成品保真度」可以机检，
> 但**证明不了「反推准不准」**——事实准确率、幻觉、谁更可靠，仍然只有代理目检这一个软证据。
> 本文把「效果」结论变成**可复现的判读流程**：双盲判读 + 一致性门槛 + 评分校准 + 三档结论。
>
> 工具：`tools/g7_adjudicate.py`（`packet` / `merge` / `calibrate`）；
> 单测：`tests/test_g7_adjudicate.py`；运行产物：`out/g7/adjudication/`（`out/` 不入库）。
> 本文不写本机盘符/用户名/内部沟通叙事；结论区分「已验证 / 未验证」。

---

## 0. 一句话与三条硬纪律

**先证明判读本身可靠，再拿判读比模型。** 判读不可靠（一致性 κ < 0.6）时，唯一允许的结论是
「样本不足」，不是「谁更好」。

三条纪律（都写进了工具，不靠人记）：

1. **双盲**：两名判读者互相看不到对方的结论，**也看不到机检结论**；判读包里只放
   图 + caption + IR 实体表 + 候选事实，机检的 binding/覆盖率/pass-fail 一律不进包。
2. **AI 判读必须标注**：判读者是 AI 时，结果文件必须带 `ai_label: "AI 判读，不是人类"`，
   否则 `merge` 拒绝合并。人类判读尚未做，任何结论只能标 AI 证据等级。
3. **三档结论**：`显著差` / `无显著差异` / `样本不足`，**永不输出「更好」**。
   一致性不达标 → 直接落「样本不足（判据不足）」。

## 1. 判读单元

### 1.1 事实（claim）

每图每模型 **3–9 条可核事实**，来自模型产出的 IR（caption 由 IR 渲染，判的是「caption 的
断言 vs 图」）。类别与抽取字段：

| 类别 | IR 来源 | 典型断言 |
|---|---|---|
| 身份 | `kind` + `label` | 画面中存在人物/物体 X（label=…） |
| 年龄 | `age_years` | 实体 X 的年龄为 N 岁 |
| 发型 / 皮肤 / 面部 | `descriptors.hair/skin/face` | 实体 X 的发型为… |
| 表情 / 姿态 | `descriptors.expression/pose` | 实体 X 的姿态为… |
| 服装 / 道具 | `descriptors.wardrobe/props` | 实体 X 的服装为… |
| 颜色 / 材质 | `descriptors.color/material`、`typography.color` | 实体 X 的颜色为… |
| 空间 | `spatial.anchor` | 实体 X 位于画面左上/中央… |
| 图内文字 | `text_content` | 图内文字「…」逐字正确 |
| 光 / 媒介 | `lighting.key` / `style.medium` | 主光为… / 画面媒介为… |

每条事实必须满足：

- **图上可指证**（位置/对象/字串）；只判「图与断言是否相符」，不判「文笔好不好」；
- 三分类：`correct`（可核且对）/ `wrong`（可核但错、凭空编、把不可辨猜成具体）/ `unverifiable`
  （图无法判断，如焦距、被遮住的细节、不可辨文字）——**`unverifiable` 不计入准确率分母**；
- 一条事实 = 一个可核断言，不把一句话拆成多条，也不把多条并成一条。

### 1.2 整图幻觉

独立于事实条目的二分类：**present / absent**。

- `present`：存在图中看不到/无法支持的内容（编身份、编年龄、编物体、编文字、猜不可辨内容）；
- `absent`：图上的断言都有依据；**漏记不算幻觉**（漏记由「事实条数覆盖」另外暴露）。

### 1.3 判读对象指纹（防事后换包）

`packet` 为每个单元记录三份指纹并写进 `manifest.json`：

- `image_sha256`：判的那张图；
- `caption_sha256`：判的那份成品 caption；
- `ir_sha256`：生成 caption 的 IR（规范化 JSON 的 sha）。

判读结果只对这三份指纹负责；上游产物一改，旧判读结果不能复用（必须重发 packet）。

## 2. 判读包（`packet`）

```bash
python tools/g7_adjudicate.py packet \
  --json-dir out/g7/round2/json60 --images out/g7/images60.json \
  --out out/g7/adjudication --split judge_a,judge_b
```

产物（全部在 `out/g7/adjudication/`）：

| 路径 | 内容 |
|---|---|
| `manifest.json` | 单元清单 + 三份指纹 + claim 清单 + 分派表（谁判哪份变体） |
| `packets/judge_a/<model>/<img>.md` | 判读者 A 的逐图包（图片路径 + caption + IR 实体表 + 候选事实 + 判读规则） |
| `packets/judge_b/...` | 判读者 B 的包：同一批 claim id，**事实顺序相反**（防顺序锚定） |
| `templates/judge_a.json` / `judge_b.json` | 空白结果模板（填 verdict 用） |
| `templates/arbiter.json` | 第三名仲裁的空白模板（只填分歧条目） |
| `human_packet/<model>/<img>.md` + `human_packet/templates/human.json` | **人类判读包**：不含 AI 判读结果、空白模板，可直接交给人类填写 |

**包里没有什么**（协议要求，工具强制）：

- 没有机检结论（binding 覆盖率、pass/fail、`bound/分母` 一律不出现）；
- 没有另一名判读者的任何结果；
- 没有人名/模型名的身份提示（只有 `judge_a` / `judge_b` 代号）。

**包里有什么不能缺**：图片路径与 sha256、caption、IR 实体表、候选事实（claim id + 断言）、
判读规则、AI 标注（AI 包）/人类说明（人类包）。

## 3. 双盲设计

### 3.1 角色

| 角色 | 职责 | 看到什么 | 看不到什么 |
|---|---|---|---|
| 判读者 A | 对包内全部 claim 给 verdict + 整图幻觉 | `packets/judge_a` + 原图 | B 的结果、机检结论、自己之外的任何结论 |
| 判读者 B | 同上（不同会话/不同上下文/尽量不同模型） | `packets/judge_b` + 原图 | A 的结果、机检结论 |
| 仲裁者 | **只**对 A/B 分歧的 claim 给最终 verdict | 分歧清单（claim id + 断言 + 两方 verdict 匿名顺序或打乱） | 谁是 A/B、机检结论 |
| 合并者 | 跑 `merge`、写报告 | 全部 | ——（负责如实标注证据等级） |

### 3.2 独立性限制（必须写进结论）

- 两名判读者都是 AI ⇒ 证据等级 **B（AI 双读，非人类）**；
- 若两名判读者底层是同一模型，独立性更弱，必须在报告里点名「同模型双读」；
- 双盲只保证「互相看不到结论」，不保证「判据等价」——所以还需要 §4 的一致性门槛。

### 3.3 合并规则

1. 两名判读者都给 verdict 且相同 → 该 verdict 为 truth；
2. 不同 → 进分歧清单；有仲裁结果 → 仲裁 verdict 为 truth；无仲裁 → **未决**
   （单列，不计入准确率分母，工具会打印未决条数）；
3. 只有一名判读者给了 verdict → 不算一致（不进 κ 的配对），该 claim 记为未决；
4. 非法 verdict（拼错/表外值）→ `merge` 直接报错并给出合法值，**不静默当没填**。

## 4. 一致性门槛（κ / α ≥ 0.6）

### 4.1 指标

- **两名判读者**：Cohen's κ（名义变量）：
  `κ = (Po − Pe) / (1 − Pe)`，Po = 观察到的一致比例，Pe = 按各自边际分布算出的期望一致比例；
- **超过两名判读者**：两两 κ，报**最小值**（保守）；
- 事实 verdict（三分类）与整图幻觉（二分类）**分别算 κ**，最终门槛取所有 κ 的最小值
  （事实 κ、幻觉 κ、分模型 κ）；
- 只统计两名判读者都给出 verdict 的 claim（未填不算一致）。

### 4.2 门槛

| 条件 | 处置 |
|---|---|
| `min κ ≥ 0.6` | 允许下结论（继续走 §5 的统计与三档判定） |
| `min κ < 0.6` | 结论**只能**是「样本不足（判据不足）」；`merge` 进程返回非零（闸红），不得比较模型 |

### 4.3 为什么不用「一致率 %」当门槛

原始一致率会被类别不平衡欺骗：45 条里 44 条 `correct`、1 条分歧 → 一致率 97.8%，
但 κ≈0（Po≈Pe）。**κ 会惩罚这种「几乎全填同一类」的假一致**。
工具的 `merge` 同时输出原始一致率（仅展示）与 κ（用于门槛）。

## 5. 统计口径与三档结论

### 5.1 指标

| 指标 | 口径 |
|---|---|
| 事实准确率 | `correct / (correct + wrong)`；`unverifiable` 剔除并在表里单列 |
| 不确定区间 | Wilson 95% CI（小样本不用正态近似） |
| 模型间事实级差异 | Fisher 精确检验（2×2：对/错 × A/B） |
| 逐图配对 | 每图准确率之差，符号检验（双侧精确二项，平局剔除） |
| 跑崩率 | 失败数 / 尝试数，Fisher 精确检验 |
| 幻觉 | 图级 present/absent，McNemar 精确检验（按图配对） |
| 多重比较 | 本轮**不做结论**；Bonferroni 只作敏感性参考，p 值必须与 CI、分母一起报 |

### 5.2 三档结论判定（只允许这三档）

| 档 | 成立条件 | 写法 |
|---|---|---|
| **样本不足** | κ < 0.6；或可判事实 < `--min-n`（默认 20）；或关键比较的 CI 覆盖 0 | 写明卡在哪一条（判据不足/样本量/CI） |
| **显著差** | κ ≥ 0.6 且 n ≥ min_n 且 Fisher p < 0.05 | 给方向 + 效应量（准确率差、百分点）+ 95% CI + Fisher p + 分母 |
| **无显著差异** | κ ≥ 0.6 且 n ≥ min_n 且 p ≥ 0.05 | 必须同时写「不显著 ≠ 无差异」+ 各模型 CI + 最小可检出差异 |

**禁用写法**：「更好 / 更强 / 全面超越 / 明显优于」。只允许「A 在 X 类上准确率高 Y 个百分点
（95% CI …），Fisher p=…，n=…；本轮结论：显著差 / 无显著差异 / 样本不足」。

## 6. 评分校准（`calibrate`）

### 6.1 目的

任何「自动分」（binding 覆盖率、自定义打分、模型自报 confidence）想写进 README，必须先证明
**它给模型/图的排序与判读排序同向**。排不对的分数不许当结论。

### 6.2 口径

- **Spearman ρ**：自动分 vs 判读准确率，按 `(模型, 图)` 单元配对（n ≥ 3，并列用平均秩，无 scipy）；
- **翻转率**：按判读准确率降序排，相邻对的自动分顺序反向的比例（平局对剔除）；
- 同时报分模型 ρ（某个模型可能全靠基线拉分）。

### 6.3 门槛与后果

| 条件 | 处置 |
|---|---|
| `ρ ≥ 0.5` | 该分**可以用于排序**（仍不能当放行闸——与 `confidence` 同一纪律） |
| `ρ < 0.5` | 工具打印「**该分不应进 README**」并返回非零；该分不得出现在 README/结论里 |

## 7. 流程与复现

### 7.1 标准流程

```bash
# 1) 生成双盲包 + 人类包（不含机检结论）
python tools/g7_adjudicate.py packet \
  --json-dir out/g7/round2/json60 --images out/g7/images60.json \
  --out out/g7/adjudication --split judge_a,judge_b

# 2) A/B 各自独立判读（只拿自己那份 packets/<judge>/，填 templates/<judge>.json）

# 3) 合并：一致性、分歧、仲裁、准确率、三档结论
python tools/g7_adjudicate.py merge \
  --judges out/g7/adjudication/judge_a.json,out/g7/adjudication/judge_b.json \
  --manifest out/g7/adjudication/manifest.json \
  --arbiter out/g7/adjudication/arbiter.json \
  --binding out/g7/binding.json \
  --out out/g7/adjudication

# 4) 评分校准：自动分排序 vs 判读排序
python tools/g7_adjudicate.py calibrate \
  --merged out/g7/adjudication/merged.json \
  --from-binding out/g7/binding.json \
  --out out/g7/adjudication
```

### 7.2 构造数据集演示（工具自检，不是效果结论）

用 4 条自造假判读（2 模型 × 2 图 × 3–9 条 claim）跑通 `packet → merge → calibrate`，
结果落 `out/g7/adjudication/demo/`。演示覆盖：

- 两名判读者完全一致 → κ=1.0、闸绿；
- 构造 1 条分歧 → `merge` 的 `disagreements[]` 能定位到 模型/图/claim id，无仲裁时进 `unresolved`；
- 构造大批分歧 → κ<0.6、进程非零、结论落「样本不足」；
- 自动分与判读排序反向 → ρ<0、打印「该分不应进 README」、进程非零。

（演示输出见 `out/g7/adjudication/demo/demo.log`；`out/` 不入库。）

**实测摘要**（自造 4 个单元 = 2 模型 × 2 图、36 条 claim；不是效果结论）：

| 场景 | 关键输出 | 闸 |
|---|---|---|
| A/B 完全一致 | 事实 κ=1.0（n=36）、幻觉 κ=1.0、逐模型最小 κ=1.0 | 绿 |
| A/B 有 1 条分歧 + 第三仲裁 | 事实 κ=0.9574、分歧 1 条、**仲裁后未决 0 条**、结论「显著差」（Fisher p=0.0030） | 绿 |
| A/B 大批分歧（构造） | 事实 κ=0.0048、分歧 23 条、结论「样本不足（判据不足）」、提示「不得比较模型优劣」 | **红**（非零退出） |
| calibrate：自动分与判读排序对齐 | ρ=1.0、翻转率 0%、`readme_allowed=true` | 绿 |
| calibrate：自动分与判读排序反向 | ρ=-1.0、翻转率 100%、打印「**该分不应进 README**」 | **红**（非零退出） |

这张表只证明**工具链按协议工作**；它不代表任何模型的好坏。

## 9. 已知限制与未验证

| 项 | 状态 |
|---|---|
| 人类判读 | **未做**（human_packet 已产出，等人类填写；在此之前所有判读只有 AI 证据等级 B） |
| AI 双读的独立性 | 弱于人类双读；若两名判读者同底层模型，必须点名「同模型双读」 |
| κ 的类别不平衡敏感 | 已知局限（prevalence effect）；无法用均衡设计完全消除，只能如实报 κ + 原始一致率 |
| 样本量 | 60 图 × 2 模型 × 3–9 条 ≈ 360–1080 条事实；分 12 类做结论时每类可能只有几十条 → 分类结论大概率仍要标「样本不足」 |
| 判读包与机检的隔离 | 靠流程纪律（判读者只能拿 packet）；若判读者自行打开 `binding.json`，双盲失效，只能靠审计发现 |
| 重绘闭环 | 未做（L4 只测「账本侧」，不测「重绘像不像」） |
| ρ 校准 | 只证排序相关，不证绝对校准；任何自动分仍不得当放行闸 |
