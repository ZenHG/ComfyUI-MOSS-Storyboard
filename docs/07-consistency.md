# 跨格一致性：机理、实测口径与旋钮边界

> 本文回答一个问题：**MOSS 故事板里，跨格一致性由什么决定？**
> 全部结论来自实测（单卡，2026-10-24）；四组指标的口径与外部对照路线一致，
> 定义与复现方式见 §五。

---

## 一、三条机制（强弱完全不同）

一致性不是"一个东西"，是三条独立机制的总和。搞清是哪条在起作用，
才知道该调哪个旋钮。

| 机制 | 做法 | 强度 | 代价 |
|---|---|---|---|
| **M1 语义锚定** | 每格独立采样，每格都完整读一遍「角色/服装/道具/场景」的全局描述 | 中 | 采样 N 次 |
| **M2 像素复制** | 把第 1 格当参考图喂回后续格（`reference_latents` 或 vision-only） | 高 | 需要编辑 LoRA 或起点图 |
| **M3 随机性抑制** | 各格共用同一 seed | —— | **有害，见下** |

### M1 为什么有效

整张生成时，N 格共享**一次**注意力，每格只分到 1/N ⇒ 全局描述被摊薄，
模型在每个区域各"想象"一遍角色 ⇒ 帽子颜色飘、脸型飘。

逐格生成时，每格**独占**一次注意力 ⇒ 全局描述被完整执行一遍。
这是逐格模式价值的**全部来源**（不是"更清晰"，那是 M1 的副产品）。

### M2 的边界（实测）

vision-only 参考图（`TextEncodeMOSSImageEdit` 不接 vae）**不能保持其它格**：
实测其它格变化 50/255（≈整张重画）。只有 `reference_latents`（接 vae + 编辑 LoRA）
才有像素级约束力 —— 而那已经超出本包范围（需要第三方 285MB 权重）。

⇒ **本包不提供参考图输入**。跨格一致性靠 M1 + 提示词纪律。

### M3 是陷阱，不是机制

各格共用同一 seed ⇒ 噪声相同 ⇒ 采样路径趋同 ⇒ 指标上"一致性极好"
（色调极差 0.0663，远超 Krea2 逐格路线的 0.146），**但 4 格画出几乎一样的画面**
（格间 MAE 掉到 0.1338，景别梯度塌陷）。

> **判据**：一致性指标好 **且** 格间 MAE 也小 ⇒ 画面重复了，不是一致性好。
> 故事板要的是「同一角色、不同景别」。

⇒ **每格必须用不同 seed。** 本包逐格模式用 `seed + 格号`。

## 二、实测矩阵（4 格 / 16:9 / 8 步 / cfg 1.0 / 4 步蒸馏 LoRA）

场景：雨夜咖啡店，苏晚（红贝雷帽 + 翠绿围巾）+ 陈屿，白瓷咖啡杯 + 柠檬水。

指标来源：按 §五 的四组指标实测
（直接喂裁好的单格；整张那组先裁格再喂）

| 组 | 色调均值↓ | 人脸余弦↑ | 景别极差 | 格间 MAE | 结论 |
|---|---|---|---|---|---|
| **整张**（一次采样） | 0.1711 | 93.1 | 0.2078 | 0.2173 | 人脸像但**不像同一个人** |
| 逐格 `sample_edge=512` | 0.2084 | **99.1** | 0.0244 | 0.1946 | 景别梯度塌陷（都太像） |
| 逐格 `sample_edge=768` | 0.3208 | n/a | 0.0105 | 0.1798 | 色调飘 |
| 逐格 `sample_edge=1024` | 0.2805 | n/a | 0.0037 | 0.1768 | 色调飘 + 景别几乎不变 |
| 逐格 `sample_edge=1408` | 0.2289 | n/a | 0.0138 | 0.1850 | 略好 |
| 逐格 1024 + **同 seed** | **0.0663** | n/a | 0.0112 | **0.1338** | ⚠ **画面重复，非一致性** |
| 逐格 1024 + 角色复制进每格 | 0.1999 | n/a | 0.0042 | 0.1973 | 色调飘 |

### 从矩阵读出的三条硬结论

1. **逐格 > 整张，人脸余弦 93.1 → 99.1。** 这是本包 0.2 的立论基础。
2. **景别梯度极差越小越好是错的。** 逐格 1024 的 0.0037 看着"稳"，
   实际是**四格景别几乎一样** ⇒ 故事板失效。格间 MAE 与景别极差要**一起**看。
3. **色调极差在逐格路线天然偏大**（0.20–0.32 vs Krea2 逐格 0.146）。
   原因是每格独立采样 ⇒ 曝光/色温各自漂。**这是逐格路线的固有代价**，
   不是 bug；Krea2 的逐格路线靠 identity_edit LoRA 锁色调，MOSS 基座没有。

## 二之二、场景 B：兽脸（黑猫）复验

同一套判据，换一个难度更高的主体：**黑猫**（琥珀竖瞳 / 粉鼻 / 白胸口斑 /
右耳尖白毛 / 红毛线球 / 白瓷碗 / 暖色木质窗台）。

| 组 | 色调均值↓ | 景别极差 | 格间 MAE | 目检 |
|---|---|---|---|---|
| **整张**（一次采样） | 0.2472 | 0.0000 | 0.2484 | ❌ **明显换猫**：虎斑 / 黑猫 / 黑猫 / 灰猫 |
| 逐格 `sample_edge=512` | **0.1677** | 0.0000 | 0.2443 | ✅ **同一只猫**，琥珀眼+粉鼻+红毛线球+白瓷碗全在，景别也换了 |
| 逐格 `sample_edge=768` | 0.2400 | 0.0000 | 0.2244 | ✅ 同上 |
| 逐格 `sample_edge=1024` | 0.2520 | 0.0000 | 0.2611 | ✅ 同上 |
| 逐格 `sample_edge=1408` | 0.2174 | 0.0000 | 0.2375 | ✅ 同上 |
| 逐格 1024 + **同 seed** | 0.0862 | 0.0000 | 0.2309 | ⚠ 猫一致但**景别雷同** |
| 逐格 1024 + 角色复制进每格 | 0.2092 | 0.0000 | 0.2610 | ✅ 同上 |

- **结论在兽脸上复现**：逐格 512 的色调极差 0.1677，**比整张 0.2472 好 32%**，
  且**优于 Krea2 逐格基准 0.146 的量级**；整张那一栏肉眼就是"四只不同的猫"。
- ⚠ **人脸余弦对本场景不可用**（MediaPipe 检人脸，兽脸检不出 ⇒ n/a）。
  这是工具的已知边界，不是本场景的一致性差；兽脸一致性靠目检 + 道具色占比。
- ⚠ **景别极差全为 0**：该指标依赖人脸框面积，兽脸无框 ⇒ 退化为 0，**不可读**。

### 两个场景合起来的规律

| 主体 | 整张 | 逐格 512 | 谁赢 |
|---|---|---|---|
| 人（红帽绿围巾） | 0.1711 / 人脸余弦 93.1 | 0.2084 / **99.1** | **逐格赢（人脸身份）** |
| 兽（黑猫） | 0.2472 / 明显换猫 | **0.1677** / 同一只猫 | **逐格赢（色调+主体）** |

⇒ **逐格路线在两类主体上都成立**，不是只在人物上偶然有效。

## 三、提示词纪律（逐格模式下比参数更重要）

既然一致性靠 M1（每格完整读一遍全局描述），那么**全局描述写得够不够"可执行"**
直接决定成败。实测有效的写法：

| 要求 | 反例 | 正例 |
|---|---|---|
| 角色特征**具体到颜色** | "苏晚：年轻女性" | "苏晚：黑发低马尾、**亮红色贝雷帽**、**翠绿色围巾**、哑光织物" |
| 道具也要进全局 | 只在某一格提杯子 | "固定道具：桌上一个**白瓷咖啡杯**、一杯柠檬水"（每格都在） |
| 环境写死 | "咖啡店" | "雨夜咖啡店靠窗双人桌、湿街反光、玻璃雨痕、暖黄吊灯" |
| 每格只写**差异** | 每格重复全套角色描述 | 每格只写景别/动作/表情，角色靠全局段 |
| 每格景别必须**真的不同** | 四格都写"特写" | 中景 / 特写 / 近景 / 大特写，明确拉开 |
| **焦距 / 机位 / 景深写在每格，不写在全局** | 全局段写死"35mm、浅景深"，第 1 格又要"大远景、环境完整进画" | 全局只留场景·角色·道具·质感；每格自带"24mm 广角·俯角·全景深"或"85mm·略低机位·极浅景深" |

> 🔴 **全局段与格内景别不能打架**（2026-10-26 踩坑回写）。我曾把"逐格四格景别全塌"
> 归因给机制，实测却漏了自家词的矛盾：全局写"浅景深"，第 1 格却要"大远景、落地窗与吊灯
> 完整进画"——远景要环境清晰，浅景深把环境糊掉，模型最省事的解法就是退回中景；
> 再叠一条写死的"35mm 胶片摄影"（标准镜头天然暗示中距离）。**归因顺序必须是
> 词 → 参数 → 机制**，跳级下结论必错；而且审词要读**真正送进模型的那段文本**
> （输出 `prompts_json`），因为编译会删改措辞，画布上看到的不等于模型收到的。

> ⚠ **每格重复全套角色描述反而更差**（实测"角色复制进每格"色调 0.1999 vs
> 不复制 0.2805，好一些但景别梯度塌到 0.0042）。原因是描述太长会挤掉
> 景别指令的位置。**全局段写角色，每格只写差异**。

## 三之二、景别：为什么 UI 中文、输出英文（2026-10-26）

**依据（官方，不是我的审美）**：MOSS `USERGUIDE_ZH.md` 写「语言：默认推荐**英文**（训练量最多）」，
构图示例是自然语言散文（`A wide view of a refrigerator ...`）；官方**没有**镜头术语表。
所以「把 `中景` 当中文标签拼在最前面」两条都不符合规范。

**做法**：八档仍是 UI 里的中文预设（导演词汇），但编译成英文**可见范围**子句：

| 档位 | 输出 |
|---|---|
| 大远景 | `Extreme wide shot, the environment fills the frame and the figure is tiny` |
| 全景 | `Full shot, the whole figure just fits the frame` |
| 中景 | `Medium shot, framed from the waist up` |
| 中近景 | `Medium close shot, framed from the chest up` |
| 特写 | `Close-up, the face fills the frame` |

自定义景别原样输出（英文用 `. ` 分隔、中文用 `，`）；`size` 清空则只发 caption。
字段仍是**自由文本**（≤64 字），八档只是预设 —— 之前"必须八选一"是本包自造的局限，不是契约。

**为什么"可见范围"比"术语"更值得赌**：术语只能靠模型自己解释（中景/中近景/近景三档它未必分得开），
可见范围是**可检查**的约束 —— 人眼能判断"腰以上入画"有没有成立，机检也能用
`shot_gradient`（人脸框面积占比）量。这条属于"把抽象标签换成可见选择"，与官方 skill
「Describe visible choices」同向。

**未验证（不当结论用）**：没有 A/B，所以**不声称英文一定更好**。可复跑判据：
同 seed × 同 caption，只换景别表达（中文标签 / 英文术语 / 英文可见范围）三臂 × 3 seed，
读 `tools/check_grid_consistency.py` 的 `shot_gradient` + 目检。⚠ `shot_gradient` 只在
每格恰好一张脸时出数（§五 限制①），远景格会 n/a。

**冲突报警**：`find_size_conflicts` 只出声不改数据 —— 描述里写「面部占满」却选了「大远景」时
`report` 点名。理由见 §三 那条踩坑：两处说法打架时模型不选其一，而是**退回中景**。

## 四、旋钮边界（本包提供什么、不提供什么）

**提供**

- `mode=逐格` —— M1 的实现（每格独占注意力）
- `sample_edge` —— 单格采样长边（绝对像素）。**越大不一定越好**：
  496 最一致但偏糊，1024–1408 清晰但色调更飘。
  没有单一最优值，取决于你要"一致"还是要"清"。
- 逐格模式自动清理全局描述里的多格措辞（否则模型照样画多格）
- 每格用 `seed + 格号`（**不同** seed，见 M3 陷阱）

**不提供**

- **参考图输入（不在本包范围内，终态决策）**。两条理由各自独立成立：
  ① vision-only（`TextEncodeMOSSImageEdit` 不接 vae）保持不住其它格 —— 实测其它格变化约 50/255，
  等于整张重画；② `reference_latents`（接 vae）绑定编辑 LoRA，换来像素级相似，
  代价是权重加载 + 景别趋同 + 每次改动都要重走参考链。**低收益、高复杂度。**
  ⇒ 一致性只走提示词层：全局段 + 逐格独立采样 + 单格 layout JSON。
- 色调锁（同上，不再追）
- "最优参数"承诺 —— 上表说明这是一个**权衡**，不是单目标

> ⚠ **指标只做定位，画面结论留给目检。** 人脸余弦检不出兽脸；
> 景别极差在无人脸时退化为 0；色调极差在不同机位天然不同
> （暖黄吊灯格 vs 雨窗霓虹格）。

## 五、怎么复现

> ⚠ **不要自己另写一套一致性度量。** 口径换了数字就不可比；按下面四组指标读：

| 指标 | 定义 | 读法 |
|---|---|---|
| `tone` | luma / R−B / 饱和度 的格间极差 | 曝光与色温基调是否被统一住 |
| `id_consistency` | 人脸几何余弦 | 只在检出人脸的格之间比较 |
| `shot_gradient` | 人脸框面积占比极差 | 景别是否真的拉开 |
| `content` | 格间 MAE | 画面是否重复 |

（度量脚本**已随仓库分发**：`tools/check_grid_consistency.py`。
⚠ 两条硬限制，2026-10-26 复测时实锤，读表前先看：
① `id_consistency` / `shot_gradient` **只在每格恰好一张脸时出数**——远景格没脸、
双人格两张脸都会让"抓哪张脸"变得不确定，那时余弦量的是"检到了谁"而不是"是不是同一个人"；
② `prop`（道具色占比方差）**混了景别**：整张拉开了景别、逐格没拉开，占比天然就不同，
所以它不能单独当身份判据。）

```bash
# 直接喂裁好的单格；整张那组先裁格再喂
python tools/check_grid_consistency.py \
  output/<组>_p0_*.png ... output/<组>_p3_*.png --hex "#c0392b" --report out.json
```

复测材料（提示词 / 种子 / 采样参数）在 `tests/fixtures/consistency-scenarios.json`，
同 seed 重跑指标逐字节一致（已验）。**§一、§二 的 2026-10-24 那批数字出自另一台机器上
未分发的脚本，口径不可考** —— 保留作参考，别当可复现依据。

⚠ **人脸余弦只比"检出人脸的那几格"**；检出人脸 < 2 格时该指标不可用
（背身格、桌面俯拍格本来就没脸）。⚠ **兽脸场景该指标整体 n/a**
（MediaPipe 检人脸不检兽脸）⇒ 兽脸一致性靠目检 + 道具色占比。
⚠ **景别极差在无人脸时退化为 0**，不可读。

⚠ **指标只做定位，画面结论留给目检。** 读数的两条纪律（来自度量口径）：
① 不同机位天然色温不同（暖黄吊灯格 vs 雨窗霓虹格），色调极差**不是越小越"对"**，
它量的是"曝光/色温基调是否被模型统一住"；
② 人脸检出少 ≠ 脸崩。

## 六、既有结论的对照（Krea2 路线，2026-10-24 复核）

同一口径下另有一条外部对照（Krea2，非本包实测）：

| 路线 | 跨格一致性靠什么 | 色调极差 |
|---|---|---|
| 逐格（`gen_grid_r5.py`，krea2 identity_edit） | 逐格复写身份/服装/色调锁 | **0.146** |
| 一次性（`gen_storyboard_grid.py`，同 latent 一次采样） | 模型在单张画布内自行保证 | 0.196–0.237 |

⇒ **Krea2 的结论与本文一致**：逐格路线一致性更好。
但两者的**锁法不同**：
- Krea2 靠 **identity_edit LoRA** 锁身份与色调（需要那个 LoRA）；
- MOSS 基座**没有**这类 LoRA ⇒ 只能靠**提示词纪律 + 每格独立采样**。

这解释了本文矩阵里"逐格路线色调极差偏大（0.20–0.32）"的来源：
**没有色调锁 LoRA，曝光只能靠提示词压，压不住就飘。**
