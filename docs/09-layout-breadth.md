# 09 · 广度：从故事板到任意元素组合

> **状态**：梳理稿，不是规格。定稿后再动工。
> 08 解决的是「故事板里每格写什么」。本文解决「不止故事板时怎么办」。

---

## 〇、为什么要现在谈广度

深度的结论已经拿到：**元素级 bbox 是强约束**（`docs/08` §八，36 张实测）。
这条能力不只服务故事板 —— 它其实是「**指定每个元素在哪**」的通用能力。

故事板只是它的一种用法：把画布切成 N 个等大格，每格一个元素。
一旦承认这一点，就不该把编辑器锁死在宫格上。

---

## 一、用户为什么生成一张图

按**目的**分，不按技法分。六类覆盖绝大多数需求：

| # | 目的 | 典型产出 | 元素结构 | 本仓现状 |
|---|---|---|---|---|
| 1 | **叙事** | 故事板、分镜、漫画分格 | N 个等大格，每格一段描述 | ✅ 已覆盖 |
| 2 | **资产** | 角色三视图、表情表、道具、场景概念 | N 个等大格，同一主体的不同视角 | ⚠ 能出，没工具化 |
| 3 | **商业** | 产品多角度、电商主图、广告海报 | 主体 + 文字块 + 留白 | ❌ 未覆盖 |
| 4 | **信息** | 文字海报、封面、标题图、信息图 | 文字块为主，主体为辅 | ❌ 未覆盖 |
| 5 | **创作** | 单幅插画、封面、概念图 | 自由元素组合 | ❌ 未覆盖 |
| 6 | **参考** | 构图草稿、明度稿、色稿 | 单主体 + 位置 | ❌ 未覆盖 |

**1 和 2 是同构的**：都是「N 个等大格 + 每格一段描述」，只是内容不同。
⇒ 故事板的机制直接能出角色三视图，只差一个预设。

**3 和 4 也是同构的**：都是「主体 + 文字块」，只是主次不同。
⇒ 这是本仓完全没碰过、但 MOSS 最擅长的一块（文字渲染强）。

## 二、元素定位的七种范式

用户说「定位」，实际有七种不同的空间意图。它们需要的编辑工具不同。

```
① 分区（并列）        ② 层叠（前后）        ③ 网格（规则）
┌────┬────┐          ┌──────────┐         ┌───┬───┐
│ A  │ B  │          │  ┌────┐  │         │ 1 │ 2 │
└────┴────┘          │  │ A  │  │         ├───┼───┤
 不重叠                 │  └────┘  │         │ 3 │ 4 │
                      │   B 在后  │         └───┴───┘
                      └──────────┘          等大等距
                       重叠 + z 序

④ 对齐（节奏）        ⑤ 文字块（层级）      ⑥ 留白（呼吸）
┌──┬──┬──┐           ┌──────────┐         ┌──────────┐
│A │B │C │           │  标题     │         │  ┌───┐   │
└──┴──┴──┘           │  ──────  │         │  │ A │   │
 等宽等距              │  正文     │         │  └───┘   │
                      └──────────┘         │    留白   │
                                           └──────────┘

⑦ 中心 / 三分（焦点）
┌───┬───┬───┐
│   │   │   │
├───┼───┼───┤   主体落在交叉点
│   │ A │   │
└───┴───┴───┘
```

| 范式 | 空间意图 | 编辑器需要的工具 | 现状 |
|---|---|---|---|
| ① 分区 | 元素不重叠，各占一块 | 画框 + 吸附边界 | 有（画框） |
| ② 层叠 | 前景压背景 | 画框 + **z 序**（上移/下移） | ❌ 缺 z 序 |
| ③ 网格 | 等大等距 | **一键等分** | ❌ 缺 |
| ④ 对齐 | 等宽等距一排 | **对齐/均布** | ❌ 缺 |
| ⑤ 文字块 | 层级分明 | **文字专用元素**（text 字段） | ⚠ 有字段，无 UI |
| ⑥ 留白 | 主体偏一侧 | 画框（靠边）+ 视觉提示 | 有 |
| ⑦ 三分 | 主体在交叉点 | **参考线**（三分线） | ❌ 缺 |

⇒ **只有 ①⑥ 能靠"画个框"完成。** 其余五种都需要额外的工具。
这就是"千奇百怪"的真实来源：不是元素多，是**空间意图的范式多**。

## 三、怎么优雅处理组合：原子 + 预设，不枚举组合

**不要试图覆盖所有组合。** 组合是无限的，工具是有限的。正确做法是三层：

### 3.1 原子（元素）

一个元素只有五个字段：

| 字段 | 作用 | 谁需要 |
|---|---|---|
| `label` | `object` / `character` / `text` | 全部 |
| `caption` | 这个元素长什么样 | 全部 |
| `bbox` | 它占哪块 | 全部 |
| `text` | **实际渲染的文字**（仅 text） | 海报、封面 |
| `palette` | 主色（仅 text / 需要定色时） | 海报、品牌图 |

⇒ 五字段足够表达任何元素。**不需要给每种目的发明新字段。**

### 3.2 预设（布局起点）

用户不从空白开始，而是选一个预设。预设 = 一组初始 bbox + 建议的元素类型。

| 预设 | 生成什么 | 服务目的 |
|---|---|---|
| `grid` | N 个等大格（行列可调） | 1 叙事、2 资产 |
| `split-v` | 左右两块 | 3 商业（产品+文案） |
| `split-h` | 上下两块 | 3 商业（上图下文） |
| `title-body` | 上标题 / 中主体 / 下正文 | 4 信息（海报） |
| `three-col` | 三等分竖列 | 3 商业（多角度并排） |
| `center` | 中心主体 + 四周留白 | 5 创作、7 三分 |
| `stack` | 前景主体 + 背景元素 | 2 层叠 |
| `free` | 空画布 | 兜底 |

**预设只是初始值，不是约束。** 用户选完可以随便改框。
⇒ 这样既有"开箱即用"，又不限制自由度。

### 3.3 关系（由预设隐含，不显式建模）

不要给用户「把 A 设为 B 的左边」这种关系语法 —— 那是数据库，不是画布。
关系用预设 + 吸附隐式表达：

- 选 `three-col` ⇒ 三个框自动等宽等距（关系已烘焙进初始 bbox）
- 用户拖动时**吸附**到：其他框的边、画布中线、三分线、16px 网格
- 不提供"绑定关系"概念

⇒ 用户看到的是"框"，系统内部没有图结构。简单、可预测、不会出现约束求解失败。

## 四、文字：MOSS 的强项，也是最大的未验证项

### 4.1 协议已经支持

官方 `MOSSImageLayoutPrompt` 的 text 元素：

```json
{"label": "text",
 "caption": "粗体无衬线标题，金色描边，轻微发光",
 "text": "示例标题",
 "bbox": [y0, x0, y1, x1],
 "palette": ["#c8a15a"]}
```

**`caption` 和 `text` 是两个字段，不能混**：
- `caption` = 这个文字**长什么样**（字体/颜色/效果）
- `text` = 实际要**渲染的字**

我们现在的 `single_panel_json` 在 text 元素缺 `text` 时拿 caption 兜底 —— 那是错的。
必须分开，缺 `text` 就报错。

### 4.2 海报的元素结构

一张文字海报通常是三层：

| 层 | label | 例子 | 注意 |
|---|---|---|---|
| 标题 | `text` | 示例标题 | 字号最大，最容易被模型改字 |
| 副标 / 信息 | `text` | 第一章 · 雪夜 | 字号中等 |
| 主体 | `character` / `object` | 人物半身 | 与文字分区，不重叠 |
| 背景 | 写进 `style`，不占 bbox | 雪原、暗调 | 不框，让模型自由铺 |

⇒ **背景不要框**。框住背景会把整张图变成一块色块。

### 4.3 实测结果（2026-10-24，46 张，约 17 分钟）

工具 `tools/probe_text.py`，三个矩阵。原测试串为内部项目名，已匿名；数值为原串实测。产物在 `output/probe_text/`，文件名自带全部参数。

**矩阵 A：分辨率 × 步数**（文案「示例标题」，原串已匿名；框高 1/6 画布）

| | 1024×576 | 1536×864 | 2048×1152 |
|---|---|---|---|
| 4 步 | ✓ 字全对，边缘略软 | ✓ | ✓ |
| 8 步 | ✓ **字全对，笔画完整** | ✓ 锐利 | ✓ 锐利，金色有金属质感 |
| 16 步 | ✓ | ✓ | ✓ 与 8 步接近，收益递减 |

**矩阵 B：字号 × 分辨率**（8 步）

| 框高占画布 | 1536×864（框高 43–144px） | 2048×1152 |
|---|---|---|
| 1/6 | ✓ | ✓ |
| 1/10 | ✓ | ✓ |
| 1/14 | ✓ | ✓ |
| **1/20** | **✓ 框高仅 43px，四字仍全对** | ✓ |

**矩阵 C：内容类型**（2048×1152 / 8 步）

| 项 | 结果 |
|---|---|
| 中文四字 | ✓ |
| 英文 `LEGEND` | ✓ |
| 中英混排 `示例标题 LEGEND` | ✓ 两种字形风格统一 |
| 两行 `示例标题\n示例副标题` | ✓ **换行被尊重**，上行大字下行小字层级正确 |
| `palette: ["#d92b2b"]` | ✓ 颜色生效 |
| 贴顶（框 y0=5%） | ⚠ **文字向上溢出，被画布裁掉**，两个 seed 都出现 |

### 4.4 三条硬结论

1. **文字能力远超预期。** 1024×576 + 8 步就能把四字全写对。
   「分辨率够大、步数够多」在**大字号**下不是必要条件；小字号（1/20 画布高）也过。
2. **bbox 对文字：宽度有效，高度不严。** 字会溢出框 —— 框高 43px 时实际字高约 130px。
   ⇒ **不能用 bbox 高度精确控制字号**。要控字号，靠框的**宽度**与文案长度。
3. **必须留安全边距。** 文字框贴顶（y0 = 5%）时，红色那组两个 seed 都被裁掉。
   ⇒ 预设里文字框的 `y0` 不小于 **0.10**，`y1` 不大于 **0.90**，且框高给足实际字高的 1.3 倍。

> ⚠ 样本量：每项 2 个 seed。中文四字全对是稳定现象（A 组 20 张里 19 张正确），
> 但「贴顶被裁」只在红色那组复现，其他颜色没测。**不要据此断言"其他颜色不会裁"。**

## 五、对现有结构的影响

### 5.1 state 要统一，不要两套

故事板 state（`version 2`）和通用布局 state 应该是**同一套**：

```json
{
  "version": 3,
  "canvas": {"width": 1024, "height": 1536},
  "preset": "title-body",
  "style": "雪原黄昏，暗调，胶片颗粒。",
  "items": [
    {"id": "t1", "label": "text", "text": "示例标题",
     "caption": "粗体无衬线标题，金色描边", "palette": ["#c8a15a"],
     "bbox": [0.06, 0.05, 0.20, 0.90]},
    {"id": "c1", "label": "character", "caption": "主角半身，侧对镜头",
     "bbox": [0.35, 0.10, 0.95, 0.80]},
    {"id": "t2", "label": "text", "text": "第一章 · 雪夜",
     "caption": "细体小字，白色", "palette": ["#ffffff"],
     "bbox": [0.72, 0.06, 0.80, 0.60]}
  ]
}
```

**故事板怎么表达？** `preset: "grid"`，每个 item 额外带 `no` / `size`：

```json
{"preset": "grid", "cols": 4, "rows": 2,
 "items": [{"id":"s1","label":"object","no":1,"size":"中景","caption":"…","bbox":[…]}, …]}
```

⇒ 一套结构，两种用法。`no` / `size` 是可选字段，只在 `grid` 下有意义。

### 5.2 节点要改名吗

| 现状 | 建议 | 理由 |
|---|---|---|
| 仓名 `ComfyUI-MOSS-Storyboard` | **不改** | 改名会打断所有工作流和链接，收益低 |
| `MossStoryboardLayout` | 不改 | 已发布，铁律 1 |
| 新节点 `MossStoryboardEditor` | → **`MossLayoutEditor`** | 它是通用的，名字不该锁死在故事板 |

⚠ 但节点名带 `Storyboard` 有助于搜索（用户搜"故事板"能搜到）。
折中：节点 ID `MossLayoutEditor`，`SEARCH_ALIASES` 里加 `storyboard` / `故事板` / `分镜` / `海报` / `poster`。

### 5.3 输出要区分「整张」和「逐格」

| 模式 | 采样方式 | 用途 |
|---|---|---|
| `single`（单张） | 一次采样整张画布 | 海报、封面、概念图、资产单图 |
| `grid`（宫格） | 逐格独立采样 + 拼版 | 故事板、三视图 |

⇒ 同一个编辑器，输出两种。`preset` 决定默认模式，用户可覆盖。

## 六、优先级

| 级 | 内容 | 理由 |
|---|---|---|
| **P0** | 文字能力实测（§4.3 六条） | 不做完不敢承诺海报，且决定 bbox 精度要求 |
| **P0** | 统一 state v3 + 编译层（单张 / 宫格两种输出） | 编辑器地基 |
| **P1** | 编辑器：画框 + 元素属性 + 预设下拉 | 核心体验 |
| **P1** | 预设 6 个（grid / split-v / split-h / title-body / three-col / center） | 覆盖 1–4 类目的 |
| **P2** | 三分参考线 + 吸附 | 构图质量 |
| **P2** | z 序（上移 / 下移） | 层叠范式 |
| **P3** | 对齐 / 均布 / 撤销 | 好用，不是必需 |

**P0 的文字实测必须先做**，理由：如果 MOSS 的中文渲染在小字号下不可用，
海报这条线就要重新设计（比如只能做大标题），预设也要跟着改。

## 八、一句话总结

**不枚举组合，只给原子 + 预设 + 吸附。**
原子五个字段（label / caption / bbox / text / palette），
预设八个起点，其余交给用户的框。

广度不是"支持更多东西"，是"用同一套东西表达更多目的"。
