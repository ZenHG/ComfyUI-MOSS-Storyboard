## 1. 它是什么，以及为什么是「方言档」而不是新 target

H3 的提示词骨架有两套，**并存、不替换**：

| 骨架 | 入口 | 字段 |
|---|---|---|
| 基础模式（三字段时间线） | `--target minimax-h3` | `integrated_multimodal_description` / `overall_soundscape` / `non_diegetic_music` |
| 全参考六段式 | `--target minimax-h3 --profile six-section` | `subject_definitions` / `summary` / `retention_analysis` / `detailed_description` / `overall_soundscape` / `non_diegetic_music` |

两套都是**同一份 IR 的投影**：基础模式把 IR 摊成一条时间线散文；六段式先用参考标签
（`<Subject N>` / `<Video N>` / `<Audio N>` / `<Picture N>` / `@图片N`）把主体和续接源
声明清楚，再写摘要、保留分析、逐镜详细描述、声景与画外配乐。

**为什么做成 `minimax-h3` 的 profile（`--profile six-section`），不做独立 target**：

1. **写域与最小改动**：新增 target 要在 `adapters/__init__.py` 的 `ADAPTERS` 表登记；
   六段式与基础模式共用同一套参考标签语义、时间线结构与运镜词表，扩展现有原生
   H3 适配器，比为它复制一个 adapter 更不容易分叉。
2. **默认行为不动**：profile 不传时，`minimax-h3` 的三字段输出**逐字节不变**
   （新测试直接与 `h3.render()` 对比，365 条基线测试也不变）。
3. **不走 generic**：通用后端只会把 IR 摊成散文/tag（`adapters/generic.py`），
   没有参考标签、六段顺序、保留分析这些概念；硬塞一份 YAML 声明接不进来。

代价与边界：`python -m moss_llm.smith targets` **不会**多一行（六段式不是 target）。
这是有意的——`targets` 列的是「后端」，六段式是同一后端下的方言变体。

registry 里的声明位置是 `minimax-h3.dialects.six-section`（字段顺序、参考标签、
选择器、来源、置信度）；**代码侧真值源是 `h3_six.FIELDS`**，单测钉住两边一致。

## 2. 格式定义（逐字来自产线真稿，不是推测）

真稿来源：2026-10-08 产线语义冲突标注包（该文档不在本仓），其中 A01 / A03 / A06
三段是干净稿（人工标注「没有自相矛盾」），已**逐字**存进 `tests/fixtures/h3_six/`。
夹具 sha256 钉在测试里：改一个全角标点测试就红。

### 2.1 六段顺序（固定）

```
subject_definitions:
summary:
retention_analysis:
detailed_description:
overall_soundscape:
non_diegetic_music:
```

### 2.2 各段的写法

**`subject_definitions`** —— 先声明，后引用：

- `<Video N> ……`：续接源（上一段末帧）的承接基准；
- `<Subject N> 名字：外观 / 服装 / 材质 / 光位……`：每个主体一行，可跨全片复用；
- 项目硬事实（座位图、机位基线这类）直接留在这个段里，产线真稿就是如此；
- `@图片N ……定稿参考图。`：静帧参考图清单；
- 行序、空行位置都是有意义的（主体 → 项目硬事实 → 空行 → 参考图），parse 会保留。

**`summary`** —— 首行是方括号模式标记，随后是段落摘要：

```
[video continuation] 七点三秒续接段落，三拍：……
[reference generation] 九点四秒开场段落，两镜：……
```

段落时长就从这里读（「七点三秒」= 7.3s）；读不出时长时 `check` 只 warn
（时间戳越界无从判），**不猜一个 8 秒默认值**。

> 时长来源优先级：显式 `duration_s=` 参数 > summary 里的「N 秒」> 六段骨架登记的
> 时长 > 无骨架 IR 的 `timeline.duration_s`。
> `IR.normalize()` 在没时长时会往 `timeline.duration_s` 写一个 **8.0 结构兜底**
> （`parse` 出来的稿就是这样）；那是给时间轴用的结构值，**不是事实**，`check`
> 不拿它判越界。所以同一份没写时长的稿，`check(text)` 与
> `check(text, IR.from_dict(parse(text)))` 结论一致（都报 `H3S-DURATION-UNKNOWN`
> warn）；真给了时长的 IR（用户手写 / 合成）仍照常判 `H3S-TS-RANGE`。

**`retention_analysis`** —— 每个被引用的主体/续接源一行：

```
<Video 1> (continuation source / previous last frame): fully_preserved - ……
<Subject 1> (appears in [Shot 1], [Shot 2]): fully_preserved - ……
```

真稿里有 `(appears in )` 这种空括号写法，也要能解析（结构化保存 `appears_in: []`）。

**`detailed_description`** —— 段首说明 + 逐镜 + 项目影像规格块：

```
本段是……（一段说明）
[Shot 1] ……画面与动作……
[Shot 2] At 00:03.000, ……画面与动作……
【项目影像规格】
- 质感：……
- 动态：……
```

- `[Shot N]` 从 1 连号；
- `At MM:SS.mmm,` 只出现在**需要切点**的镜头上（Shot 1 不写；一镜到底整段不写）；
- 镜内动作节拍也可以再写 `At 00:03.600,`（真稿 A01 就有）；
- 台词整体放进 `<d>[zh]……</d>`，与基础模式同一条纪律；
- `【项目影像规格】` 是**产线项目模板块**，不是官方六段字段：parse 原样保留，
  `synthesize()` 不生成（通用 IR 里没有「质感/动态/光/色」这套项目规范的位置，
  硬编一段等于替用户编事实）。

**`overall_soundscape`** —— 画内声景散文；**`non_diegetic_music`** —— 画外配乐，
没有写 `N/A`。两段都允许把值写在段头同一行（产线两种写法都有，parse 都吃）。

### 2.3 最小骨架

```
subject_definitions:
<Subject 1> 甲：深灰外套，黑色短发，身形清瘦。

summary:
[video continuation] 八秒续接段落，一镜。

retention_analysis:
<Subject 1> (appears in [Shot 1]): fully_preserved - 按本段定义保持。

detailed_description:
本段为当代现实主义实拍段落。
[Shot 1] 中景固定机位，<Subject 1> 站在过道里。
【项目影像规格】
- 质感：35mm 胶片模拟，颗粒几乎不可见

overall_soundscape:
车厢内的低频嗡鸣持续铺底。

non_diegetic_music:
N/A
```

## 3. 与基础三字段契约的差异

| | 基础模式（三字段） | 全参考六段式 |
|---|---|---|
| 字段数 | 3 | 6 |
| 主体声明 | 实体属性在正文里顺带写 | `subject_definitions` 先声明、正文用标签引用 |
| 参考图 | 无 | `@图片N` + `<Picture N>` |
| 续接源 | 模式指令行（I2VA/FL2VA/L2VA） | `<Video N>` 行 + `retention_analysis` 条目 |
| 时间轴 | 每镜 `[Shot N]`，Shot 2 起**必须**带 `At` | 每镜 `[Shot N]`，时间戳按需（可全无） |
| 时长真值 | 工作流字段 / `timeline.duration_s` | `summary` 里的「N 秒」为准（`duration_s` 兜底） |
| 机检器 | `h3.check()`（28 条铁律可机检子集） | `h3_six.check()`（六段齐序 / 参考标签 / 时间戳 / 台词 / 配乐取值） |
| 负向通道 | 无（H3 本来就没有） | 无 |
| 长度预算 | 无（不走子句装箱） | 无 |

**兼容性承诺**：`minimax-h3` 的默认输出与改动前逐字节一致；registry 只新增
`dialects` 子键，`targets` 列表、`prompt.fields`、采样参数都没动。t4 的新测试里
有一条直接断言「默认路径输出 == `h3.render(ir)`」。

## 4. 往返口径与实测

### 4.1 字节级（3 段真稿，实测通过）

```
t = 夹具原文（UTF-8，含全角标点与段间空行）
ir = IR.from_dict(h3_six.parse(t))
h3_six.render(ir) == t        # 3/3 True，逐字节
```

**为什么做得到**：`parse` 把六段拆成两种东西——

- **能结构化的**：参考标签行（`<Subject N> body`）、`@图片N` 行、summary 的模式标记
  与正文、retention 的 `(appears in …)` 与状态、镜头行的 `[Shot N]` + `At` 前缀 + 正文
  → 存成结构化字段，`render` 按格式重建；
- **不能结构化的**：段首说明、项目影像规格块、声景、配乐这些自由散文 → **逐行原文保存**。

这与 `h3.parse`「认不出的句子原样进 `detail`，不丢」是同一条纪律：能结构化的结构化，
不能结构化的逐字留。所以「逐字节相等」不是把原文整段存了一遍再吐出来——参考标签行、
保留分析行、镜头行都是重建的（见 `_render_definitions` / `_render_retention` /
`_render_description`）；只有散文是原文。

### 4.2 事实级（3 段真稿，逐条断言）

| 夹具 | summary 时长 | 镜数 | Shot 2 起切点 | `<d>` 台词 |
|---|---|---|---|---|
| A01 | 7.3s | 2 | 3.0s | 「对，最后一站。」/「我下一站下。」/「顺路，送你到出口。」 |
| A03 | 6.6s | 1 | ——（一镜到底） | 无 |
| A06 | 8.0s | 3 | 3.0s / 5.0s | 「以前在。」/「现在……」 |

同时断言：主体定义 → IR 实体（4 个，人物/场景/道具分类）、retention 条目 →
`appears_in` 镜头号、正文 `<Video 1>` 续接口径逐字在。

### 4.3 合成路径（没有六段骨架时）

`h3_six.synthesize(ir)` 完全不依赖已解析的稿子，从 IR 的 `entities` + `timeline` 生成：

- `examples/05-h3-t2va.json`（3 镜、有台词）→ 3 个 `[Shot N]`、`At 00:02.800` /
  `At 00:05.800`、台词逐字进 `<d>`，`check` 0 error；
- 静态反推 IR（无 timeline）→ 单镜六段稿，按已有实体列主体；声景缺省写 `N/A`
  并报 `H3S-SOUNDSCAPE-NA` warn——**不替用户编声景**。

合成是**占位级**：主体定义用属性罗列（英文），不生成段首说明与项目影像规格块。
它的用途是「任意 IR 也能进六段式通道」，不是替产线写稿。

## 5. 错误码表

`h3_six.check(text, ir=None, *, duration_s=None, music_policy="any")`。判据只覆盖
**形式与自洽**；表演、情绪、构图好坏一条都不判。

| 码 | 级别 | 触发 | 怎么修 |
|---|---|---|---|
| `H3S-MISSING-SECTION` | error | 六个段头缺任意一个（逐段各报一条） | 补齐六段，顺序固定 |
| `H3S-SECTION-ORDER` | error | 段头顺序不是规范顺序 | 按 §2.1 排 |
| `H3S-TS-RANGE` | error | 任意 `At MM:SS.mmm` ≥ 段落时长 | 时间戳收回时长内；时长以 summary 为准 |
| `H3S-SECTION-EMPTY` | error | 某段内容为空 | 填内容；空段模型读不出指令 |
| `H3S-SECTION-DUP` | error | 同一段头出现两次 | 每段只出现一次 |
| `H3S-SHOT-SEQ` | error | `[Shot N]` 不是 1..N 连号 | 镜头号从 1 连号 |
| `H3S-NO-SHOTS` | error | `detailed_description` 里没有任何 `[Shot N]` | 每镜以 `[Shot N]` 起行 |
| `H3S-TS-ORDER` | error | `At` 时间戳没有严格递增 | 切点/节拍严格递增 |
| `H3S-REF-UNDEFINED` | error | 正文引用 `<Subject N>` 但定义段没声明 | 先在 `subject_definitions` 定义 |
| `H3S-RETENTION-REF` | error | retention 引用未声明的主体/续接源 | 同上 |
| `H3S-D-LANG` | error | `<d>` 缺语言标签 | 写 `<d>[zh]……</d>` |
| `H3S-MUSIC` | error | `non_diegetic_music` 为空，或既不是 N/A 也不是配乐描述 | 无配乐写 `N/A` |
| `H3S-FENCE` | error | 带 Markdown 代码围栏 | 去掉 ``` |
| `H3S-SUMMARY-TAG` | warn | summary 首行没有 `[video continuation]` / `[reference generation]` 标记 | 补方括号标记 |
| `H3S-DURATION-UNKNOWN` | warn | 解析不出段落时长 ⇒ 时间戳越界无法判 | summary 里写「N 秒」 |
| `H3S-SOUNDSCAPE-NA` | warn | 声景写 `N/A`（只有全片静音才合法） | 补画内声景描述 |
| `H3S-SHOT1-TS` | warn | Shot 1 带了 `At` | 首镜不写时间戳（铁律 11：开场时间戳会把首帧锁成置景图） |

三个**必须独立可判**的码（任务验收项）各有正例 + 破坏版单测，且测试断言
「报缺段时不报段序错、不报时间戳越界」，反之亦然。

时长口径有两条路径的单测钉住：同一份「没写时长 + `At 00:09.500`」的稿，
`check(text)` 与 `check(text, IR.from_dict(parse(text)))` 都只报
`H3S-DURATION-UNKNOWN`（不报越界）；用户手写 IR、手改 `timeline.duration_s`、
合成路径三种「真给了时长」的情形仍会报 `H3S-TS-RANGE`。

## 6. 使用方式

API：

```python
from moss_llm.smith import h3_six
from moss_llm.smith.ir import IR

text = open("manuscript.txt", encoding="utf-8").read()
ir = IR.from_dict(h3_six.parse(text))      # 六段稿 → IR（含 timeline.shots 与 six_section 骨架）
again = h3_six.render(ir)                  # 有骨架：逐字回放
rebuilt = h3_six.render(ir, replay=False)  # 改过 IR：重新合成
issues = h3_six.check(text)                # 六段式机检
```

CLI：

```
python -m moss_llm.smith compile <ir.json> --target minimax-h3 --profile six-section
```

profile 名接受 `six-section`（推荐）/ `six_section` / `h3-six-section`。

> 体检口径：CLI 的通用 `lint.check` 已能兼容六段式（集成方已修 `L003`，见 §7.1），
> 但**六段式专用判据仍以 `h3_six.check` 为准**——它额外查六段齐序、参考标签、
> 时间戳越界这些通用 lint 不管的项。

## 7. 已知限制 / 未覆盖（诚实清单）

### 7.1 通用 `lint.check` 与六段式的兼容（曾不兼容，已修）

`lint.check` 的 `L003` 在 `timeline_mode` 下原来只剥 `[Shot N]` 与 `<d>`，而六段式
summary 里的模式标记是方括号（`[video continuation]` / `[reference generation]`），
会被 `WEIGHT_SYNTAX` 当成 `[权重]` 语法误报 error。

- **修复**：`lint.py` 的 timeline 分支在扫描前再剥掉
  `\[(?:video continuation|reference generation)\]`（集成方改，本轮验收范围内）；
- **验证**：CLI `compile <六段 IR> --target minimax-h3 --profile six-section --json`
  → `issues: []`；`tests/test_h3_six.py` 的 lint 接线测试钉住「六段式产物不报 L003」；
- **残留边界**：通用 lint 只做到「不误报」，六段式专属判据仍在 `h3_six.check`
  （六段齐序 / 参考标签 / 时间戳越界等）。

### 7.2 invariants 的 M6 覆盖的是三字段路径

`invariants.m6_timeline_roundtrip` 写死了 `h3.parse`（三字段解析器）。所以对六段式
方言档跑 `INV.run()` 时，M6 验的是同后端的三字段路径，不是六段式产物。适配器在
`warnings` 里明说这一点，避免把「invariants 全绿」读成「六段式也验过了」。
六段式自己的往返由 `tests/test_h3_six.py` 的字节级 + 事实级测试覆盖。
要统一的话需要给 invariants 加「按 adapter 选解析器」的钩子——那是 `invariants.py`
的改动，不在本轮写域。

### 7.3 parse 只做「结构化 + 逐字保留」，不做全文语义分解

- 帧内动作节拍（镜内 `At 00:03.600,`）目前只作为正文保留，不单独抽成事件附录；
- 参考图 `@图片N` 与正文 `<Picture N>` 的引用**不做**全片一致性校验（只校验
  `<Subject N>` / `<Video N>` 是否在定义段声明）；
- 第二套排版变体（只有 `subject_definitions` / `overall_soundscape` /
  `non_diegetic_music` 三个段头、`[Shot N]` 写在定义段里）按**缺段**报错，是刻意的：
  六段式契约要求六段齐全，接受变体会让「缺段」判据失去意义。

### 7.4 六段式 LLM 改写未真机验证

`H3Adapter._rewrite_six()` 已接六段契约（字段顺序、参考标签、`N/A` 口径）与
「采样 + 机检择优」，但本轮没有 `--mode llm` 的实跑证据（无侧车/权重组合在本轮范围内）。
只算「接了线」，不算「验过」。

### 7.5 出片质量未验证

本轮没有跑 H3 生成。六段式骨架对不对（字段/标签/时间戳）是机检能回答的；
「这样写出来画面更好」需要 GPU 出片 + 人判，属于未验证。

### 7.6 夹具只覆盖 3 段

产线标注包里共 30 段，其中 20 段是上述「三字段头 + 镜头写在定义段」的变体
（本轮按缺段判）；本任务只取 3 段干净的标准六段稿做往返基线。扩覆盖 = 再取真稿
+ 扩展解析器，「逐字节」口径可以直接复用。
