## 4. 发现的问题（PASS/FAIL）

### F1 —— 唯一真问题：新工具里硬编码本机盘符路径（**已由 Lead 修复**）

- **位置**：`tools/g7_select.py`（T1 G7 选图脚手架，非本次复核的写域），第 46–47 行。
- **现象**：`SOURCE_DIRS` 两行写死了本机盘符路径（`input` / `output` 各一条）。
- **为什么当时没红**：`check_release_ready.py` 的 S2「GitHub 公开面」只扫**已跟踪**文本文件；该文件当时未跟踪，所以 `release_ready` 只红 S16（未跟踪文件）。
- **如果直接提交的后果**：`git add -A` 后 S16 转绿，但 S2「全部受控文件无盘符路径」会红（`DOC_DRIVE_RE` 能命中盘符路径；允许清单只有 Node 默认安装路径与一个 JSON 转义示例值，不含 ComfyUI 路径）——即「修好 S16 反而暴露 S2」。
- **Lead 修复与复验（A）**：改为 `source_dirs()` 解析：优先 `COMFYUI_INPUT`/`COMFYUI_OUTPUT`，否则走 `tools/_paths.host_root()`（`COMFYUI_PATH` → `.comfyui_path` → 标准安装位置推断）拼 `<宿主>/input|output`；`scan()` 的家族限流改用 `enumerate` 下标。复验：`--help` exit 0、`ruff check .` 全过、**staged 54 个文本文件盘符/用户名扫描 0 命中**、`release_ready` 53/0。
- **对落盘产物的影响**：该脚本只读选图、不写生成产物；本次**未重跑 G7 scan**（不必要，也不改任何已有产物）。

不判 FAIL：CI 判定口径是退出码，本机全部 rc=0；只是注释数字建议同步。
