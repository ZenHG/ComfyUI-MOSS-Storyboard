## 1. 缺陷 1：非人物体被标成 `character`

### 1.1 根因（G7 实测 + 本轮离线复核）

G7 客观规则：`kind=character`、**没有任何**人物字段（gender/hair/skin/face/expression）、
**却带**物体字段（material/color/build/detail）之一。

| | character 实体 | 其中「无人物字段、有物体字段」 | 占比 |
|---|---|---|---|
| A-4B | 62 | 34 | 55% |
| B-9B | 48 | 24 | 50% |
| 合计 | 110 | **58** | **53%** |

本轮用落盘 IR（`out/g7/json/**` 的 36 份成功记录）独立复算，与本表**逐数对上**：
110 个 character、58 个命中（53%）。这 58 个里 **57 个带 `descriptors.material`**；
唯一例外是 **A-4B · img08 · e8**（`kind=character, label="light"`，只有
`color=blue and red neon lights outside`、没有 material）——它被类型闸降级仍然是对的。

> 注意区分两个分母（`docs/47` 复核后统一口径）：
> - 类型闸命中 =「无人物字段、有任一体字段」= **58**（含上例 light，它带 color）；
> - character∧material = **58**；类型闸覆盖其中 **57**（98.3%），剩 **1** 例是铜鹰雕像。

**后果是三重、同一根因**：

1. **材质绑定丢失**：`describe_entity` 的人物分支**不渲染** `descriptors.material`
   （只有非人物分支有 `with {material}`）。材质只落进独立的 `Textures:` 子句，
   而 G7 binding 只认「实体自己的子句」⇒ 「材质与反光」组只剩 **0% / 8%**。
2. **给物体编年龄**：人物分支强制年龄短语 ⇒ `an 80-year-old coffee grinder`、
   `a 120-year-old sword`（G7 §6 已单列）。
3. **凭空出现「一个人」**：长 label + 无性别 → 编译器兜底 `a person`，同描述还会被
   合并成 `the same figure appears again …`（B · img13 实测）。

### 1.2 修法（a + b）

**a. 取证提示词约束（低风险，改 `reverse.SYSTEM`）**

- 规则 15：`character` **仅限人 / 作品明确拟人化的角色**；杯子、窗、灯、车、食物、
  工具、墙、布料、动物雕像都是 `object`（环境是 `background`）。
- 规则 16：非人物**禁止** `age_years` / `age_confidence` / gender / hair / skin /
  face / expression；给非人物年龄=幻觉。
- schema 示例旁补一句：`"character" means a person ... a cup, a window, a vehicle or
  a wall is "object" even when the image is a photo of it.`

**b. `coerce_ir` 类型常识闸（可单测的硬闸）**

- 判据：`kind=character` 且 **无任一人物字段**、**有任一物体字段** → 降级 `object`。
- 降级后年龄一并丢弃（非人物分支本来就不渲染年龄，留在 IR 里只会变成一条
  永远对不上的固定项）。
- **每次都出声**：`Report.kind_downgrades` / `Report.age_dropped` 两个新字段（`to_dict`
  向后兼容，旧键不动）＋ 人话 warning（`实体 e3：标为 character 但无人物字段、却带
  物体字段（material） → object（否则会编年龄并丢材质）`）。

修复后的直接收益（离线可判）：实体的**自己的子句**变成
`coffee grinder with brushed stainless steel`（binding 数得到），
年龄短语消失，`Textures:` 复述也不再重复。

### 1.3 对确定性输出/基线的影响：零，且**不需要重冻**

- 类型闸只作用于 `reverse.py` 的**反推管线**（取证 JSON → IR），不碰
  `clauses.py::describe_entity` 的渲染逻辑，所以确定性编译路径一行未变：
  - `python tools/freeze_smith_set.py --check` → 基线一致：4 份 IR × 5 个后端；
  - `python tools/check_coverage.py --check` → 28 组合不丢不编 + 覆盖率不低于基线。
- 没改 `tests/fixtures/smith/expected.json` / `coverage.json`（**未重冻**）。

### 1.4 c 案（人物分支补渲染 `descriptors.material`）为什么不做

任务书要求三选评估，这里给出可复核的取舍依据：

1. **b 已覆盖 character∧material 的 57/58 = 98.3%**：落盘 IR 里「character 且带
   material」的实体共 **58** 个，类型闸覆盖其中 **57** 个；剩下 **1 例**是
   `A-4B · img18 · e1` 的 `bronze eagle statue`（有 `hair/skin/face/expression` 人物字段、
   带 material、age 50）——b 不降级（有任一人物字段即保留，判据刻意不猜语义）。
2. **c 会改确定性输出**：给人物分支渲染 `with {material}` 会改变所有
   「character + material」IR 的编译结果 ⇒ 必须重冻 freeze 基线、向用户解释
   「为什么输出变了」，且 `material` 对人物语义含糊（皮肤？衣物？道具？），
   与既有的 `wardrobe` 表达会打架。
3. **现有夹具里 0 例命中，分母可复现**：`tests/fixtures/smith/*.ir.json` 共 **18** 个实体、
   其中 character **7** 个，带 material/color/build/detail 的 character **0 个**；
   放宽到 `moss_llm/smith/examples/*.json`（**11** 个实体、character **6** 个）同样
   **0 例**（合计 29 实体 / 13 character / 0 例）。本轮改了也测不到收益；为 1 例未知
   收益去动全部用户的确定性输出不划算。

**reopen 条件**：下一轮 60 图若显示「人物（真正的人）的材质绑定仍显著低」，
再开 c 并重冻基线；本轮把 1 例已知残余写进 §4。

## 2. 缺陷 2：JSON 模式无重复保护

### 2.1 根因（G7 实测）

40 次跑批里 **4 次整单归零**（A 3 次 / B 1 次），全部同一失败模式：
`finish_reason=length`，JSON 未闭合（重复循环撞 completion 上限）。

逐字特征：A · img07 有 34 个 label（16 种），`soldier left extremely far background` 与
`soldier right extremely far background` 各写 10 次；B · img07 的 32 个实体全叫
`soldier`；A · img10 有 49 个实体、`tent fabric` / `bedding` / `folding chairs` 各循环 7 次。

**为什么纪律拦不住**（对代码的诚实复核）：

- JSON 模式下 **DRY 全族 + presence/frequency 被摘除/归零**（纪律 4：键名会合法重复）；
  `repeat_penalty`（1.05）实际仍在发，但它只是 token 级弱约束，**从未被证明能压住这种
  整段循环**，且草稿纪律给人的是「JSON 下没有重复惩罚」的印象。
- `entities` 是**无上限数组**：语法约束允许无限追加元素，模型可以「语法正确地」写到
  completion 上限。因此真正的闸是**数组上限**，不是采样参数。

### 2.2 修法：三层防线（按生效档位各管一段）

| 层 | 实现 | 在哪一档生效 |
|---|---|---|
| ① 语法约束 | `EVIDENCE_SCHEMA.entities.maxItems = 40`；`TEXT_SCHEMA.blocks.maxItems = 80` | 服务端认 `json_schema` 时（最强档） |
| ② prompt 规则 | `SYSTEM` 规则 17：每个实体**只写一次**、不要重复同一 label、`entities` ≤ 40 | 所有档（含降级到 `json_object`/无约束） |
| ③ 收口兜底 | `coerce_ir`：`raw_entities >= MAX_ENTITIES` 时 warn「疑似截断，请人工确认」＋ `Report.capped/capped_at`；`> MAX_ENTITIES` 再截断并写进 `report.dropped`（`实体数 49 超过上限 40，已丢弃多出的 9 个（重复循环的典型形态）`） | 最终 IR 层，任何档都过 |
| ④ 次级防线 | `server.py` 的 JSON 请求**显式保留 `repeat_penalty`**；自定义 sampling 没给时补默认值 1.05（`body.setdefault`） | 请求层 |

**④ 的取舍**：DRY / presence / frequency 仍然在 JSON 下摘除/归零（它们按段/频次判重，
会惩罚合法重复的键名）；`repeat_penalty` 是 token 级、不按段判重，语法约束下键名由
grammar 兜住，保留它不会把 `"label":` 惩罚成乱码。它是**次级**防线，本轮不宣称单靠它
就能压住循环——主闸是 ①/②/③。

### 2.3 不伤 JSON 合法性 / 既有行为（单测钉住）

- schema 仍是合法 JSON；`required` 仍只有 `canvas/style/entities`（不逼供）；`kind` 枚举未动。
- `chat_template_kwargs.enable_thinking=false` 未回归；结构化输出四级降级阶梯未回归
  （第 0 档 `json_schema` → 第 3 档无约束，仍有末档且不静默）。
- JSON 请求：`presence_penalty==0`、`frequency_penalty==0`、无 `dry_*`、有 `repeat_penalty`；
  自定义 `repeat_penalty:1.3` 原样保留。
- 非 JSON（散文）请求：DRY 保留、`repeat_penalty` 保留、不强行注入 presence/frequency——
  采样纪律不变。

### 2.4 对确定性输出/基线的影响：零

只动请求参数与取证 JSON 的约束，不碰确定性编译路径；freeze/coverage 均绿（§1.3 同一次实测）。

### 2.5 `maxItems` 截断不可见：已加 capped 告警（G7 审计发现）

**机制**：服务端认 `json_schema` 时，`EVIDENCE_SCHEMA.entities.maxItems = 40` 会在**语法层**
先把重复循环截停。`coerce_ir` 看到的已经是 40 条合法 JSON——于是：

```
模型重复循环 → 语法层在 40 条截断 → coerce_ir 收到 40 条 → report.dropped=[]、无告警
⇒ 用户以为成功，实际拿到 40 个重复实体；下游把 40 个重复主体写进 prompt，分母被灌大
```

这与「失败必须可见」的纪律矛盾。**修法**（两条路径同一口径）：

- **smith 路径**（`reverse.coerce_ir`）：`len(raw_entities) >= MAX_ENTITIES` 时立即
  `r.warn("实体数达到上限 40：疑似截断，请人工确认（…重复循环可能已被 json_schema 的
  maxItems 静默截断…）")`，并置 `Report.capped=True` / `capped_at=len(raw_entities)`
  （`to_dict` 新增两键，向后兼容）；超过上限时照旧截断 + `dropped`。
- **节点路径**（`guard_caption_json`）：`subjects/props/materials/text` **达到**各自上限
  （不只是超过）就在 report 写 `反推实体上限（capped）：…（达到上限 N；疑似重复/截断，
  请人工确认）`；超过上限的仍截断并报丢弃数量。

**措辞纪律**：恰好 40 个合法实体也可能——所以是「疑似截断，请人工确认」，不是断言；
39 个及以下不告警（避免把告警变成噪音）。测试：40 → capped、39 → 不告警、
节点 subjects=12/props=32 → capped 出声。

**验证状态**：**已验证**——本机 **25/21** 条单测 + 构造 **39/40/41** 三档探针（41 时 `capped_at`
是原始条数、IR 截到 40）；**未验证**——真实服务端的语法层截断行为（本轮无可用 json_schema
端点）；「恰好 40/12 个合法画面」的误报率也没有真机数据。

## 4. 未验证 / 边界 / 未接线（诚实清单）

1. **效果未测（最重要的未验证项）**：本轮不做 GPU 跑批。材质绑定覆盖率、物体编年龄数、
   跑崩率的前后变化**没有测量**；离线只能给分母（类型闸命中 58 个可被降级；character∧
   material 58 个、类型闸覆盖其中 57 个，剩铜鹰雕像 1 例；4/40 失败样本的特征），
   **不给幅度结论**。由下一轮 G7（60 图）测量。
2. **b 的误伤边界**：一个「没有人物字段但带 material」的拟人角色（例如被材质覆盖的
   吉祥物/雕像）会被降级成 object。判据只用字段、不猜语义，所以这类会误降级——但
   `Report.kind_downgrades` 逐条出声，可人工复核；误伤率留给下一轮统计。
3. **maxItems=40 的截断风险**：超密 UI 截图（文字块很多）可能真实超过 40 个实体；
   G7 实测最大 49 全部由重复循环产生（正常图 3–8 个）。**达到上限即 warn + `Report.capped`
   （恰好 40 个合法实体也会触发，措辞是「疑似截断，请人工确认」）**；真正超过上限时
   `report.dropped` 点名数量和丢弃数，不静默。
4. **`repeat_penalty` 未加码**：值仍是 1.05；本轮只把它变成「JSON 下显式保留 + 缺省补上」，
   没有证据支持调更高（未跑真机）。主闸是 schema/prompt/coerce 三层。
5. **c 案残余**：`bronze eagle statue` 这类 1 例仍走人物分支（材质不在实体子句），见 §1.4
   reopen 条件。
6. **节点路径未接线（follow-up，不在本任务写域）**：ComfyUI 节点 `MossPromptSmith` 的
   caption 路径使用自己的 prompt pack（`moss_llm/prompts/`）与自己的请求构造
   （`nodes.py::_chat`，只发 `json_object`、不带本轮的字段约束/repeat 保护）；本任务的
   `reverse.py` / `server.py` 修复覆盖的是 smith LLM 路径（CLI reverse、G7 工具链、
   洗图基准的 LLM 段）。节点 `compile` 路径经 IR 受益。若要让节点 caption 也拿到这两条
   保护，需要在 `nodes.py` + `moss_llm/prompts/` 做等价改动——**建议另开任务**，本轮
   不碰别人写域。
7. **CI 清单**：`tests/test_caption_quality.py` 需要加进 `.github/workflows/ci.yml` 才会被
   CI 跑到；该文件不在本任务写域，已报 Lead。
