## 7. 发现的问题（只记录，未改任何被复核文件）

### F1（严重）复制 workspace 进自身子目录 ⇒ GNU cp 直接报错

- 位置：`host-matrix` 第 05 步、`windows` 第 05 步，均为
  `mkdir -p "$MOSSSB_PATH"; cp -a "$GITHUB_WORKSPACE/." "$MOSSSB_PATH/"`。
- 原因：`MOSSSB_PATH = ${{ github.workspace }}/comfyui/custom_nodes/ComfyUI-MOSS-Storyboard`，
  而 `git clone ... comfyui` 已把宿主放进 workspace ⇒ **目标在源内部**。
- 复现（本机 Git GNU coreutils cp，与 ubuntu runner 同源）：
  ```
  cp: cannot copy a directory, '<ws>/.', into itself, '<ws>/comfyui/custom_nodes/MOSS/'   （exit 1）
  ```
- 影响：Actions bash 默认 `-e` ⇒ 第 05 步必红；即使不 `-e`，dest 只剩空目录，后续
  `[阻塞] 纯节点冒烟` 也必红 ⇒ **host-matrix（2 版本）与 windows 全部红**。
- 建议修法：宿主 clone 到 workspace **外**（如 `${{ runner.temp }}/comfyui`，并同步 env 路径）；
  或复制时排除 `comfyui/`（`tar --exclude=./comfyui -cf - . | tar -xf -` / `rsync --exclude`）；
  或先复制仓到 custom_nodes、再 clone 宿主。

### F2（严重）新增示例节点 title 触发 check_frontend F4 红

- 位置：`examples/llm-compile-zero-model.json`（生成器 `tools/make_compiler_example.py:304`）：
  `"title": "MOSS Prompt Smith（task=compile · 零模型）"`。
- `check_frontend.py::f4_titles`：只接受 `title == d or title.startswith(d)`，其中
  `d ∈ {nodes_zh[t], nodes_en[t]}`；当前 `MossPromptSmith` 显示名是 `🖊 提示词工匠` /
  `🖊 Prompt Smith`（`legacy: "MOSS Prompt Smith"` 只在 i18n legacy 表里，F4 不认）。
- 实测：`check_frontend.py` = **19/1**，`[FAIL] F4 ... ["llm-compile-zero-model.json: ... title='MOSS Prompt Smith（task=compile · 零模型）'"]`，rc=1。
- 影响：`unit`（step 32）与 `windows`（step 08）都红 ⇒ F1 之外的第二、第三个红点。
- 建议：① 改 title 为「空」或以当前显示名开头且**后缀用英文**（如 `🖊 Prompt Smith · zero-model compile`）；
  ② 或让 F4 接受 i18n 声明的 legacy 前缀（与前端 `swapTitle` 对齐）——但不要把「自定义中文后缀」合法化。

### F3（高）windows 第 09 步在「无 `.git` 的副本」里跑 git 依赖检查

- 位置：windows 第 05 步 `rm -rf "$MOSSSB_PATH/.git"`；第 09 步 working-directory=`MOSSSB_PATH`：
  `python tools/check_release_ready.py` + `python tools/make_dist.py --verify`。
- 复制场景实测（把仓库复制到临时目录并删 `.git`）：
  - `check_release_ready.py` → rc=1，`[FAIL] 仓库里有受控文件 0 个`（`git -C ROOT ls-files` 返回空）；
  - `make_dist.py --verify` → `subprocess.CalledProcessError`，`git ... ls-files -z` exit 128。
- 影响：即使 F1/F2 修好，windows job 仍红。
- 建议：卫生闸/`make_dist` 从**原始 workspace** 跑（absolute path 或 `working-directory: ${{ github.workspace }}`），
  或保留副本 `.git`（并排除未跟踪的宿主目录）。顺带：`check_release_ready` 在无 git 时表现为
  「受控文件 0 个」红（不是静默放过），这点是好的。

### F4（低）ci.yml 头部计数注释过期

- 无参 `check_ui_workflow.py` 实测 **17/0**（注释 15）；逐文件项数实测：

- 建议：把 ci.yml 文件头与 docs/44 §3 的逐文件数字更新，或只保留「合计 210」并去掉易漂的逐文件表。

### F5（低）docs/44「本机同一批脚本全绿」精度问题
