## 二、决定不做（每条都有理由，不是漏了）

| 决定 | 理由 |
|---|---|
| **不做 batch>1 的多版输出** | 4 步很便宜；多版用 seed 队列即可。做 batch 会把"一格一裁"的语义和显存占用一起复杂化 |
| **不内置 tiled VAE decode** | 宿主已有 `VAEDecode (Tiled)`；内建会重复实现且难覆盖所有边界（用户可直接替换这一环） |
| **后端 tooltip 保持中文** | 中文只在后端写一份、英文在 JS（避免两处漂移）。代价：JS 未加载时英文用户看到中文——已在 README「节点中英切换」明写 |
| **不自动下载权重** | 体积、许可、国内网络三重问题；MOSS 权重由用户自备 |
| **不硬拦 >4MP 画布** | 显存差异太大（24G/48G/96G）。只 warn + 在 `report` 里写清楚，把决定权留给用户 |

## 三、未覆盖（诚实记录，别当成已覆盖）

1. **成片质量没有量化评分**。只验证了"能出、尺寸对、格子与描述大体对应"。
   要量化需要人工标注集 + 打分口径，不在本轮范围。
2. **CI 的 `host` job 未在真 runner 上验证过**（本机是 Windows）。
   已设 `continue-on-error`，等它在 main 上连续绿几次再改成阻塞。
3. **只在 Windows + 单卡验证**。代码里没有平台分支（除工具里的路径兜底），但 Linux/macOS 未实证。
4. **英文 README 没有节级同步闸**（`en_sync.py` 那类工具未移植），只标了"节选翻译"。
5. **中英提示的语义一致性无法自动对读**：中文在后端、英文在 JS，两边行数不可比。
   「中英行数一致」这条判据只在单文件表结构下成立，本包结构不适用。
6. **前端"看得见"这件事没有自动化闸**。写过 `tools/ui_smoke.mjs`（无头浏览器）但本机
   chromium 无 WebGL，画布 `canvas is null`、节点不渲染 ⇒ 结论不可信，已降级为可选诊断。
   现在靠：控制台两行日志 + `MOSS_SB_LANG.where()` + 人眼。
7. **未做多实例/并发测试**：两个 ComfyUI 同时跑同一工作流未验证（几何是纯函数，理论上无共享状态）。

## 四、风险登记

| 风险 | 触发条件 | 影响 | 现有防线 |
|---|---|---|---|
| 宿主改内核签名 | ComfyUI 升级 | 采样崩 | `probe_host_api` 给人话错误；`requires-comfyui` 下限 |
| 界面汉化插件回写 | 装了中文翻译插件 | 英文界面露中文 | 1.5s 兜底轮询 + `__mosssbWant` 标记 |
| 用户手改 spec | 手编工作流 | 裁切错位 | `parse_spec` 严格校验 + 尺寸不符直接 raise |
| 大画布 OOM | `panel_edge` 调大 | 进程被杀 | `report` 强 warn（>2MP / >4MP） |
| 布局框不生效 | MOSS 布局为 experimental | 格子内容不按描述 | 默认叠加"复绘宫格线"；README 明确未量化 |
| 模板路线被误用 | 用户按 Krea2 老习惯接线 | 黑图 | 0.1.2 起**移除通路**：`init` 无 `template/both`、采样器无模板输入，堵死比标注更彻底 |

## 五、下一轮建议（按性价比排序）

1. **做一次成片评分**：20 个镜头 × 4/8/9 格，人眼打分 ≥3 档，得出"格数上限"的实测结论。
2. 把 `host` job 转成阻塞，并加一个 Linux 实机跑的 e2e（CPU 也能跑 4 步？——不能，仍需 GPU，故用 runner 只能到装载层）。
3. 给 `spec` 加版本号迁移器（`MOSS-SB1` → 未来 `MOSS-SB2`），保证老工作流能读。
4. 英文 README 加节级同步闸（`en_sync.py` 那类工具），消除手工漂移。
