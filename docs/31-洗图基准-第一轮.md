## 1. 流水线

```
源图 ──⓪入库(sha256/尺寸)──▶ sources/
     ──①反推(VLM, llama-server)──▶ IR(.ir.json) + 取证报告(.report.json)
     ──②编译(零模型, moss_llm.smith.api.compile_ir)──▶ prompt + issues/invariants（每后端一份）
     ──③出图(ComfyUI POST /prompt)──▶ PNG
     ──④triage(纯 numpy/PIL，零模型)──▶ score.json
```

**为什么拆四段**：四步失败的样子不同——反推失败是「没看见」，编译失败是「后端装不下这句话」，
出图失败是「宿主/权重」，打分失败是「判据自己坏了」。每步各自落盘，
重跑某一步不用重烧前面的 GPU 时间（`--caption` / `--generate` / `--score` 可单独跑）。

| 段 | 入口 | 占 GPU | 产物 |
|---|---|---|---|
| ⓪ 源图入库 | `--stage` | 否 | `sources/{id}.png`（另存副本）、`sources.json`（sha256 / 尺寸） |
| ① 反推 | `--caption` | 是（llama-server） | `captions/{id}.ir.json`、`.report.json`、`captions/manifest.json` |
| ② 编译 | 随 `--generate` | 否 | `compile/{backend}/{id}.json`（positive / token / issues / invariants） |
| ③ 出图 | `--generate` | 是（ComfyUI） | `workflows/{backend}/*.api.json`、`images/{backend}/{id}.png`、`run.json` |
| ④ 打分 | `--score` | 否 | `score.json` |
| 目检拼图 | `--compare` | 否 | `images/{backend}/{id}.compare.png`（源图 \| 出图） |

源图另存进 `sources/` 是为了产物自包含：原图被挪走也能复核 sha256 与重跑反推。

### 2.1 反推口径（第一段怎么跑）

- 侧车：llama-server + 一个能看图的 GGUF（本轮用 6G 档的 Qwen3.5-4B QUASAR + F16 视觉塔，
  T1 已核实）、ctx=16384、temperature 0.1、max_tokens 8192；加载 4.5 s，4 张源图共约 2 分钟。
  **权重与 llama-server 的可执行文件不写死在代码里**（公开仓要求）：按
  `--model/--mmproj/--server` → `MOSS_LLM_MODEL`/`MOSS_LLM_MMPROJ`/`MOSS_LLM_SERVER`（或
  `G7_MODEL`/`G7_MMPROJ`/`G7_SERVER`）→ `moss_llm.server.find_server_exe()` 常规查找；
  一个都找不到时明确报错，不猜本机路径。
- 反推走 `moss_llm/smith/reverse.py` 的 `caption.faithful` 口径（取证不创作），
  并落 `.report.json`（warnings / raw_chars / text_pass）。
- **满屏文字的 UI 截图需要降级**：场景记录会写很长的结构，实测在 ctx=8192 时
  llama-server 日志出现 `n_tokens = 8191, truncated = 1`（JSON 没闭合）。
  处理：ctx 提到 16384 + scene 失败时**只跑文字专线重建 IR**（`reverse_mode=text_only`），
  ui-text 由此拿到 **25 个文字实体**。其余 3 张是 `scene+text` / `scene+text_rescue`。
  如实记录：这不是提示词问题，是 token 预算问题。

## 3. 打分口径与校准状态

### 3.1 为什么没有 VQAScore

| 检查项 | 结果 |
|---|---|
| Python 包 | 本机环境 **没有** `vqascore`（`import vqascore` 失败） |
| 模型权重 | 本机无 VQAScore 所需评测模型（CLIP/BLIP 系权重不在本机） |
| 元评估 | 未做「VQAScore 分数 vs 人类偏好」的一致性/ECE 校准 |
| 网络 | 依赖外部下载，且不在本轮时间预算内 |

结论：**VQAScore 未运行**。按任务口径退到本地可复现的代理指标，并显式声明
`metric.calibrated = false`、`metric.not_for_gating = true`。

### 3.2 代理指标（proxy-v1）

| 分量 | 怎么算 | 权重 | 为什么 |
|---|---|---|---|
| `structure` | 64×64 灰度 z-score 后与源图的 Pearson 相关（映射到 0..1） | 0.40 | 构图/空间布局漂没漂 |
| `palette` | HSV 三分量直方图的 Bhattacharyya 系数（色相 0.5 / 饱和 0.25 / 明度 0.25） | 0.25 | 调色漂没漂 |
| `luma` | 灰度均值/标准差的接近度 | 0.15 | 整体曝光/对比保没保住 |
| `saturation` | HSV 饱和度均值差 | 0.10 | 过曝/过饱和/灰掉 |
| `edge` | 梯度幅值均值的相对差 | 0.10 | 变糊/变锐（细节密度） |
| `aspect_match` | 宽高比一致性（单独记录，不进加权分） | — | 这是硬结构，不匹配直接记为异常 |

`triage_index` = 加权平均（0..1，越大越接近源图）。**它只回答「漂了多少」，
不回答「图好不好」**。分差 <0.02 视为噪声（同一后端不同源图的离散度就大于它）。

### 3.3 校准状态

- 未做与人类偏好的相关性检验（ρ / 翻转率都没测）⇒ **不能当质量结论**；
- 未做跨后端分数可比性检验 ⇒ 只用于**同一后端内的回归/triage**；
- 因此：本轮所有分数都标「代理指标，未校准，只 triage，不作放行闸」。

## 5. 观察（AI 读图，不是人类目检）

逐张看 `out/wash_benchmark/images/<backend>/<id>.compare.png`（左源图 / 右生成）：

1. **图内文字是最硬的天花板**。`ui-text` 两后端都重绘成「界面/海报风」：
   krea2 prose 版出现 `Unsaved vforkflow`、`MOSS-Storyboard` 等大量错字；
   MOSS 走 Layout JSON，版式更像界面但文字几乎全错。**洗图不能用来保文字**，
   要保字只能后面叠排版/编辑器。
2. **身份漂移**。`portrait` 两后端都保住了「动漫风 + 咖啡磨豆机 + 齿轮背景」的设定，
   但主角**换了个人**（脸型/五官/发型细节都变）；krea2 比 moss 更接近原画风。
   这与 `docs/07` 的机制结论一致：只有文字约束，没有像素约束。
3. **构图骨架反而相对稳**。`street` 两后端都保住「街道 + 右侧水塔 + 左侧店面 + 逆光」，
   但具体物件被重建：krea2 版新增了围栏、行人、塑料袋，水塔位置/形态变化；
   源图右下角的水印「豆包 AI 生成」被放大重绘到生成图右下 —— 洗图会把水印当内容。
4. **材质/光线大体保留、构图细节重建**。`material` 的「石墙 + 石柱 + 侧窗光」保住了，
   但湿地反射、柱子位置、窗洞形状变化。
5. **编译体检的 error 只在部分后端/部分源图出现，且不阻断出图**（8/8 成功）。按后端计数：
   - `moss-image` 4 份：**2 份各 1 条 L006**（street/material 的角色缺 `age_years`）；
     **ui-text 走 Layout JSON，0 error**、portrait 也 0 error。
   - `krea2` 4 份：**3 份有 error** —— ui-text 1 条 **L010**（文字未逐字出现，prose 路径），
     street/material 各 1 条 L006。
   - `qwen-image-2_1`（未出图，仅编译过）：与 krea2 同形（ui-text L010、street/material L006）。
   所以「UI 截图报 L010」只对 **prose 后端**成立；MOSS 的 Layout JSON 路径没有这条。
   这组 error 说明 IR 取证口径与 MOSS/方言的硬闸之间还有缝（下一步：反推时给背景人物补年龄、
   文字实体补逐字引用），不是出图失败。

## 7. 局限

1. 代理指标未校准，不能当质量结论，更不能当放行闸；
2. 4 张源图、2 个后端、每对 1 个 seed：只能当**机制演示**，不是基准结论；
3. 洗图天然漂身份/构图（文本重绘的机制边界）——分数低不一定是「模型差」，
   可能是「这张图的来源细节本来就无法用文字保住」；判读时要分开；
4. Qwen 后端实际跑的是 Flash（且未跑通），不是 registry 的 2.1 PE；
   MOSS/Krea 用的是 turbo 蒸馏档，与 registry 默认采样档不同；
5. 文字保真没有 OCR 机检，只有 AI 目检结论；
6. 两后端均值差 0.06：样本 4 张、无置信区间、代理指标未校准 ⇒ **只报数，不下结论**；
7. **Qwen 失败的因果未独立复核**：只确认「宿主日志时间线与 run.json 的 connection refused
   对得上」，宿主日志是仓外文件（原文片段已复制到 `out/wash_benchmark/qwen_restart.log`，
   未入库）；不要把它写成「已证实是看门狗导致」。

## 8. 下一步（按性价比）

1. **装 VQAScore + 元评估**：拿 30–50 对图做人类偏好标注，测 ρ 与翻转率；不过校准不许当闸；
