## 3. `reverse()` 端到端与 API 兼容

用 stub llm（`chat_vision` 返回固定 JSON）+ 打桩 `prepare`（64×64 假 Prepared）跑真实 `reverse()`：

| 场景 | 结果 |
|---|---|
| 40 条 / 8 label 循环响应 | 抛 `ReverseError`；`exc.report` 是 `Report`、`capped=True`、`capped_at=40`、`raw_chars` 已记录；未进入文字专线（未产生 IR） |
| 普通 2 实体响应 | 返回 IR（2 实体）、`report.capped=False` —— 成功路径未回归 |

API 兼容性（直接构造）：

- `ReverseError("消息").report is None`（旧单参调用不受影响）；
- `ReverseError("消息", report=rep).report is rep`（同一对象）；
- `isinstance(ReverseError(...), RuntimeError)` 仍为真（异常类型兼容）；
- `coerce_ir` 未传 report 时，异常对象仍带一份可读 `Report`；
- `Report.to_dict()` 旧键（image/size/warnings/dropped/entity_count/age_gate/raw_chars/kind_downgrades/age_dropped）全部保留，`capped`/`capped_at` 仍在。

## 7. 发现（均为轻微，不影响 PASS）

**F1（文档数值，建议改）**：`docs/56` §2.2:68 与 §5:119 把「40 条里 1 条重复」标成「~5% / 5%」，
实际 1/40 = **2.5%**；任务卡原例是「2 条 = 5%」。建议改成「2 条（5%）」或「1 条（2.5%）」；
若改用 2 条，建议同步测试用例（当前测试用 1 条）。功能无影响：矩阵 M11/M12 证明两种都正确合并。

**F2（文档覆盖面，建议补一句）**：`docs/56` §1:29 只写 A-4B 的 3/20、10/60。G7 §8.2 已列出
B-9B `img51/img58` 两张 40 实体；本回复放确认 **B-9B 60 图也会有 2 张显式失败**。
建议 §1 补一句 B 臂规模（否则读者会以为只有 A 臂受影响；round3 若跑 60 图，B 失败数应记 2）。

**F3（文档遗漏，建议补一行）**：`coerce_ir` 与 `decompose.py` 共用（`task="decompose"`），
新闸在 prompt 分解路径也会触发，被 `_from_llm` 包成 `DecomposeError("抽取为空：…")` ——
