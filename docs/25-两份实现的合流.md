# 两份实现的合流：谁强、留谁、代价是什么

> 2026-10-31。起因是 `moss_llm/smith/` 里五个模块的 docstring 各自挂着一句
> 「本版并存，下一版二选一」。那句注释本身就是问题：**两份实现都在长，而没有一条测试
> 能发现它们已经不一致**。这一版把它们收敛掉，并把取舍写成可复查的账。

## 一、两份实现从哪来

| | A：节点侧 | B：编译器侧 |
|---|---|---|
| 落点 | `moss_llm/nodes.py` `server.py` `pack.py` `runtime_install.py` `prompts/` | `moss_llm/smith/`（`ir.py` `adapters/` `decompose.py` `h3.py` …） |
| 承诺 | 一次调用出成品提示词 + report | 同一份事实换后端，事实不丢 |
| 引入 | 2026-10-30（b90c562），有真机验证 | 2026-10-31 并入，有 300+ 条单测 |
| 强项 | 进程管理、显存、装包、i18n 面板、与 ComfyUI 一体 | 确定性、多方言、不变式、往返、H3 时间线 |

两边**不是同一个东西的两种写法**，是同一层的两半：A 负责「把模型跑起来并问出一句话」，
B 负责「这句话里的事实能不能换一种说法而不丢」。真正该合的只有**五个重叠模块**。

## 二、重叠面的逐项对照

判据不是「谁代码多」，而是「这一项出过错时，哪一份的判据能抓住」。

### 1. 侧车（`server.py` ↔ `smith/llm.py`）

| 能力 | A `GgufLocalServer` | B `LlamaServer` | 取谁 |
|---|---|---|---|
| fit / fit-target（显存适配） | ✅ | ❌ | A |
| KV cache 量化 / ubatch / parallel | ✅ | ❌ | A |
| MTP 元数据判定 + 起不来时回退并出声 | ✅ | ❌ | A |
| GGUF 头部只读解析（毫秒级） | ✅ | ❌ | A |
| mmproj 按投影宽度硬配对 | ✅ | ❌ | A |
| `--help` 探测（老版本没有 `--jinja`） | ❌ | ✅ | B |
| 日志落盘 / 启动失败能看到原因 | ❌（DEVNULL） | ✅ | B |
| attached 模式（连别人跑着的端点） | ❌ | ✅ | B |
| JSON 约束三级降级 + 每降一档出声 | 一档 | 四档 | B |
| JSON 模式清零重复惩罚 | ❌ | ✅ | B |
| `build_body` / `build_cmd` 可离线单测 | ❌ | ✅（body） | B |
| LoRA 适配器 | ❌ | ✅ | B |
| alias 用完整路径（同名不同目录不撞） | ❌（只用文件名） | ✅ | B |

结论：**一个类，取并集**。位置放父包 `server.py`（B 的 `llm.py` 转发过去），
因为父包的节点是主要使用者，而 B 的测试本来就按「类」写、不按文件写。
`GgufLocalServer` 保留成薄壳（只做「复用还是新建」的判断），节点与既有测试零改动。

### 2. 装运行时（`runtime_install.py` ↔ `smith/runtime.py`）

A 有：镜像链（国内可用）、GitHub digest 的 sha256 校验、断点续传、慢速源中止、
原子替换（`runtime.new` → `runtime.old`）、摊平目录（DLL 必须和 exe 同级）、
按 `Win32_VideoController` 判厂商（不依赖 nvidia-smi）、CUDA 能力表 + 驱动上限。
B 有：纯函数 `pick_asset` / `pick_cudart`（可离线单测）、装到用户主目录。

B 除了「纯函数好测」以外**全面弱于** A：无摘要、无镜像、无续传，
解压到一半失败会把可用的运行时砸掉。→ **删 B**，`smith setup` 调父包。
B 的两个纯函数所守的语义（平台命名差异 / CUDA 版本配套）改写成针对 `runtime_install._pick`
的测试，一条都没丢。

### 3. 找可执行文件（`server.py:find_exe` ↔ `smith/paths.py`）

搜索顺序本来就不一样：父包多认 `LLAMA_CPP_HOME` 与包内 `runtime/`，
B 多认旧环境变量名。→ **只留父包一个答案**，`smith.paths.find_llama_server` 转发；
`supports_flag` 也改为走父包那份带缓存的 `--help`（原来每次起一个进程）。
`model_dirs` / `find_files`（模型目录约定）父包没有，留在 `smith/paths.py`。

### 4. 图像预处理（节点 `_b64_png` ↔ `smith/vision.py`）

| | A | B |
|---|---|---|
| 尺寸 | **原始尺寸直传**（1536×1024 能吃一两千视觉 token） | 最长边 1536 |
| 编码 | PNG（4:2:0 糊小字的问题躲不掉） | JPEG q95 subsampling=0 |
| EXIF 方向 | ❌ | ✅ |
| 透明通道 | ❌（RGBA→RGB 变黑底） | ✅ 合成到白底并出声 |
| 多帧 | 取第 0 帧 | 取第 0 帧 |

→ 搬到父包 `moss_llm/vision.py`，两个入口：`prepare(path)` 与 `prepare_tensor(IMAGE)`。
节点换用它之后，图内小字更清楚、token 更省，且降级说明会进 report。

### 5. 提示词来源（`prompts/*.txt` ↔ B 里的硬编码 SYSTEM）

这两者**不是重复**：
- `prompts/*.txt` 是「怎么写出成品提示词」的指令（任务契约），带 sha 清单防篡改；
- B 的 `reverse.SYSTEM` 是「怎么取证」的指令（输出 IR schema），两段式里的第一段。

任务不同，留两份。但要注意它们共享的是**约束不能打架**：`must_keep` 逐字、
图内文字原样、不编看不见的东西——这三条两边都写了，改动时两边都要改。

## 三、合流时抓到的六个真 bug

「两份都对、合起来错」这一类，只有合并时才暴露；下面每条都写了**怎么发现的**。

1. **服务端口令会静默打挂真实 token 计数。**
   A 给侧车加了 `--api-key comfyui-local`；B 的 `ServerCounter` 要 POST `/tokenize`。
   带口令的服务回 401，而 `ServerCounter.count()` **捕获异常后退回估算**——
   真实 token 数被静默降级成 ±15% 的猜测，report 里看不出来。
   → 不再设服务端口令（进程本来只绑 127.0.0.1），客户端侧保留 `api_key` 供外部端点用。
   **判据**：`build_cmd` 里断言 `--api-key` 不出现。

2. **CUDA 主包和运行库版本不配套。**
   `_cudart` 找不到同版本就退回**最低**版本 → 出现「主包 cuda-13.4 + 运行库 cuda-12.4」，
   装完是加载失败，而错误只会说某个 DLL 找不到。
   → 只挑「有同版本运行库」的主包；一个都没有就返回空，让上层换 build。
   **判据**：`test_cuda_never_pairs_main_with_a_different_cudart`。

3. **未知后端会静默换成 CUDA 包。**
   `_pick` 原来有 `next((b for b in (backend, "cuda", "vulkan", "cpu") if b in by), None)`
   ——给 Intel 卡装 CUDA 包，装完跑不起来，报错还指向「显卡驱动」。
   → 要哪个给哪个，没有就空。（这条是 B 的旧测试守住了、A 的实现漏了。）
   **判据**：`test_unknown_backend_returns_empty_not_a_wrong_package`。

4. **一条测试跑不到，因为路径拼错了。**
   `tests/test_smith_ir.py` 里 `ROOT / "moss_llm.smith" / "data" / …`（用了点号）。
   在装了 PyYAML 的解释器上必红，在没装的上**被 skip 掩盖**。
   → 改成 `"moss_llm" / "smith"`。教训：skip 不是通过；「本机绿」不等于「三种 Python 都绿」。

5. **装了 torch 但传 numpy 会炸。**
   `_to_uint8_array` 原来按「torch 装没装」分流：装了就用 `t.to(torch.uint8)`。
   传 numpy 数组时 AttributeError，而调用方看到的是「预处理失败」。
   → 先 `isinstance(image, torch.Tensor)`，再退 numpy。

6. **前端门禁读不到带引号的枚举键。**
   `check_frontend.py` 的 F7 用 `([\w:.\-]+):\s*"` 抓 COMBOS 的键，不认 `"moss-image":`。
   于是带连字符的后端名永远「缺中文」，而表里其实写了——一条**假红**，
   长期看会让人习惯性忽略这条门禁。
   → 正则允许可选引号。

## 四、合流后节点多了什么：`task=compile`

原来 IR 编译器只有 CLI，ComfyUI 用户碰不到。现在同一个节点里：

```
task=compile → 把 IR（JSON / YAML / 文件路径）贴进「文字输入」
            → target 选后端（moss-image / qwen-image-2_1 / krea2 / flux3 / flux1_dev / sdxl / minimax-h3）
            → 毫秒级返回提示词 + report（方言机检 + M1–M6 + 砍掉的子句 + 采样建议）
```

三条性质值得单独说：

- **没有权重也能用**。四个任务里只有它不需要 GGUF、不需要 llama-server、不联网。
  「装了节点但没下模型」是开源用户最常见的第一次体验，以前那一次是报错。
- **可复现**。同一份 IR 编译两次逐字节相同（这条现在有测试守着）。
- **报告是判据不是结论**。`report` 里列 error / warn 逐条带修法，不给一个「成功」。

代价：`smith` 从「零依赖、删掉不影响任何人」变成「父包会懒加载它」。
所以 `_compile()` 里 `import` 失败时给的话术是「另外三个任务照常可用」——
删掉 `smith/` 目录，节点要能退化而不是崩。这一点有测试（§12 全绿即证明）。

## 五、没合并的两处，以及为什么

- **`smith/reverse.py` ↔ 节点的 caption 通道**：前者图 → 证据 → IR（可再换后端渲染），
  后者图 → 一段成品提示词（终点）。任务不同，判据也不同。留两份。
  但它们现在共用同一个侧车类与同一套图像预处理。
- **`smith/expand.py` ↔ 节点的 expand 通道**：前者 IR → 补齐欠定槽位（零模型、可验证长度带与固定项），
  后者一句话想法 → 一整段（模型在环、不可复现）。留两份。
  硬合成一个会得到一个既不可复现、又验不了的中间态。

判据：**不是「代码像」就该合，是「同一条判据该管同一件事」才合。**

## 六、防再漂移

两条机检，都是「拷贝一份就会立刻红」的写法：

1. `smith.llm.LlamaServer is server.LlamaServer` —— 转发必须是**同一个对象**，
   不是同名副本。谁哪天为了方便再抄一份，这条立刻红。
2. 节点的 `_TARGETS`（V1 参数表的镜像）必须与 `data/model-registry.yaml` 的 targets 一致。
   参数表为了不 import 编译器而自带一份列表，那就必须有东西盯着它别漂。

另外 `runtime.py` 是**删除**而不是留壳：留壳等于留一个「以后可以在这里加东西」的入口，
下次有人加进去就又变成两份。

## 七、遗留（诚实记录）

- 全部验证仍是单测 + 确定性冒烟，**没有一次真实出片**：`compile` 的产物好不好看，
  这一版没有判据，只有「事实没丢」的判据。
- LoRA（H3 rewriter）只做到「能拼 `--lora` / `--lora-scaled` 并能探测不支持」，
  **没有真跑**——缺基座权重。
- `task=compile` 只走确定性模式；`--mode llm`（让模型扩写）仍只在 CLI 里。
