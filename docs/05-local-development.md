# 本地开发与维护

面向**改这个包的人**。用户只需要 [`README.md`](../README.md)。

---

## 一、工作副本怎么摆

推荐**单一副本 + 目录联接**：仓库放在任意位置，`custom_nodes` 下只放一个联接。

```bat
mklink /J <ComfyUI>\custom_nodes\ComfyUI-MOSS-Storyboard <path\to\repo>
```

- **不要**在 `custom_nodes` 里放第二份拷贝：两份会被宿主各加载一次，后加载的那份静默覆盖节点定义，
  症状是"改了代码没生效"，且没有任何报错。
- 当前环境（Windows）实测：联接对宿主完全透明，`__file__` 解析到真实路径，热重启即生效。

## 二、宿主路径从哪来

开发脚本一律通过 `tools/_paths.py::host_root()` 解析，顺序：

1. 环境变量 `COMFYUI_PATH`（CI、多实例都用它）
2. 仓库根的 `.comfyui_path`（**本地文件，已在 `.gitignore`**，内容就一行路径）
3. 按标准安装位置推断（`<ComfyUI>/custom_nodes/<本包>/` ⇒ 上三级）

**不要**把盘符写回代码：那属于本地环境，不属于这个包。

## 三、两件容易被混为一谈的"重载"

| 改了什么 | 怎么生效 |
|---|---|
| Python（`nodes.py` / `core/` / `v3/`） | **重启 ComfyUI 进程** |
| 前端（`web/*.js`） | **刷新浏览器页面（F5）**——重启进程**不算** |

前端是单页应用：页面打开后扩展 JS 常驻内存，磁盘上换了文件、页面里还是旧的。
"改了没生效"的排查顺序永远是：先确认浏览器真的重新加载了，再怀疑代码。

## 四、改动后的验证顺序（从快到慢）

```bash
python tests/test_core.py               # 秒级，纯数学
python tests/test_contract.py           # 秒级，契约与词表
node   tests/test_i18n.mjs              # 秒级
python tools/smoke_nodes.py             # 十秒级，要宿主可 import
python tools/host_loader_check.py       # 十秒级，走宿主真实加载器
python tools/check_ui_workflow.py       # 十秒级，示例工作流槽位
python tools/check_frontend.py          # 十秒级，前端一致性
python tools/check_release_ready.py     # 十秒级，发布面
python tools/e2e_matrix.py              # 分钟级，要 GPU + 权重
```

前八条应全绿。最后一条是唯一能证明"别人机器上也能出图且尺寸对"的检查。

## 五、几处必须先知道的约束

1. **画布与单格的宽高必须是 16 的倍数**。对齐差额（0–15px）只加在右/下外边距，
   绝不改单格尺寸——改了，每格坐标就跟着漂，裁切与宫格线全部错位。
2. **`INPUT_TYPES()` 是参数表的唯一来源**。V3 schema 由它自动生成，不要在别处手写第二份。
   新增参数只能**追加到末尾**：`widgets_values` 按位置存，插在中间会让已有工作流参数静默串位。
3. **改了参数表必须重新生成示例工作流**；
   **改了 i18n 词表必须同时看 `placeholder`**（多行文本框的标题不是 `label`）。
4. **`seed` 在 V1/V3 两条出口上会差一个槽位**：V1 由前端自动补「生成后控制」，V3 必须显式声明。
5. **`denoise` 在低步数下会被宿主截断**：`int(steps/denoise)`。4 步时 0.85 等价于 1.0。
6. **`cfg=1` 时负面提示词不进计算图**（宿主的 cfg1 优化）—— 这也是它默认折叠的原因。
7. **发布包只收 git 跟踪的文件**，且路径必须是 **ASCII**：打包器按 latin-1 解路径，
   非 ASCII 文件名会被**静默跳过**（只在日志里留一行 `File not found`）。
8. **MOSS 没有原生 img2img**：模板初始化路线在本版拿不到有效重绘，默认走纯布局。

## 六、提交前自检

```bash
python -m ruff check .                  # 必须 All checks passed
python tools/check_release_ready.py     # 发布面：凭据 / 路径 / 临时件 / 打包 / 版本 / 元数据
git status --short                      # 必须干净（发布器只接受提交态）
```

## 七、写作规范（文档、注释、提交信息通用）

这个仓是公开的。写之前先想：**读者只有代码，没有人**。

- **不写内部沟通**：谁提的要求、什么时候提的、当时怎么讨论的 —— 一律不写。
- **不写本地环境**：盘符、用户名、家目录、另一台机器的路径。要举例就用 `<ComfyUI>` / `/path/to/...`。
- **不写情绪化的过程叙述**："踩了个坑"、"翻车"、"差点" 这类词不进仓库。
  要记录事实就写「X 在 Y 条件下不成立」。
- **时态就一种**：现在时陈述规则；需要溯源时给出**条件与结论**，不写叙事。
- **提交信息**：`type(scope): 一句话说做了什么`，正文写**为什么**与**影响面**，不写过程。
- **结论要分「已验证 / 未验证」**，这是唯一允许出现在文档里的不确定性表达。

判断标准很简单：**把它交给一个陌生人，他能不能只凭这些文字把事做对，且看不出这是谁的机器。**
