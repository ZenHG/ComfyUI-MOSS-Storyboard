## 3. 构造桩证据（A，脚本未入库，方法在 §7）

### 3.1 两遍式：pass1 → 护栏 → pass2

构造 pass1 返回：1 个真人物（带 `gaze/wardrobe`）+ 1 个 `kind=object` 磨豆机（带
`age_years=80`、`gender=male`）+ 13 个填充人物；props 20、materials 17、text 25；
pass2 返回 `{"caption":"final"}`。实测：

- 请求数 = 2；第 1 个 schema=`CAPTION_INVENTORY_SCHEMA`，第 2 个
  schema=`CAPTION_PASS2_SCHEMA`、system=pass2 文本、**image=None**。
- pass2 的 user 解析后：`subjects=12`、`props=21`；磨豆机不在 subjects、出现在 props
  字符串（含 `stainless steel`）；全 payload 不含 `age_years`/`gender`。
- report 依次含：`反推类型闸…subject[coffee grinder]：kind=object`、
  `反推年龄闸…age_years=80`、`反推实体上限：subjects 14→12…`、`双遍：第一遍盘点 …`。
- 返回值 = pass2 的 caption（`"final"`）。
- pass1 非法 JSON：只发 1 次请求、不跑 pass2、输出原文，report 写
  「第一遍盘点不是合法 JSON…已按单遍结果输出」。

### 3.2 单遍式

桩返回 oneshot JSON（caption + 20 subjects + 30 visible_text + 9 must_keep +
9 uncertainties）：`guard_caption_json` 后 12 / 24 / 8 / 8，notes 逐项报上限；
`_pick_prompt(obj)` 在 guard 之前算出的 caption 与 guard 后一致（**输出文本不被截断**，
F5）。

### 3.3 `_chat` 降级矩阵（桩 `_post` 按 payload 决定 400/成功）

| 场景 | 实际请求序列（括号内为 response_format 类型） | 结果 |
|---|---|---|
| 全 400 | (json_schema,R),(json_schema,-),(json_object,R),(json_object,-),(none,R),(none,-),(json_schema,-,无 thinking),(json_object,-,无 thinking),(none,-,无 thinking) | 9 次后抛可读错 |
| 只拒 json_schema | (json_schema,R)→400,(json_schema,-)→400,(json_object,R)→成功 | 降档并出声 |
| 只拒 repeat_penalty | (json_schema,R)→400,(json_schema,-)→成功 | 参数先摘，结构化档保住 |
| 结构化档+repeat 全拒 | 前 5 次 400，第 6 次 (none,-) 成功 | flag=`response_format`，降级出声 |
| 带 thinking 的全拒 | 前 6 次 400，第 7 次 (json_schema,-,无 thinking) 成功 | thinking 最后摘，结构化档保住 |
| `want_json=False` | 1 次，无 response_format / repeat_penalty | 不受降级逻辑影响 |
| `schema=None`（expand/edit 口径） | 首档即 json_object | 无 json_schema 档 |

其中 `R`=带 `repeat_penalty`；`-`=已摘。

## 4. 发现的问题（只记录，未改任何文件）

分级：**F1 必修**（护栏目标被绕过）｜**F2 设计需说明**（行为可接受，但文档/测试没把边界
说清）｜**F3–F6 文档精度**（不影响代码正确性）。

### F1【必修】未知 `kind` 跳过字段闸

`_caption_subject_is_object()`：

```python
if raw_kind in ("object", "prop", "scene", "background"): return True, ...
if raw_kind not in ("person", "character", ""):          return False, ""   # ← 直接放行
```

**复现（A）**：`{"subjects":[{"kind":"animal","appearance":"bronze horse statue"}]}`
→ guard 后仍留在 `subjects`，`environment.props` 为空、notes 为空。`kind:"people"` 同理。
在 `json_schema` 档 enum 会挡住这类值；但降级到 `json_object`/无约束后模型可能自由写
`kind`，此时物体既不进 props、也不出声。**影响**：pass2 仍可能把该 subject 写成人（与
护栏目标相反），且 report 无提示。**建议**：未知 kind 也走字段闸（或明确判 object），
并加 1 条单测。

### F2【设计需说明】显式 `kind:"person"` + 只有 appearance 也会被降级

**复现（A）**：`{"kind":"person","role":"woman","appearance":"shoulder-length black hair, pale skin"}`
→ 被挪进 props，notes 写「标为 character 但无人物字段、却带物体字段（appearance）」。
代码语义是「显式 person 仍受字段闸」——这一选择本身可辩护（模型也会把物体标成 person），
但 `docs/46` §4.3 的已知限制只写「背影/遮脸人物…只有 appearance」，未点明显式
`kind=person` 同受此闸；16 条测试也未覆盖该组合（真人物用例带 `gaze/expression/pose`）。
**建议**：§4.3 补一句 + 1 条测试钉住（避免未来把「显式 person 直接放行」当修复又引入
误放行）。附带：§0 表格用「已完成」，全文无「已验证」字样，建议加一行「已验证（本机
单测）」以贴合「区分已验证/未验证」的口径。

### F3【文档精度】「最多 7 次 400」与实测不符

`docs/46` §5 写「四级降级在『服务端全不认』时最多 **7 次 400**」；实测带 schema 时最坏
**9 次请求**（全部被拒即 9 次 400，最后抛错），非 schema 路径 6 次。**建议**改为实测口径
（或说明 7 只算了部分组合）。

### F4【文档精度】「12 个文件 sha 全部更新」

`docs/46` §2.1 写 manifest「12 个文件 sha 全部更新」；实测重新生成后**只有 2 个条目**
（caption.pass1/2）的 sha 变化，其余 10 个重新计算后与原值相同。**建议**写「重新生成
manifest，实际变更 2 个条目」。

### F5【文档精度】单遍式上限不改写输出文本

单遍分支先 `_pick_prompt(obj)` 取 caption，之后才 `guard_caption_json(obj)`；因此数组
上限只影响 report 与机检所用 obj，**不会截断用户看到的那段 caption 文本**。
`docs/46` §2.2「单遍式…主要是数组上限」容易被读成「输出会被截断」。**建议**明确「单遍式
的上限是 report/机检口径，不改写 caption 文本」。

### F6【文档精度】降级 subject→props 的字段丢失

`_caption_subject_to_prop()` 只保留 `role`/`appearance`/`position`；`count`、
`wardrobe`/`pose`/`gaze`/`hands`/`feet` 在挪进 props 时静默丢弃（只按类型闸整条报一句）。
**复现（A）**：`{"kind":"object","role":"mug","count":2,"appearance":"ceramic"}` →
props=`["mug — ceramic"]`（数量 2 消失）。物体语义下 `wardrobe/pose` 多半无意义，但
`count`（几只杯子）可能值得保留或至少出声。**建议**：按「保留 count 或 report 点名丢
count」二选一，并写进 docs/46 §2.2 的丢弃字段清单。

## 7. 复现方法

复核用临时脚本未入库，核心做法可复现（三条最小片段）：

```python
# 1) 两遍式：桩 _chat，断言 pass2 收到护栏后的 inventory
node._chat = FakeChat([json.dumps(inv), '{"caption":"final"}'])
report = []

    "http://x", {"texts": {"caption.pass2.en": "PASS2"}}, "SYS", "USER",
    None, 0.2, 64, 7, False, None, report)

# 2) 四级降级：桩 _post 记录 payload，按 response_format/repeat_penalty 决定 400 或成功
old = moss_llm.nodes._post
moss_llm.nodes._post = recorder
try:
    node._chat("http://x", "s", "u", None, 0.2, 64, 1,
               want_json=True, schema=moss_llm.nodes.CAPTION_INVENTORY_SCHEMA)
finally:
    moss_llm.nodes._post = old

# 3) 未知 kind 边界（F1）
moss_llm.nodes.guard_caption_json(
    {"subjects": [{"kind": "animal", "appearance": "bronze horse statue"}]})
```
