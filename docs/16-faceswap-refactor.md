# 换脸节点：重构前 → 重构后

> 这一页只讲**变化**与**为什么这么变**。节点参数怎么填、边界在哪，见 README 的
> 「🎬 故事板 · 换脸」一节；实测原始记录不在公开树里，本页只引结论与可复现的判据。

## 〇、一句话

**前**：换脸 = 另一个包的一个编码节点 + 手接 `VAEEncode` + `KSampler` + 手工裁格贴回，
四个节点、三处会静默错位。
**后**：本包一个节点，几何由 `spec` 管，贴回逐像素不动。

---

## 一、重构前：那条路长什么样

| 步骤 | 谁做 | 会错在哪 |
|---|---|---|
| 参考图进 vision | 社区包 `ComfyUI-MOSS-RefHiRes` 的 `TextEncodeMOSSImageEditHiRes` | 宿主原生节点把参考图硬编码压到 384×384；用原生节点等于没给参考图 |
| 源图 → latent | 手动 `VAEEncode` | 忘了接 → 起点是空 latent，变成纯文生图 |
| 采样 | 手动 `KSampler`（8 步 / cfg 1.0 / euler + simple / denoise 0.95） | `denoise` 在 8 步下被量化：0.875–0.99 **全部等于 1.0**，看着在「编辑」实际是全量重画 |
| 只换一格 | 手动 `Crop` → 换 → `Paste` | 坐标靠手抄；裁与贴的 `shave` 不一致就静默重采样，画面变糊 |

四个节点、四次手工接线，任何一处错都不会报错，只会「图不太对」。

## 二、重构后：一个节点

`MossStoryboardFaceSwap` 把上面四步合成一步，**几何不再靠手抄**：

```
model + clip + vae + image + ref + prompt
  → [取第 index 格] → [抬到 sample_edge] → [参考图进 vision] → [采样] → [缩回格子] → [贴回]
  → image（整张宫格） + report
```

`spec` 由本包自己的几何节点给，裁格与贴回用的是**同一套整数坐标**，所以「贴回哪里」
与「生成时哪里」不会分叉。

## 三、行为对照：变的是什么，不变的是什么

| 项 | 重构前 | 重构后 | 判定 |
|---|---|---|---|
| 参考图进 vision 的预算 | 宿主 0.147（等于没给） / RefHiRes 可调 | 可调，默认 **1.05** | **变**（见 §四.1 为什么这里可以变） |
| 缩放方向 | 只降不升 | 只降不升 | **不变** |
| `Picture N:` 前缀 | 节点拼，用户自己写会重复 | 节点拼；用户写过的**先剥再拼一条** | **修掉一个静默错** |
| `denoise` 的量化语义 | 宿主按 `int(步数/降噪)` 截断 | 同左，但 `report` **打印实际生效值** | **语义不变，可见性变** |
| 参考图数量 | 可多张 | **只取第一张**，并在 `report` 说明 | **收紧**（实测多张更差） |
| `reference_latents`（ref_kv） | 可开、可设窗口 | **不做** | **砍掉**（实测中间窗口全部更差） |
| 只换一格 | 手接 Crop/Paste | `spec` + `index`，自动贴回 | **变** |
| 目标格之外 | 取决于手接是否正确 | 逐像素不变（实测 `max|Δ| = 0`） | **变，且可证** |

## 四、两条铁律：一条适用，一条不适用

重构 HiRes 节点时踩过两个坑，这里必须逐条对照，否则会重复犯错。

### 1. 「替代节点的默认值必须与原版逐位一致」——**本节点不适用**

那条铁律的适用前提是**替代**：HiRes 节点与宿主 `TextEncodeMOSSImageEdit` 同功能，
用户换上它、不动任何旋钮，输出不该变，所以默认值必须留在 0.147。

本节点**不是替代品**，是一个新节点：没有「原版」可比，也不存在「用户换上它以后行为悄悄变了」。
所以默认取**实测产线值 1.05**，并在 `report` 里把「预算 → 实际进 vision 的尺寸」打出来。

> 反过来讲：如果哪天本包再提供一个「与宿主某节点同功能」的节点，默认值就必须逐位一致。

### 2. 「逐行改写 = 派生 = 必须跟上游许可」——**本节点按独立实现处理**

HiRes 节点不能并进本仓（本仓 MIT），原因是它的 `execute()` 是宿主
`nodes_moss_image.py::TextEncodeMOSSImageEdit` 的**逐行改写**：变量名相同、偏置算法相同、
切片写法相同 —— 那是派生作品，标 MIT 是许可冲突。

本节点**没有**复制任何源码：

- 不 `import` 宿主那张 `EDIT_FORMATS` 表，不实现 ref 窗口那条路（因此也不存在改写）；
- 只调用宿主**公开 API**：`clip.tokenize(images=…)`、`clip.encode_from_tokens_scheduled`、
  `comfy.utils.common_upscale`；
- 行为按**公开契约**（前缀形态、`<|image_pad|>` 锚点）重新实现，结构与上游不同。

判据一句话：**照抄结构 = 派生；按契约重写 = 独立实现。** 边界写在
[`THIRD-PARTY-NOTICES.md`](../THIRD-PARTY-NOTICES.md) §四之二。

## 六、边界：哪些话不能说

- **本节点分格路径没有独立的身份读数。** 已有的实测都是整图 i2i；本节点会把单格抬到
  `sample_edge` 再采样，采样画布不同，读数不能直接搬。
- **本域余弦没有分辨力。** MOSS 生成的亚洲女性实测异人 `0.521` > 同人 `0.468`，
  这类批次上的任何余弦都读不出身份，**目检是唯一有效证据**。所以本包不给「像不像」的绝对分数，
  也不设阈值；早期写过的「走完同人上限 68%」是跨条件比较，已撤。
- 具体做不到的事（双主体、姿态、大特写不服从、连续换两次空转、不做蒙版局部重绘）见 README。
