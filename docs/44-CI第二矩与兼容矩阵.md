# CI 第二矩与兼容矩阵（M2）

> 结论口径：本文里的「已验证」= 本机（Windows）实跑过的命令与数字；
> **「未验证」= GitHub Actions runner 上没跑过**。CI YAML 的结构与命令本机无法等价复现，
> 所以本文**不声称「CI 已绿」**——只声称「同一批脚本在本机逐条跑过」。
>
> 背景与优先级见 历史记录（git 历史） §3 M2；贡献者日常闭环见
> [`CONTRIBUTING.md`](../CONTRIBUTING.md)。

## 0. 一句话

这是 ComfyUI 自定义节点包：用户通过 Manager/Registry 安装、拖示例工作流、看节点 report。
所以 CI 要防的是**用户侧的四类风险**——宿主版本、示例工作流、Registry 元数据、干净安装；
而「要 GPU / 要浏览器」的真机闸不进 CI，改成**本地一键预检**并明确输出 `SKIP（未跑）`。

| 面 | 在哪防 | 状态 |
|---|---|---|
| 宿主版本 | `host-matrix` job：两个钉住版本的装载 + 纯节点冒烟 + 示例回归 | **本机等价脚本已验证；GH runner 未验证** |
| 示例工作流 | `host-matrix` / `windows`：`examples/` 全部 12 个 + 2 个夹具过连线/槽位/值域（210 项） | **本机已验证（210/0）** |
| Registry / Manager 元数据 | `release-preview`：pyproject 纪律 + `.comfyignore` 打包面 + `make_dist --verify` | **本机已验证（verify 16/0）** |
| Windows 安装 | `windows` job：纯节点冒烟 + 示例回归 + CPU 单测 + 卫生闸 | **本机（Windows）等价跑过；GH runner 未验证** |
| GPU / 浏览器真机 | `tools/ci_preflight.py`（本地） | **已验证：有环境跑、缺环境 SKIP、`--require-all` 非 0** |
| GitHub Actions 本身 | — | **未验证（本机无法复现 runner）** |

## 1. 宿主版本矩阵：钉哪两个、为什么

| 版本 | 角色 | 选择理由 |
|---|---|---|
| **`v0.42.0`** | 最低支持线 | `pyproject.toml` 的 `[tool.comfy].requires-comfyui = ">=0.42.0"` 就是它在守：MOSS-Image 原生支持（`CLIPType.MOSS_IMAGE` / `nodes_moss_image.py`）首次进入宿主是 0.42.0。**低于它的宿主装得上本包，但提示词编码会静默错**，所以这条线必须有一个 CI 实例跑着。 |
| **`v0.43.2`** | 撰写时最新稳定 tag | 代表「用户今天新装 ComfyUI 会拿到的版本」。版本号取自上游 GitHub tags（2026-11-01 查询：`v0.43.2` 是最新的非预发布 tag）。它盯的是**向前兼容**：上游改签名/改目录结构时，先用它暴露。 |

纪律：

- **不追 `latest`**：矩阵里出现 `latest` 时，上游任意一次发版都可能让 CI 红，而红的原因与本包
  改动无关——那样的闸功能上等于噪音。
- **升级矩阵的动作**：把新 tag 加进 `strategy.matrix.comfy`（或替换旧的较新版本），
  在 PR 里写清「为什么这个版本值得进矩阵」；同时看 历史记录（git 历史） §4 的节奏。
- 两个版本都必须能跑完 `[阻塞]` 步骤；只在某一个版本上失败的步骤，要么是上游差异（写进本文），
  要么是本包不兼容——后者应当在代码里修，而不是把版本从矩阵里删掉。

> 已知边界：矩阵只验证 **CPU 可判定**的部分。宿主真正的 GPU 采样路径本机 CI 不覆盖（见 §6）。

## 2. CI 结构与「阻塞 / 豁免」的边界

job 一览（`.github/workflows/ci.yml`）：

| job | 干什么 | 阻塞？ |
|---|---|---|
| `lint` | `ruff check .` | 阻塞 |
| `unit`（py 3.10/3.11/3.12） | 全部 CPU 单测 + 覆盖率/确定性基线 + 前端一致性 | 阻塞 |
| `frontend` | node 侧 i18n / 旧稿兼容 / 编辑器纯函数 | 阻塞 |
| `release-preview` | 发布卫生 54 项 + pyproject 元数据纪律 + `.comfyignore` 打包面 + `make_dist --verify` + 构建 zip artifact | 阻塞 |
| `host-matrix`（v0.42.0 / v0.43.2） | 装载 + 纯节点冒烟 + 14 个示例工作流回归 + 干净副本装载 | 3 步阻塞 + **1 步 CUDA 豁免** |
| `windows` | 纯节点冒烟 + 同样 14 个示例回归 + CPU 单测子集 + 卫生闸 | 阻塞（不含前端差分/GPU 步骤） |

### 2.1 `host-matrix` 里哪一步阻塞、哪一步豁免，为什么

| 步骤 | 判定 | 原因 |
|---|---|---|
| `[阻塞] 自加载 + 纯节点冒烟`（`smoke_nodes.py`） | CPU 可确定判定 | 只 import 本包、构造 schema、跑纯节点；不需要 CUDA。 |
| `[阻塞] 示例即回归`（`check_ui_workflow.py`） | CPU 可确定判定 | 只 import **本包**节点取 `INPUT_TYPES()`，与宿主符号有关的检查在宿主不可 import 时会**明确跳过**（输出写「跳过」，不冒充通过）。 |
| `[阻塞] 干净副本独立装载`（`make_dist --verify`） | CPU 可确定判定 | 断言产出目录自足：节点清单、前端在位、编辑器/宫格/裁格纯函数可跑、没有模块来自原仓。 |
| `[CUDA 豁免] 走宿主 load_custom_node`（`host_loader_check.py`） | **step 级 `continue-on-error`** | CPU runner 上 ComfyUI 在 **import 期**就会断言 CUDA（`Torch not compiled with CUDA enabled`），这一步**必然失败且与本包无关**。job 结论仍绿，失败详情完整留在日志里。永久红的闸等于没有闸，所以用 step 级豁免而不是 job 级。 |

两处「为了 CPU 可判定」的机关，都是刻意的：

1. **把仓库复制进 `custom_nodes`，而不是软链**。模型下拉是扫 `<宿主>/models/LLM` 生成的；
   本包按 `__file__` 往上找 `custom_nodes` 祖先。软链会让 `resolve()` 回到 workspace，
   于是「找不到宿主模型」→ 示例里存的 model 值被判成非法 → 假红。真实副本让扫描路径成立。
   **宿主必须 clone 到 workspace 之外**（runner 临时目录）：若宿主在 `$GITHUB_WORKSPACE` 内，
   `cp -a "$GITHUB_WORKSPACE/." "<workspace>/.../custom_nodes/..."` 的源目录包含目标目录，
   GNU cp 会以 `cannot copy a directory into itself` 退出 1（本机已用 Git 自带 GNU cp 复现；
   修复后同一命令在「宿主在 workspace 外」的布局下 exit 0）。CI 注释里写明了这条约束。
2. **占位 GGUF（空文件）**。runner 没有权重；示例里的模型下拉值要能落在一个存在的选项上。
   放一个空文件只为让下拉列表可复现，**不加载、不出图**；这一点写进 CI 注释，不是偷偷造假。

### 2.2 Windows job 的口径

- 跑：纯节点冒烟 / 14 个示例回归 / CPU 单测子集（与 ubuntu unit 同一批脚本）/ 卫生闸 + 干净副本装载。
- 不跑：`test_i18n.mjs` / `test_compat.mjs` / `check_editor_ui.py`（前端差分，已由 ubuntu `frontend`
  job 覆盖）与任何 GPU 步骤——**Windows runner 没有 GPU**，写了也只会是永久红。
- **副本只做「冒烟 + 示例回归」**（这两步需要 `custom_nodes` 祖先路径）；卫生闸与
  `make_dist --verify` 在**原始工作树**跑——它们读 `git ls-files`，而副本为了保持干净会删 `.git`，
  在无 `.git` 的副本里跑只会得到「受控文件 0 个」这类假红（本机等价复现：删 `.git` 的副本 rc=1，
  原工作树正常）。
- 目的：把「Windows 用户装不上/路径分隔符/编码」这类平台问题提前暴露；本机就是 Windows，
  同一批脚本本机全绿（见 §6）。

## 4. 豁免的取消判据（别让豁免变成永久洞）

`[CUDA 豁免]` 那一步在当前 CPU runner 上**不可能绿**（与本包无关）。所以它的取消条件写成
**环境条件**，而不是「等它绿」：

1. 当 runner 具备 CUDA（自托管 GPU runner，或 GitHub 提供的 GPU runner）后，先让该步连续
   **10 次运行全绿**（push 或 PR 触发均算），再删掉 `continue-on-error` 改成阻塞；
2. 或上游 ComfyUI 让 `import nodes` 在 CPU 上不再断言 CUDA（两个矩阵版本都满足）——
   同样先观察 10 次全绿，再改阻塞；
3. 在此之前，等价判据是**本地真机**：`python tools/ci_preflight.py` 会跑
   `host_loader_check.py`（19 项）并给出 PASS；发布前用 `--require-all` 强制要求它跑过。

任何一次为了「让 CI 变绿」而放宽判据（删断言、改数据、把 error 降级成 warn）都不属于本文
允许的豁免；发现闸本身错了，请在 PR 里说明是假红还是假绿，并补新断言防回归。

## 5. 本地预检脚本：`tools/ci_preflight.py`

把 CI 覆盖不到的真机闸收成一条命令；**核心契约是「SKIP 不是 PASS」**。

```bash
python tools/ci_preflight.py --probe-only   # 只探测：宿主 / GPU / Playwright + 计划
python tools/ci_preflight.py                # 有环境就跑；缺的明确 SKIP（未跑）
python tools/ci_preflight.py --require-all  # 发布前：缺任何环境即非 0（退出码 2）
python tools/ci_preflight.py --require-all --with-gpu   # 再加：GPU 端到端矩阵（真出图）
```

| 项 | 判定方式 |
|---|---|
| 宿主 | `COMFYUI_PATH` → 仓库根 `.comfyui_path` → 标准安装推断；判据是 `<根>/custom_nodes` 真存在 |
| GPU | `nvidia-smi` 可执行且能列出设备 |
| Playwright | `node` 可执行 + `tools/ui_kit.mjs` 能找到 `playwright-core` 与 chromium |
| 步骤 | `host_loader_check.py` / `ui_smoke.mjs` / `ui_widget_compat.mjs` / `ui_llm_panel.mjs`；`e2e_matrix.py` 需 `--with-gpu` |

- `ui_*.mjs` 的退出码 **2 = 环境问题** ⇒ 预检记为 `SKIP（未跑）`；其余非零才是 `FAIL`。
- GPU 端到端默认**不跑**（会真出图、占显存）：发布前显式 `--with-gpu`；缺端到端工作流文件时
  SKIP 并打出缺哪个文件，不猜权重。
- 退出码：`0` = 没有 FAIL（允许 SKIP）；`1` = 有 FAIL；`2` = `--require-all` 下还有 SKIP。
- 自身单测 `tests/test_ci_preflight.py`（16 条）钉住：环境探测桩、SKIP 与 PASS 严格区分、
  `--require-all` 必非零、GPU 步骤必须显式启用。

`--probe-only` 的输出形如（占位符是真实形态，不是本机路径）：

```
宿主 ComfyUI : <ComfyUI 根目录>
GPU          : NVIDIA GeForce RTX ...
Playwright   : playwright-core + chromium

计划：
  host-loader      将运行
  ui-smoke         将运行
  ui-widget-compat 将运行
  ui-llm-panel     将运行
  e2e-matrix       未启用（发布前用 --with-gpu；会真实出图、占显存）
```

## 6. Registry / Manager 面（元数据与干净安装）

Manager/Registry 只读元数据，读错了不会报错——它只会「装不上 / 装了不显示 / requires 不生效」。
所以把三条机检放进 `release-preview`：

| 检查 | 内容 | 为什么 |
|---|---|---|
| pyproject 元数据纪律 | `project.name == "moss-storyboard"` 且不含 ComfyUI；`license` 是 `{file/text}`；`keywords/classifiers/dependencies` 在 `[project]` 段（不在 `[project.urls]` 后面）；`dependencies == []`；`[tool.comfy]` 有 `PublisherId / DisplayName / requires-comfyui`，且 `requires-comfyui` 与 §1 的下限一致 | TOML 的表归属一旦写错，宿主解析器**读不到**依赖/平台标签 ⇒ 静默失效；`name` 是 Registry 的 node id，发布后不可改 |
| `.comfyignore` 打包面 | 开发设施（`tests/ tools/ docs/ .github/`）被排除；运行期必需文件（`__init__.py / nodes.py / core/ / v3/ / web/ / examples/ / pyproject.toml / requirements.txt / LICENSE / README.md`）**不被**排除 | 黑名单排多了 = `ImportError`；排少了 = 开发设施混进发布包 |
| `make_dist --verify` | 按 `git ls-files` + `.comfyignore` 构建干净副本，并**在副本里独立装载**：节点清单、前端在位、编辑器/宫格/裁格真跑、断言没有模块来自原仓 | 用户装的就是这份副本；「仓库里能跑」不等于「副本自足」 |

本机实测：`make_dist.py --verify` = **通过 16 / 失败 0**；`check_release_ready.py` = **54 项**
（仓库有未跟踪文件时会多一条「工作树干净」的失败，这是发布闸的正确行为，不是 bug）。

## 7. 未验证 / 不能声称的部分（诚实清单）

1. **GitHub Actions 本机不可跑**：`host-matrix`、`windows`、`release-preview` 的 YAML 只在本机做了
   **结构解析 + 命令逐条等价执行**，没有在 GH runner 上真实跑过。第一次 push 后若红，
   优先修环境差异（runner 镜像 / pip 解析 / 版本 tag 是否存在），不要先改判据。
2. **Windows runner 未验证**：本机是 Windows，同一批脚本本机全绿；但 `windows-latest` 镜像的
   Python/pip/torch 行为可能与本机不同。
3. **v0.43.2 未在真实宿主上跑过**：版本号来自上游 tags；装载与示例校验的 CPU 路径本机可用
   等价副本模拟（见 §3），但真实宿主启动没有验证。
4. **真机闸（宿主装载 / 无头浏览器 / GPU 端到端）不在 CI**：由 `ci_preflight.py` 覆盖；
   没有环境时它们是 `SKIP（未跑）`，不能当通过。
5. **效果质量不进 CI**：本文件所有闸都是 L0/L1（形式/稳定/装载），不是「图更好看」。
