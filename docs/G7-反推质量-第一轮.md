# G7 · 反推质量 · 第一轮（20 图 × 2 模型）

> 任务：T1 · G7 gold set 第一轮。判据定义见 `<记忆总账>` §0.5、§9；本文只写这一轮**实测**。
> 判读者说明：本文的「目检」是 **AI 代理目检**（读图 + 读 caption），**不是人类**；Lead 独立复核。

## 0. 一句话结论

**样本不足**（三档中的第三档）：20 图 + 10 图人工判读的规模**不足以**判定 A 显著差于 B，
也**不足以**说二者无差异。可以确定的是三条方向性事实：

1. 事实准确率：A 88.7%（55/62）vs B 85.7%（48/56），差 3.0 个百分点，Fisher p=0.783 —— **未达显著**；
2. 唯一原始 p<0.05 的指标是「文字两遍互证」（A 24% vs B 62%，p=0.037），但它是 6 项比较之一、
   n=17/16，Bonferroni 校正后 0.22 —— **只作方向，不作结论**；
3. 真正的共同缺陷（两个模型都有、且比模型间差异大得多）：**非人物体被大量标成 `character`**
   ⇒ 「材质与反光」组的材质绑定几乎全灭（A 0/16、B 1/12），并连带把年龄编到物体上
   （80 岁磨豆机、120 岁剑、50 岁雕像）。这一条**已验证**，可直接作为下一轮修复项。

## 1. 三档判定与统计口径

| 档 | 本轮是否成立 | 依据 |
|---|---|---|
| A 显著差于 B | ❌ 不成立 | 事实级准确率 A 反而略高（88.7% vs 85.7%）；逐图配对 6 胜 1 负 3 平（符号检验 p=0.125）；跑崩率 15% vs 5%（Fisher p=0.605） |
| 无显著差异 | ❌ 不能这么说 | 「不显著」≠「无差异」。准确率 95% CI 分别 [78.5%, 94.4%] / [74.3%, 92.6%]，宽约 ±9pt；按此样本量，最小可检出差异约 15pt。把 p>0.05 当「没差别」正是 G4 那轮的教训 |
| **样本不足** | ✅ **本轮结论** | 两个模型都在同一条错误走廊里（类型错、猜文字、重复循环），模型间差异小于这些系统性缺陷；要检出 10pt 级差异需要原计划的 60 图规模 |

统计口径（全部为双侧精确检验，小样本不用正态近似）：

- 事实级准确率：`correct / (correct + wrong)`，`unverifiable` 从分母剔除；Wilson 95% CI；Fisher 精确检验。
- 逐图配对：每图准确率之差，符号检验（二项精确）。
- 跑崩率：20 次里的失败次数，Fisher 精确检验。
- 幻觉：10 图「有/无」，McNemar 精确检验。
- 多重比较：6 个类别/指标同时看，未校正；本文所有 0.01<p<0.05 的数都**不作结论**。

## 2. 方法与同口径设置

### 2.1 gold set

20 张，四类各 5 张：单人特写 / 多人互动 / 含图内文字 / 材质与反光。
来源：宿主机的 `<ComfyUI>/input` 与 `<ComfyUI>/output`（真实可判读画面；避开纯色块、
纯 UI 截图、带标注的探测图、多格拼图）。**候选目录不写死在脚本里**：`tools/g7_select.py`
优先读 `COMFYUI_INPUT` / `COMFYUI_OUTPUT`，否则按宿主根（`COMFYUI_PATH` → 本地
`.comfyui_path` → 标准安装位置推断）拼出 `<宿主>/input|output`。
清单（路径 + 类别 + 尺寸 + sha256）落 `out/g7/images.json`，
sha 用于复核「同一张图没被换过」。

### 2.2 两条模型臂

**两个模型、20 张图全部重跑一遍**，最终表里的数字全部来自 8192 这一轮。

### 2.4 跑批结果

40 次调用全部执行（20 图 × 2 模型），**36 成功 / 4 失败**，失败均为「JSON 未闭合」的
重复循环撞 completion 上限，逐条列在 §4.4。**19 张图至少有一个模型的完整产出；
img07（军官列队）两个模型都跑崩，是全表唯一无数据的图**。每类分母在表里逐格给出，
没有用 1.0 冒充空缺。

## 3. binding 机检判据（零模型）

工具：`tools/g7_binding.py`（离线单测 `tests/test_g7_binding.py`，35 条）。
对象：模型产出的 IR + 由 IR 确定性渲染出的成品 caption（`clauses.render_prose(build_clauses(ir))`）。

| 类别 | 分母（applicable） | bound 判据 |
|---|---|---|
| 颜色 | 实体自己的描述字段里出现颜色词 | 该颜色词出现在**该实体自己的子句**内、距子句起点 ≤ N 词 |
| 材质 | 实体自己的衣物/道具/材料/颜色字段里出现材质词（**人物不取皮肤**，否则 "smooth/glossy" 会让材质类人人有分） | 同上 |
| 方位 | 实体有 `spatial.anchor` | 方位词出现在该实体子句内；且 **bbox 来自模型时**，bbox 中心必须落在 anchor 声明的象限（两通道互证；bbox 由方位重建的不判，否则自己证自己） |
| 图内文字 | `kind=text` 且 `text_content` 非空 | 每一行都**逐字出现在直双引号内**（多行文字块按行核，允许同一引号块内换行） |
| 数量 | 同 kind+label 的实体成组且 n≥2（**仅单图 canvas**，多格画的跨格重复不算数量） | 组子句或紧随的 "the same figure appears again" 子句表达了数量 |

三条边界（否则这张表会被误读成准确率）：

**两条口径注释（lang-zh 交叉复核提出、已对齐）：**

- **图内文字类只收 `kind=text`**：`character/object` 里塞的 `text_content` 不算本类
  （那是类型错误，归 §7.1），实现与上表判据逐字一致。对齐前实现收「任何带 text_content
  的实体」，A 多出 2 个 character 进分母（28 vs 26），其中 img19 的一个还因文字串恰好
  被别的实体渲染而被误记 bound；对齐后 A 文字类为 23/26。
- **颜色/材质词按连字符拆分量**：`white-gold` 要拆出 `white` + `gold`，否则
  `typography.color` 里的复合色会被当整词静默漏检（B · img14 实测）。修后 B 颜色分母
  53→54、bound 40→41（76%）。这类修正只动判据、不重跑模型，属于「先修判据再出结论」。

1. **分母来自模型自己的 IR，不是真值召回。** 覆盖率 1.0 只说明「记下的都绑对了」，
   不说明「该记的都记了」。所以每个模型的**分母本身**也是结果（见 §4.1 括号里的分母）。
   分母为 0 时覆盖率报 n/a，不报 1.0（记忆总账 §9.7 的坑）。
2. **不判事实对错。** 颜色记错（红记成蓝）但只要绑在同一实体上仍算 bound；事实准确率与
   幻觉由 §6 的代理目检单独判。
3. **它是「账本 → 成品」的保真度。** bound 失败的第一含义是「模型记了、但没挂对该实体 /
   没活到 caption 里」，第二含义才是「模型没记」；两类在 `binding.json` 的 instances 里分开标注。

绑定窗口实测：N=120，490 个属性词里**最大词距 86、超窗 0 个**——同子句才是判据本体，N 不卡正常描述。

### 4.1 覆盖率总表（2 模型 × 5 类，附分母）

| 类别 | A-4B（bound/分母） | B-9B（bound/分母） | Fisher p（仅参考） |
|---|---|---|---|
| 颜色 | 83%（44/53） | 76%（41/54） | 0.474 |
| 材质 | 40%（18/45） | 44%（12/27） | 0.807 |
| 方位 | 93%（94/101） | 94%（68/72） | 0.764 |
| 图内文字 | 88%（23/26） | 81%（17/21） | 0.684 |
| 数量 | 100%（3/3） | 100%（1/1） | 1.000 |

读法：两个模型的**覆盖率没有统计差异**，但分母形态不同——A 记了 101 个实体、45 条材质、
26 条文字；B 记了 74 个实体、27 条材质、21 条文字。也就是说 **A 更全，B 更省**；
同样「40% 材质覆盖率」背后的绝对量是 18 vs 12。数量类两个模型的分母合计只有 4，
**该类样本不足**，下一轮要么扩图、要么改判据（模型倾向给每个实例单独 label，同组很少成立）。

## 5. 校准（硬要求：机检 vs 目检）

### 5.1 结果

10 图 × 2 模型 × 5 类 = 67 个「有分母」的格子（其余为 n/a），机检 pass/fail 与代理目检
**67/67 一致 = 100%**（阈值 80%）。逐格证据落 `out/g7/inspect/{img}.md`，
判读结论落 `out/g7/inspect/agent.json`，统计落 `out/g7/inspect/stats.json`。

### 5.2 校准真正抓到的东西（先修判据，再出结论）

第一版机检在 dry-run 时与代理目检**明显不一致**；另有两处口径偏差是 lang-zh 交叉复核
（`docs/38`）抓到的。**五处全部是「找不着就判失败」或「收错了分母」的假结果**，修完才做
上面的 100% 校准：

| # | 症状 | 根因 | 修法 | 来源 |
|---|---|---|---|---|
| 1 | 方位类覆盖率只有 33%（如 `top-left` 明明写在 caption 里） | 分词把 `top-left` 当一个词，方向词 `top`/`left` 永远匹配不上 | 属性词按连字符分量匹配（单测钉住） | dry-run 自检 |
| 2 | 同一实体的颜色/材质全判「不在自己子句里」 | 实体 id 同时出现在 subject 子句和 relation 子句（`the man faces the grey wall`），取「最后一个」指到了关系句 | 按维度优先取 subject/text 子句（单测钉住） | dry-run 自检 |
| 3 | 文字专线补进来的实体整段错位 | 落盘 caption 用「未重排」的实体顺序，判据却先 `normalize()` 重排再重建 | 判据按落盘顺序还原 IR（单测钉住） | dry-run 自检 |
| 4 | B · img14 的 `typography.color="white-gold"` 整词漏检 | 颜色词表只做整词相等，复合色被当成未记录 | 颜色/材质词按连字符拆分量（单测钉住）；B 颜色 53→54 分母、40→41 bound | lang-zh 复核 |
| 5 | 文字类分母 28 vs 文字实体 26 | 实现收「任何带 text_content 的实体」，与判据写的 `kind=text` 不一致 | 实现对齐为 `kind==text`（单测钉住）；A 文字 24/28→23/26 | lang-zh 复核 |

修之前（A 已完成的 9 图上）方位类只有 33%（14/42）、颜色类 42%（8/19）；三处 dry-run
修完后全量 20 图是方位 93%（94/101）、颜色 83%（44/53）。**如果跳过校准直接出结论，
会得出「两个模型方位都很差」的假结论。**

### 5.3 校准的边界（必须写清）

- 判读者是 **AI 代理目检**（读图 + 读 caption），不是人类；Lead 已安排 `lang-zh` 做独立交叉复核（`docs/38`：PASS、无阻断，6 条 minor 已逐条修入本文与工具）。
- 代理目检是在看到机检结论后逐格核对「这个 pass/fail 是否站得住」的，所以 100% 一致
  不等于独立验证；它的价值在于**抓假失败**（§5.2 五条）与**标出机检盲区**（§6 的文字编造，
  机检全部判 pass，目检判 wrong）。
- §5.2 第 5 条改了文字类分母后，`img17` 的文字格从 fail 重判为 pass：该格只剩
  `Bricke` 一个 `kind=text` 实体、且逐字进了引号；「把不可辨文字猜成 Bricke」是**准确率**
  问题（记在 §6），不是绑定问题。校准结论因此仍为 67/67。
- 校准只覆盖 10 图；`img15`（羊皮卷）上 B 的文字 1/5、A 的 2/5 这类**未目检格子**的
  失败原因没有逐条人工确认，是下一轮校准的优先项。

## 6. 事实准确率与幻觉（代理目检，10 图）

判读单元：每图每模型 3–9 条可核事实（身份/年龄/发型/服装/道具/姿态/空间/环境/光/文字/媒介），
逐条判 correct / wrong / unverifiable；另有整图「幻觉：有/无」。

| 指标 | A-4B | B-9B |
|---|---|---|
| 事实条数 | 64 | 59 |
| correct | 55 | 48 |
| wrong | 7 | 8 |
| unverifiable | 2 | 3 |
| **准确率**（correct/(correct+wrong)） | **88.7%**（95% CI 78.5–94.4） | **85.7%**（95% CI 74.3–92.6） |
| 幻觉图数 | 4/10 | 3/10 |
| 跑崩率（另 20 图机检） | 15% | 5% |

- 准确率差 3.0pt，Fisher p=0.783；逐图配对 6 胜 1 负 3 平，符号检验 p=0.125。**均不显著**。
- 幻觉 4 vs 3 图，McNemar 精确 p=1.000。**不显著**。
- 幻觉的具体形态（两边不同）：
  - A：把 SYSTEM 里的示例串 `the string exactly as printed` 当成图内文字抄进 IR（img09）；
    给物体编年龄（img17 磨豆机 80 岁/豆子 3 岁、img18 雕像 50 岁、img20 剑 120 岁）。
  - B：给物体编年龄（img18 鹰 28 岁）；把不可辨的铭牌猜成具体品牌（img17 `Bibble`、
    img20 水印两行合并读成 `NOIRMANCETORNE`）；成品 caption 里凭空出现 "a person"（img13，
    机制见 §7.1）。
  - 共同：**都在猜不可辨读的文字**（A `Bricke`/`写不下去` 之外的招牌、B `unreadable`），
    而 SYSTEM 要求「读不出就置空」。

## 7. 两类系统性失败（比模型间差异更重要）

### 7.1 非人物体被标成 `character` → 材质/颜色绑定丢失 + 编年龄（两个模型都有）

可复核的统计（36 份成功记录，客观规则：`kind=character` 且**没有** gender/hair/skin/face/expression
任一人物字段、**却**带 material/color/build/detail 任一物体字段）：

| | character 实体 | 其中「无人物字段、有物体字段」 | 占比 |
|---|---|---|---|
| A-4B | 62 | 34 | 55% |
| B-9B | 48 | 24 | 50% |
| 合计 | 110 | **58** | **53%** |

这是**下界**：雕像/鹰这类有 `face`/`pose` 的拟人物体不在这个规则里（实测 img18 的鹰、
img17 的磨豆机都还有 age 字段）。后果是三重的：

1. `describe_entity` 的人物分支**不渲染 `descriptors.material`**（只有非人物分支才有
   `with {material}`）⇒ 材质类绑定在「材质与反光」组 0% / 8%、在「含图内文字」组 29% / 43%；
2. 人物分支强制年龄短语 ⇒ 物体被编上年龄（`an 80-year-old coffee grinder`、`a 120-year-old sword`），
   这是本轮**最刺眼的幻觉**；
3. 长 label + 无性别时编译器兜底成 `a person`，而且同描述会被合并成
   `the same figure appears again …` ⇒ 成品 caption 里凭空出现「一个人」（B · img13 实测）。

这条是**管线问题**（schema 枚举里 `character` 太容易选中，且 `coerce_ir` 不做类型合理性校验），
不是某个模型的问题。修法不该是改判据，而是：① 取证提示词里给 `character` 加「仅限人/拟人角色」；
② `coerce_ir` 对 `character` 做常识闸（无 age 且 label 命中物体词表 → 降级 object 并出声）；
③ 人物分支补渲染 material。**三条都未做**，留给下一轮。

### 7.2 JSON 模式无重复惩罚 → 重复循环（A 3/20、B 1/20）

见 §4.4。触发场景高度一致：**多同类实体的宽景/满版图**（军官列队、帐篷内杂物、海报文字）。
后果是整次取证归零（不是「差一点」）。可选修法（未验证）：JSON 调用里保留
`repeat_penalty`（只摘 DRY 与 presence/frequency 中真正会伤键名的项）、或对实体数设上限、
或在 schema 里给 `entities` 加 `maxItems`。

## 8. 限制与下一步

**限制**

1. n=10 图的人工判读 + 20 图的机检：准确率 CI 宽约 ±9pt，检不出 10pt 级差异——本轮结论只能是「样本不足」。
2. binding 覆盖率的分母来自各自 IR，两个模型的「率」不是同一批实体的配对比较；跨模型只能比形态（全/省）。
3. 代理目检不是人类；文字准确性没有独立 OCR 交叉（只有两遍互证这个弱证据）。
4. 数量类分母合计只有 4，该类本轮等于没测到。
5. 未做「反推 → 重绘」闭环（G7 的原始定义包含重绘对照），本轮只测「账本侧」，不测「重绘像不像」。
6. 4 次跑崩让 A 少 3 格、B 少 1 格；表里已逐格标注，未用 1.0 填充。

**下一步建议（按性价比）**

1. 修 §7.1 的类型闸（预期直接抬升材质类覆盖率，且消掉大部分「编年龄」幻觉）——这是本轮最确定的收益。
2. 给 JSON 模式加重复保护（§7.2），把 15%/5% 的跑崩率压下来。
3. 扩到 60 图 × 2 模型（T1 原计划），现有工具链可直接跑：`tools/g7_caption.py` + `tools/g7_binding.py`。
4. 文字类单独加 10–15 张（招牌/书页/水印/漫画气泡），并把「两遍互证」升级为 OCR 交叉。
5. 人工复判 §5.3 里未目检的格子（img15、img16、img19 的文字/材质失败原因）。

## 9. 复现

```bash
# 1) 选图（人看缩略图后 freeze；本轮的 picks 已冻结）
python tools/g7_select.py scan          # → out/g7/candidates.json + out/g7/sheets/
python tools/g7_select.py freeze        # → out/g7/images.json（20 张，四类各 5）

# 2) 两模型同口径跑批（串行；跑完侧车必停）
python tools/g7_caption.py --models A-4B,B-9B --overwrite
#    → out/g7/json/{A-4B,B-9B}/{img_id}.json（caption + raw_response + tokens + 耗时 + IR）

# 3) binding 机检（零模型）
python tools/g7_binding.py measure --models A-4B,B-9B
#    → out/g7/binding.json + out/g7/binding_table.md

# 4) 代理目检包 + 校准（先出待检单元，再逐格填判，再算一致率）
python tools/g7_inspect.py sheet --ids img01,img03,img08,img09,img11,img12,img13,img17,img18,img20
python tools/g7_binding.py calib-sheet --ids img01,img03,img08,img09,img11,img12,img13,img17,img18,img20
#    → out/g7/calib/machine_cells.json（待目检的机检单元）
#    （按该文件逐格填 out/g7/calib/agent_cells.json 的 agent_pass）
python tools/g7_binding.py calibrate    # → out/g7/calib/calibration.json（<80% 会红）
python tools/g7_inspect.py stats        # → out/g7/inspect/stats.json（事实准确率/幻觉）

# 5) 单测（离线，35 条）
python tests/test_g7_binding.py
```

环境：llama-server `b9596-9fcaed7`（Windows CUDA 12.4 build）；GPU 单卡 12GB；
跑批期间独占 GPU（ComfyUI 宿主空闲占用约 4GB 时两模型仍可装入）。
权重与 llama-server 的位置**不写死**：按文件名在模型目录里找，或用环境变量指定
（`G7_MODEL_A` / `G7_MMPROJ_A` / `G7_MODEL_B` / `G7_MMPROJ_B` / `G7_SERVER`；
模型目录也可用 `MOSS_LLM_MODEL_DIRS`，服务端也认 `MOSS_LLM_SERVER` / `LLAMA_CPP_HOME` / `PATH`）。
