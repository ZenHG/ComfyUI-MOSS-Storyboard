# 开源化路线图（2026-11-01）

> **前提：这是一个 ComfyUI 自定义节点包。** 用户不读 Python、不跑 CLI；他们通过
> ComfyUI Manager / Registry 安装，拖示例工作流，连节点，看节点面板与 report，把工作流
> 存成 JSON 分享给别人。开源后第一批用户是 ComfyUI 用户，**衡量收益的尺子是「他们能否
> 装得上、跑得通、不静默坏、出错能自己修」**；编译器（`moss_llm.smith`）与 CLI 是节点
> 背后的能力层，不是用户入口。
>
> 本文只写判断与方案；实现细节落各方案对应的 `docs/` 子文档。

---

## 0. 一句话

本项目的敌人是**静默失败**（结果错了但没人报错）。测试不是证明代码正确，而是把维护者的
眼睛变成可执行的判据——让 ComfyUI 用户与贡献者在不读完全部代码的前提下，仍能安全升级、
快速归因。开源后用户 × 宿主版本 × 显卡档位 × 老工作流会成倍放大，**这些判据是唯一的防波堤**。

---

## 1. 现有测试资产在防什么（按 ComfyUI 用户会遇到的事）

约 2,300 项可复跑检查，按事故类型分：

| 失败类别 | 真实事故（仓库记录过的） | 现有闸 |
|---|---|---|
| **工作流静默坏** | `widgets_values` 按位存参，插一个 widget 全体参数串位；V1/V3 双出口互斥写错就静默失效；老工作流槽位错位 | 逐位值域校验（10 个示例/夹具，158 项）；真机旧稿归位 14 项；互操作 106 项 |
| **出图静默错** | 画布/格子非 16 倍数；框不生效；Krea2 512 token 截断尾部；模型方言把事实吞掉 | 几何单测 313；确定性 sha 基线（4 IR × 5 后端）；覆盖率闸 28 组合 |
| **宿主升级后崩** | ComfyUI 内核签名变化；`WEB_DIRECTORY` 写错前端静默不加载 | 采样前 `probe_host_api()` 校验宿主符号；自加载 63；走宿主同一装载函数的 19 项 |
| **面板/前端失效** | 参数面板写回存档；隐藏参数的行高/滚动异常；i18n 显示与存档混写 | 活宿主面板断言 43 项；前端词表纯净度 20；编辑器前端 160；i18n 64 + 兼容 43 |
| **契约漂移（贡献者改动）** | 新增参数漏英文提示；`negative` 被挪出 advanced 区导致「写了不生效」 | 契约 150 项（每个参数都要 TIPS、negative 必须 advanced、参数表单一是真相源） |
| **发布面事故** | 本机路径/凭据进仓库；dump 被 `git add -A` 带进提交；版本号五处不一致；包混进开发设施 | 发布卫生闸 53 项；干净副本独立装载 16 项；SPDX、文档清单与实物一致 |
| **效果质量（未覆盖）** | 所有「更好」仍是代理论据；「6G 能不能跑」等档位问题只能靠人工结论 | 只有 G7 判据链（账本侧 + 校准）；**没有盲评、没有档位自动回归** |

三条让闸可被信任的纪律：

1. **基线冻结**：确定性输出钉成 sha256，变了必须解释「为什么变」，否则视为回归。
2. **闸必须会红**：每条判据配破坏版测试（塞一条不可渲染事实必须红），防「永远绿的闸」。
3. **诚实分母**：覆盖率必须附分母并点名缺哪条；未验证项单列，不写成已验证。

## 2. 开源后的收益（按 ComfyUI 生态的角色）

| 角色 | 收益 | 不做时的代价 |
|---|---|---|
| **普通 ComfyUI 用户** | Manager 一键装、零额外依赖；示例工作流开箱即用；报错给可操作动作；老工作流升级不坏；「未验证」标签防过度承诺 | issue 区被「装不上 / 参数没了 / 图不对」淹没；差评集中在安装与兼容 |
| **进阶用户（多卡、多模型、多语言）** | 显存档位表（4G–24G）按档抄作业；模型下拉/mmproj 配对有据可查；中英界面与文档齐全 | 「我的 6G 卡能不能跑」变成每天重复回答 |
| **贡献者** | 改一行由机器判对错；**加一个后端/方言 = 加一份 YAML**；示例即回归用例；提交前有一页式自检 | 只有作者能改，PR 全靠人肉评审 |
| **维护者** | PR 先过闸；发布器把不可逆步骤前移并预演（GitHub + Registry 双渠道）；可并行开发不互相踩 | 每次合并都是赌博，发布节奏被人工回归拖死 |
| **项目声誉** | 「可证伪的判据体系」是差异化：同类节点大多只做提示词增强，没有判据/基线/分母 | 沦为又一个「效果玄学」节点 |

成本：CI 分钟（几乎全 CPU）、基线维护（每次变化写理由）、测试脆弱性纪律（只测行为不测实现）、
以及「绿 ≠ 好」必须持续声明（L0–L4 分层）。

## 3. 方案组合

### 第一梯队（开源前：防波堤，当前开工）

#### M1 · 质量证据闭环（走节点路径）

**是什么**：先修第一轮 G7 实测出的两类系统性缺陷（它们直接决定 `MossPromptSmith` 的
caption/expand 任务产出质量），再把 gold set 从 20 图扩到 60 图 × 2 模型，用双盲判读 +
评分校准回答「谁在哪一类上差多少、置信区间多少」，并把改进落到**节点 report 的字段**上。

两类缺陷：

1. 非人物体被大量标成 `character`（客观规则下 58/110 = 53%）⇒ 材质绑定在「材质与反光」组
   只剩 0% / 8%，并连带把年龄编到物体上。修法（按序评估，不必然全做）：取证提示词加
   「character 仅限人/拟人」；`coerce_ir` 常识闸（无人物字段却带物体字段 → 降级 object 并出声）；
   人物分支补渲染 `descriptors.material`（会改变确定性输出 ⇒ 必须重冻基线并说明理由）。
2. JSON 模式摘掉重复惩罚 ⇒ 重复循环撞 completion 上限（第一轮 4/40 次整次取证归零）。
   候选修法：JSON 调用保留 `repeat_penalty`、schema 给 `entities` 加 `maxItems`、实体数上限。

**验收**：
- 同一 20 图前后对比：材质绑定覆盖率、物体编年龄幻觉数、跑批失败率、文字互证率——
  给出方向、幅度与分母，不只说「变好」。
- gold set 扩到 60 图（四类各 15）并冻结 sha256。
- 节点路径验证：活宿主里用 `llm-caption-to-moss` 示例跑一次，节点 report 能体现改动
  （材质相关 warn 减少 / 失败可见）；无 GPU 时至少 `smoke_nodes` + 编译路径全绿。
- 双盲判读协议：两名独立判读者（不同上下文/不同模型）+ 机检三方对比；一致性 ≥0.6 才下结论。
- 评分校准：自动分与人类排序的 Spearman ρ；ρ<0.5 就把该分从 README 删掉。
- 报告落 `docs/`；**代理判读必须标注「AI 判读，不是人类」**，并附可交给人类填的判读包。

**依赖**：GPU（约 30–60 分钟跑批）；不下载任何权重。

#### M2 · ComfyUI 兼容与 CI 第二矩

**是什么**：把「出问题一定在用户机器上」的这几类风险搬进可复跑的闸。

- **宿主版本矩阵**：CI 里对两个钉住的 ComfyUI 版本跑装载与纯节点冒烟；升级宿主时先看矩阵。
- **示例即回归**：`examples/` 每个工作流都过连线/槽位校验（已有 10 个接入，补齐剩余），
  并加一个**零权重可跑**的入门工作流（`task=compile`，毫秒级，无模型也能出结果）。
- **Registry / Manager 面**：`pyproject.toml` 元数据、`.comfyignore` 打包面、干净副本独立装载
  进 CI；发布前 `comfy node validate` 等价检查。
- **GPU/浏览器真机闸**：不进 CI（runner 无 GPU/无宿主），改为本地一键预检脚本：
  有环境就跑并给结论，没有就明确 SKIP（退出码与文案区分「通过」与「未跑」）。
- **host job 拆分**：CPU 可确定判定的步骤转阻塞；必须 CUDA 的步骤保留 step 级豁免并写明原因
  （永久红的闸等于没有闸）。

**验收**：CI 新增阻塞项在 PR 上可复现；本地预检脚本在无 GPU 时输出 SKIP 且不混同通过；
CONTRIBUTING 的「改动闭环」与实际步骤一致；示例回归覆盖全部示例。

#### M3 · ComfyUI 用户文档与双语同步

**是什么**：用户不读代码，文档就是产品。把用户路径与维护者路径分开，并让中英双侧不再手工漂移。

- 用户路径：安装（Manager / 手动 / Registry）、第一张图、五个最常见的坑、参数表、
  报错对照表（错误话术必须在源码里逐字可查）、已知边界、显存档位表。
- 示例画廊：每个 `examples/*.json` 说明「它演示什么、需要什么权重、跑完该看到什么」。
- 维护者路径：常见任务「改 X 动哪个文件、改完必须跑什么」（CONTRIBUTING/AGENTS 分工不变）。
- 双语同步闸：标题层级/顺序/成对存在 + 显式例外清单，接进发布卫生闸。

**验收**：双语同步闸在故意删一节时必红；发布卫生闸新增该项；示例都有说明且被 README 点名；
README 里的报错对照表与源码一致。

### 第二梯队（开源后 1–3 个月：增长飞轮）

| # | 方案 | 要点 | 验收 |
|---|---|---|---|
| M4 | 安装与分发硬化 | Manager/Registry 发布自动化、干净安装回归、版本与弃用策略、发布说明双语；**发布前处理 Registry 上 0.3.3 的 `NodeVersionStatusFlagged` 状态**（2026-11-01 实测，对 Manager 安装的影响未验证，见 docs/45） | 干净环境一键装 + 首图跑通；发布预演零人工步骤；Registry 版本状态正常 |
| M5 | 显存档位与模型矩阵 | 4G/6G/8G/12G/16G/24G 最小可用组合实测表；模型下拉/mmproj 配对；侧车跑完释放显存；与宿主共存实测 | 每档一张表 + 自动回归；用户按档抄作业 |
| M6 | 输入广度（caption 质量） | 分块反推（2×2/3×3）+ 本地 OCR 文字交叉 | 密集 UI/海报文字召回 +20%；OCR 与人工标注 IoU ≥0.5 |
| M7 | 兼容性契约 | 工作流 JSON 版本迁移器；节点参数只许追加末尾（已有铁律，补自动化）；V1/V3 出口守护 | 老工作流升级后参数逐位不变，迁移可回滚 |
| M8 | 社区贡献通道 | 「加后端/方言 = 加 YAML」产品化（schema + 模板 + CI 校验）；示例与前端贡献入口；硬约束一页纸 | 外部贡献者不改 Python 接入后端，CI 自动验证 |

### 第三梯队（长期：护城河）

| # | 方案 | 要点 | 为什么值得 |
|---|---|---|---|
| M9 | 评测元评估 | 自动分 vs 人类排序相关性；ρ<0.5 就删分 | 防「自己发明分数当结论」 |
| M10 | 失败模式自检系统化 | 同架构异权重、mmproj 宽度、MTP 共存、截断、KV 预算 → doctor 式自检 + **节点 report 红旗** | 把「为什么需要这个项目」产品化 |
| M11 | H3 产线模板库 | 参考图对齐/续接/项目影像规格做成可参数化块，与产线节点对齐 | 视频线深度用户直接受益；不依赖 LoRA 基座决策 |

### 明确不做

不做一套通用模板（各模型提示词哲学互斥，统一模板必在某后端静默失败）；不再扩模型面
（候选集已收口，再扫只增噪音）；不把量化保真度（KL/复读率）当效果结论；不用 `confidence`
当放行闸（校准未过，只能排序）；不自动下载权重（体积/许可/网络三重问题）；LoRA 许可未声明
前只做内部验证。

## 4. 顺序与理由

1. **M1**：唯一「既能提升现有节点产出质量、又能产出对外可引用数字」的方案，不需要下载权重。
   先修缺陷再扩样本，否则 60 图只是把错误结论放大。
2. **M2 / M3**：开源第一个月是 issue 洪水；兼容性闸（宿主版本、示例、Registry 元数据）与
   用户文档是防波堤，且都不依赖 GPU。
3. **M4 / M5**：安装与「我的卡能不能跑」是 ComfyUI 用户最常问的两件事。
4. **M6 / M7 / M8 / M9 / M10 / M11**：按实际用户声音排优先级，不提前铺开。
