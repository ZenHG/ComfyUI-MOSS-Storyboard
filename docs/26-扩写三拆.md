# 扩写三拆：补全 / 翻译 / 改写

> 2026-11-01。回答一个问题：`--mode llm` 的扩写出问题时，**问题来自哪一步**。
> 判据口径见 `docs/24-smith-ir-扩写判据.md` §1（三种语义）；验收口径见后续任务书 §T2。

---

## 0. 三句话

1. **补全、翻译、改写是三种语义，不是三档强度。** 一次调用同时做三件事，出了错无法归因，
   也没法单独关掉某一项。
2. **拆开之后每一步都能单独判死**：补全查「默认值来源」，翻译查「术语表命中」，
   改写查「事实集合不变」——三条判据全是纯 Python，零模型、零网络。
3. **默认路径一个字节都不动**：拆步是 opt-in（`adapter.expand_steps = None` 为默认），
   四条真机逆向 IR 的确定性输出 sha256 由 `tools/freeze_smith_set.py` 钉住，仍然全绿。

---

## 1. 三步各做什么

管线起点是该方言的**确定性草稿**（`adapter._render(..., "deterministic")`，不调模型、
必然合法），然后按固定顺序叠加：

```
确定性草稿 ──▶ 补全 ──▶ 翻译 ──▶ 改写 ──▶ verify()（最终体检，仍由它兜底判死）
```

| 步 | 输入 → 输出 | 只允许做什么 | 判据 | 需要的资产 |
|---|---|---|---|---|
| **completion 补全** | 草稿 + OPEN 槽位 → 补上槽位的草稿 | 只填 `setting / camera / lighting / material / medium`；不动已说过的事实 | 每一项填充可追溯到「该风格的公认默认」；改固定项 / 造数字 / 造引号文本 / 造专名判 **error** | `steps.DEFAULT_LIBRARY` |
| **translation 翻译** | 含中文口语的草稿 → 目标方言措辞 | 只把中文口语换成方言术语；引号内图内文字**逐字不动** | 术语表命中率（分母 = 源文里真正出现的术语数）；漏一个术语判 **error** | `steps.GLOSSARY` |
| **rewrite 改写** | 目标方言措辞 → 重排后的措辞 | 只重排顺序；不加、不删、不改事实 | 事实集合不变（复用 roundtrip 的 scanner）；丢了/多了事实判 **error** | — |

为什么起点用确定性草稿而不是让模型从空白写：**关掉任何一步、甚至三步全关时，产物仍
必须是一个合法 prompt**。确定性草稿就是那个兜底。这也是「降级可用」和「残废」的分界。

补全**不许补 `subject`**：主体缺了是 IR 的洞，编一个主体等于换一个人，不是默认值问题。
图内文字（`text` 维）同理不补——它必须逐字。

## 2. 怎么开

**默认关**（`expand_steps = None` = 历史单次调用）。要拆步就显式给元组：

```python
from moss_llm.smith.adapters import get_adapter

ad = get_adapter("moss-image", registry, llm=llama)
ad.length = "standard"
ad.expand_steps = ("completion", "translation", "rewrite")   # 拆步，三步全开
```

| `expand_steps` | 行为 | 模型调用次数（每候选） |
|---|---|---|
| `None`（**默认，关**） | **历史单次调用**：一次做完三件事，行为与拆步前一致 | 1（+ 回炉 1） |
| `()` | 拆步但三步全关：直接交付确定性草稿 | 0 |
| `("completion",)` | 只补全 | 0–1 |
| `("translation",)` | 只翻译 | 0–1（源文无中文时跳过） |
| `("rewrite",)` | 只重排 | 0–1 |
| `(全部三步)` | 完整管线 | 0–3 |

规则：

- 接受三种合法形态：`None`/`False`（不拆）、逗号分隔字符串、步名元组/列表；
  **其它类型**（如误写 `expand_steps = True`）会显式 `ValueError` 并列出可用步名——
  开关写错要有人看见，而不是在别处炸一个 `TypeError`。
- 顺序**固定**为 补全 → 翻译 → 改写；写元组时的顺序不影响执行顺序。
- 未知步名直接 `ValueError`（写错的开关应该有人看见，而不是静默当没开）。
- 每步调用前先过 `steps.precheck()`：
  - 补全：没有可补的 OPEN 槽位 → 不调模型；
  - 翻译：源文里没有术语表命中的中文 → 不调模型；
  - 改写：上一步产物为空 → 不调模型。
  「没对象还硬做」只会带来无谓的事实漂移。
- 每候选仍走历史的分层排序（`Report.score()`），步级 error 也计入硬错层；
  回炉只回喂**出问题的那一步**，不再对着整段重写碰运气。

### 2.1 默认是关的：怎么开、开了之后多少成本

**默认 = 关。** `Adapter.expand_steps = None`（类属性默认值）表示 llm 模式仍走历史的
**一次调用**（补全/翻译/改写一次做完）；确定性路径完全不读这个开关。拆步必须显式打开：

```python
ad.expand_steps = ("completion", "translation", "rewrite")   # 三步全开
ad.expand_steps = ("completion",)                            # 只开补全
ad.expand_steps = ()                                         # 拆步但三步全关（= 交付确定性草稿）
ad.expand_steps = None                                       # 回到默认（关）
```

成本按「每个候选」计（默认 `gen_candidates=4`、`gen_retries=1`）：

| 档 | 模型调用次数 | 输入 token | 说明 |
|---|---|---|---|
| **默认关** | 1 次/候选 + 回炉最多 1 次 | 账本（历史大小） | 与拆步前完全一致 |
| 开 1 步 | ≤1 次/候选 | 账本 + 该步 system（默认值库或术语表，约 0.3–0.6k token） | 预检不通过就 0 次 |
| 开 2 步 | ≤2 次/候选 | 同上 | |
| 开 3 步 | ≤3 次/候选 | 同上 | 翻译/改写常被预检跳过，常见 2–4 次 |

- 上界：3 步 × 4 候选 + 一次回炉（最多再 3 次）≈ 15 次调用；只有「三步全开 + 四个候选
  全失败」才会到，命中即停。
- 开启后**输入 token 也会涨**：补全的 system 里带默认值库、翻译的带术语表，各约几百 token。
- 真机耗时/质量收益**没有实测**（单测全用假 LLM，见 §6）；要控成本可把
  `gen_candidates` 降到 1，或只开需要归因的那一步。

## 3. 判据细节（能判什么、判不了什么）

### 3.1 补全

默认值库按键是 `IR.style.medium`（`photograph` / `manga` / `illustration`，
认不出退回 `generic`），值是该风格在各维度上的**闭集**默认值。同一个库既写进 prompt
（模型只能从这里选），也用来核对（判据只认这里的条目）。

可判的五类对象：

| 判据 | 级别 | 说明 |
|---|---|---|
| 改动固定项（图内文字 / 年龄 / 用户指定项） | error | 与源文本相比**新引入**的才算这一步的错；继承下来的不算 |
| 凭空造数字 | error | 最高置信的幻觉信号（可数、可验证） |
| 凭空造引号文本 | error | 图里没有这段字 |
| 造专名（句首之外的大写词，IR 里没有） | error | 人名 / 品牌 / 地名最常见 |
| 填了 OPEN 槽位但内容不在默认值库 | error | 「不可追溯的新细节」里能客观判的一类 |
| 新加颜色词 | warn | 颜色在 `verify` 里本来就按软项处理 |
| 补全后仍空着的槽位 | warn | **宁缺勿编**：没填不是错，报告要说出来 |

### 3.2 翻译

- 术语表条目形如 `中文 → [可接受英文写法, ...]`。命中率 = 命中术语数 / 源文出现的术语数。
- **分母为 0 时判「不适用」**（`applicable=False`、`verdict="skipped"`、不产出 hit_rate）：
  没有对象的比率不能算 100% 通过。
- 引号内的图内文字先被遮蔽再判术语：它必须逐字保留，翻译步不得动它（改了判 error）。
- 漏翻的术语判 error 并点名；译文里仍有术语表未覆盖的中文只判 warn（判不了它该不该翻）。

### 3.3 改写

- 事实集合：用 `decompose.scan()` 读源文与产物的字面事实（引号文本 / 年龄 / 数字 /
  颜色 / 方位），集合必须相等；丢了或多出都判 error。
- 词袋保留率：只该重排，所以词袋应几乎不变；< 0.9 判 warn（可能用错了步）。
- 还能量到「顺序真的变了没有」（`metrics.order_changed`），但不把「没重排」判错——
  顺序本来就对时，不改是正确行为。

### 3.4 判不了的（边界，别当结论用）

- **开放词汇的幻觉**：凭空加的情节、关系、氛围、情绪。补全只判五类可判对象（数字 /
  引号 / 专名 / 槽位可追溯性 / 颜色），开放词汇判不了，要人读或第二个模型交叉。
- **默认值库是闭集**，模型写出同义但不在库里的措辞会报 error。这是**有意的保守设计**
  （宁可报错给人看，也不静默通过），代价是可能误报；库可以扩，判据不用改。
- **术语表也是闭集**，未收录的中文词无法判。
- **「重排得好不好」「补得贴不贴切」**判不了：只判「有没有背叛事实 / 有没有不可追溯」。
- 步级判据不判长度带：长度由最终 `verify` 判一次，避免同一条警告被两个判据各算一遍。

## 4. 报告：问题来自哪一步

`expand.Report` 新增四个字段（`to_dict()` 里是新增键，**旧键一个没动**）：

| 字段 | 含义 |
|---|---|
| `stage` | 问题来自哪一步：`completion` / `translation` / `rewrite`；`single` = 历史单次调用（无法归因）；`""` = 未知（直接调 `verify()`） |
| `stage_issues` | `{步名: [问题]}`，只列有问题的步 |
| `steps` | 每步的执行摘要（含**关掉的步**）：`enabled / ran / applicable / verdict / metrics / note` |
| `stage_note` | 为什么这样归因（或为什么无法归因）的人话 |

规则：

- `stage` 先看 **error**，没有 error 再看 warn（按步顺序取第一个）。
- 步级 error 会以 `[补全] …` 的形式**升级**进整体 `errors` 并把 verdict 判 `fail`：
  否则「术语没翻但事实都在」会被最终 `verify` 判 pass，报告读起来像没问题。
- `steps` 里的 `verdict` 取 `pass / warn / fail / skipped`；`skipped` 同时可能是
  「关掉了」「没对象直接跳过」「模型返回空」三种，`note` 会写清是哪一种。
- 单次调用模式下 `stage="single"`、`steps=[]`，`stage_note` 明确写「无法归因到子步骤」。

## 5. 验证证据

全部零 GPU、零网络、假 LLM（`tests/test_expand_steps.py`，19 条）：

```
python tests/test_expand_steps.py        # 19 条全绿
```

| 组 | 条数 | 钉住什么 |
|---|---|---|
| 补全 | 4 | 可追溯填充 + 捏造数字 + 不可追溯填充 + **关掉仍合法** |
| 翻译 | 4 | 术语命中 + 漏翻点名 + 分母为 0 判不适用 + **关掉仍合法** |
| 改写 | 4 | 重排事实不变 + 改年龄被抓 + 丢图内文字被抓 + **关掉仍合法** |
| 归因 / 开关 | 5 | 归因到补全 / 归因到翻译 / 开关表留痕 / 全关=确定性 / 未知步名报错 |
| 默认路径 | 2 | 单次调用只调 1 次且 `stage="single"` / 确定性模式不看开关、逐字节不变 |

「合法」的断言口径是三条同时成立：`expand.verify().verdict != "fail"`、
`roundtrip.diff().ok`（零丢失）、`invariants.run()` 全绿。

回归基线（拆步默认关闭，所以确定性输出不受影响）：


## 6. 已知限制与未验证（如实清单）

1. **真机未验证**：以上全部是假 LLM 单测。真实 8B 模型上「三步是否各自守规矩」「默认值库
   闭集会不会频繁误报」「3 倍调用换来的归因值不值」都没有实测数据，**不作结论**。
   下一步应在真机上用同一份 IR 跑 单次 vs 拆步，比对 verify 硬错率、长度带命中与耗时。
2. **翻译步经常无对象**：当前反推产出的 IR 大多是英文，中文口语只出现在少数 IR
   （如 UI 截图里的中文标签）。所以拆步模式下翻译步常常是 `skipped`——这是如实反映，
   不是失败；翻译判据的价值要等中文 IR 真正进来才体现。
3. **默认值库覆盖窄**：只写了摄影 / 漫画 / 插画三类媒介的高频默认，其他媒介退回
   `generic`；扩库是纯数据改动（`steps.DEFAULT_LIBRARY`），判据不用改。
4. **补全的触发条件是「维度线索词」**：模型用了一个判据不认识的措辞去填槽位时，
   可能既不判填充也不判不可追溯（漏判），也可能把无关句子里的线索词当成填充（误判）。
   这条边界写在判据上方，未做词表之外的语义匹配。
5. **回炉只回喂第一步失败**：`stage` 只指向第一个出问题的步；同一次里第二步的失败要等
   下一轮才可能被修。回炉上限仍是 1 次，与历史一致。
6. **H3 不走这条管线**：`minimax-h3` 的 llm 模式整个替换了 `realize`（官方三字段改写契约），
   三拆只作用于图像后端的 `_render_llm`。H3 是否要拆是另一个问题。
7. **长度带在拆步模式下更容易落入 warn**：补全只补一个槽位的一句，未必够到 150–300 词
   下界；报告会如实报 warn，不假装达标。
8. **排序键的硬错层现在包含步级 error**：这是拆步模式的新行为（未拆步时步级 error 恒为 0，
   排序与历史完全一致）。

## 7. 扩展点（改数据，不改判据）

| 想加什么 | 改哪 |
|---|---|
| 某媒介的默认光 / 镜头 / 材质 | `steps.DEFAULT_LIBRARY[<style>][<dim>]` 加条目 |
| 让某个自由文本媒介名对上某个库键 | `steps._STYLE_ALIASES` 加一行 |
| 中文口语词 → 方言术语 | `steps.GLOSSARY` 加一条 `{中文: {"dim": …, "targets": (…, …)}}` |
| 槽位线索词 | `steps.DIM_CUES` |
| 判据本身 | `steps.check_completion` / `check_translation` / `check_rewrite`（各自独立） |

**改判据后必须跑**：`python tests/test_expand_steps.py` +
`python tests/test_smith_ir.py` + `python tools/freeze_smith_set.py --check`
（拆步默认关闭，所以判据改动不影响确定性基线——这正是「opt-in」的价值之一）。
