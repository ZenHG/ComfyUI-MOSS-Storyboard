## 4. 发现的问题（文档与实物不一致 / 建议补的坑）

> 按任务约定：**本轮不改别人文件/不改 README**，只记录并报 Lead。

### ① README「启动日志开头有 `ComfyUI Version:`」与实际不符

- 现象：README（中英）§1.2 末尾写 “Host version: the startup log starts with `ComfyUI Version:`”。
- 实物：启动 stdout 日志开头是 `[START] Security scan` / `** ComfyUI startup time:`；未见 `ComfyUI Version:`。
  ComfyUI 自身日志（`<ComfyUI>/user/comfyui.log`）里是小写：`ComfyUI version: 0.43.0`。
- 影响：用户按字面 Ctrl+F 找不到，会以为文档过时。
- 建议改法（中英同步）：写成「宿主版本：ComfyUI 自身日志（`<ComfyUI>/user/comfyui.log`）里的
  `ComfyUI version:` 行；启动画面里也有 `** ComfyUI startup time:` 与路径信息」。

### ② README 模型表把文本编码器写在 `models/clip/`，0.43 的正式目录名是 `models/text_encoders/`

- 实物：本机文件在 `models/text_encoders/qwen3.5_9b_int8_convrot.safetensors`；
  宿主 `folder_paths.py` 同时注册两个目录：`folder_names_and_paths["text_encoders"]
  = [models/text_encoders, models/clip]`，并有别名 `"clip": "text_encoders"`。
- 结论：**照 README 放到 `models/clip/` 仍然能跑**（兼容目录），所以不算错；但新版本
  ComfyUI 的界面/官方文档都用 `text_encoders`，只写 `clip` 会让新用户困惑。
- 建议改法：写成 `models/text_encoders/`（旧版宿主兼容 `models/clip/`）。

### ③ 启动日志在成功行后紧跟 `⚠ 未检测到 llama-server`，README 未说明

- 实物启动日志（同一份日志原文）：
  ```text
  [MOSS SB] v0.3.3 已加载｜节点 7 个（出口 v3）｜3/4/6/8/9 宫格
  [MOSS SB] 可选 LLM 子包 1 个节点（分类 moss/llm，不计入上面那 7 个）
  [MOSS SB] ⚠ 未检测到 llama-server：本包节点仍会出现，但跑起来会报错。…
  ```
- 影响：零权重用户（按 README Step 0 走的正是这批人）会看到黄色警告就以为装坏了。
- 建议改法：§1.2 或 Step 0 加一句「没装 LLM 子包/llama-server 时出现
  `⚠ 未检测到 llama-server` 是**正常**的：7 个核心节点不受影响；跑 caption/扩写类节点前再装即可」。

### ④ docs/45「报错表 13 行」的口径可以更精确

- 实物：中英表**可见各 14 行**；机检计入 **13**（`label 只能是 object/character/text` 那行是源码
  `label 只能是 %s（收到 %r）` 的合法三值展开，S18 明确豁免）。
- 影响：读者若自己数行会得到 14，与「13 行」对不上。
- 建议改法：docs/45 写成「可见 14 行；机检计入 13 行（1 行为源码 `%s` 合法展开）」。

### ⑤ Registry `latest_version.status = NodeVersionStatusFlagged`

- 实物：`api.comfy.org` 节点状态 `NodeStatusActive`、latest `0.3.3`；但 latest **版本**状态为
  `NodeVersionStatusFlagged`（被标记/待复核之一，具体含义未查官方文档）。
- 影响：Manager 里能否正常安装/显示该版本，**未验证**；安装动作本轮没做。
- 建议：发布前用 Manager 实装一次确认；若 flagged 影响安装，需按 registry 流程申诉/重发。
