# ComfyUI-MOSS-Storyboard

🌐 [English](README.md) · **中文**

![MOSS Storyboard：可视化布局编辑器、一次生成 4 格故事板、逐格精确裁切](assets/hero-storyboard.png)

给 **MOSS-Image** 用的**布局与编辑节点包**。两个用途：

- **故事板** —— 一张画布分成 3 / 4 / 6 / 8 / 9 格，每格一段描述，同时把每格裁出来。
- **局部编辑** —— 只改一格、或把一张脸换进一格；改完贴回，其它格逐像素不动。

> 🔴 **先记这一句：画布上的框是参考，不是坐标。**
> 框会变成一句带坐标的文字进提示词，模型自己决定画在哪——会画偏、画大、把两个框揉在一起，也可能完全不理。
> 细节与实测见 [1.6](#16-框只是参考能改变什么不能改变什么)。

| 项 | 值 |
|---|---|
| 版本 | **0.3.2** |
| 许可 | **MIT**（第三方出处见 [`THIRD-PARTY-NOTICES.md`](THIRD-PARTY-NOTICES.md)） |
| 宿主 | **ComfyUI ≥ 0.42.0**（原生支持 MOSS-Image 自 PR #17095 起） |
| 依赖 | 核心**零**额外 pip 依赖（`torch` / `comfy*` 由宿主提供）。换脸节点的自动蒙版可选装 `insightface` + `onnxruntime`，不装也能跑 |

**本包保证**：画布尺寸、每格坐标、裁切位置、宫格线位置 —— 算术，逐像素对齐。
**本包不保证**：画面内容、元素落点、跨格是不是同一张脸 —— 由模型采样决定。

## 1 · 装好，出第一张图

### 1.1 装什么

| 依赖 | 必需 | 放哪 |
|---|---|---|
| ComfyUI **≥ 0.42.0** | ✅ | 更低版本没有 `moss_image` 这个文本编码器类型 |
| `moss_image_sft_bf16.safetensors` | ✅ | `models/unet/`（或 `models/diffusion_models/`） |
| `qwen3.5_9b_int8_convrot.safetensors` | ✅ | `models/clip/` |
| `flux2-vae.safetensors` | ✅ | `models/vae/` |
| 额外 pip 包 | ❌ | 无（换脸自动蒙版可选 `insightface` + `onnxruntime`） |

权重**不随包分发**。下载地址与目录名以官方教程为准：<https://docs.comfy.org/tutorials/image/moss-image/moss-image>。

**4 步蒸馏 LoRA 是可选的，也不属于本包。** 示例里预置了 `LoraLoaderModelOnly` 但**默认旁路**，
没装不影响跑。示例用 **MOSS-Image-SFT 模型卡口径：50 步 / cfg 3 / euler / sgm_uniform**；
装了 LoRA 就 `Ctrl+B` 取消旁路，并把 `steps` 改成 **4**、`cfg` 改成 **1.0**。

> ⚠ **两档不能混。** 装了 LoRA 却跑 50 步 / cfg 3，或没装 LoRA 却跑 4 步 / cfg 1.0，
> 都不会报错，但结果会变差（有时整张发黑）。见 [2.3](#23-配方两档别混)。

### 1.2 装

**ComfyUI Manager（推荐）**：搜 **MOSS Storyboard** → 安装 → 重启 ComfyUI。

**ComfyUI CLI**（安装带 `comfy` 命令时）：

```bash
comfy node install moss-storyboard
```

**git**：

```bash
cd <你的 ComfyUI>/custom_nodes
git clone https://github.com/ZenHG/ComfyUI-MOSS-Storyboard
```

重启后，节点菜单 **`moss/storyboard`** 下出现七个节点，启动日志有一行（`<版本号>` 为实际装的版本）：

```
[MOSS SB] v<版本号> 已加载｜节点 7 个（出口 v3）｜3/4/6/8/9 宫格
```

**没有这一行 = 包没加载。** 这比任何配置检查都直接。
要退回旧的 V1 接口：设环境变量 `MOSSSB_NODE_API=v1`。

### 1.3 跑第一张

1. 装好上面的包与三个模型文件。
2. 把 [`examples/moss-layout-editor-storyboard.json`](examples/moss-layout-editor-storyboard.json)
   **拖进 ComfyUI 窗口**（或菜单 `Workflow → Open`）。连线已经接好。
3. 点 **Queue**。

产物：**1024×576** 整张 + 4 张 **496×272** 逐格。

> **图存在哪？** 本包自己不存图。示例接了 `SaveImage`，所以落在 ComfyUI 根目录的
> `output/moss/storyboard/`：`grid_*.png`（整张）与 `panel_*.png`（逐格）。

然后在「🎬 故事板 · 生成」的 **正面提示词** 里写：

```
雨夜咖啡店，单一画布分成严格对称的 4 格，细白线分隔；

[PANEL 2]: 特写，她的眼睫与玻璃雨痕

```

> 🔴 **最容易踩的一步：格数和段数必须一致。** 出厂默认 **8** 格，而上面这段只有 4 段 ——
> **先把节点上的格数改成 4**，否则采样前直接报错
> （`提示词有 4 段 [PANEL]，但布局是 8 格`）。反过来，写了 8 段却只有 4 格也一样报错。
> 画布尺寸自动算，**不用手填宽高**。

两个输出都是图，**都要自己接保存节点**：

| 输出口 | 是什么 | 接到哪 |
|---|---|---|
| `grid` | 整张宫格 | `SaveImage`（存盘）/ `PreviewImage`（只看） |
| `panels` | 逐格，数量 = 格数 | `SaveImage` —— 一次存 N 张 |

> 想先看宫格形状再花时间采样：从「🎬 故事板 · 宫格几何」的 `template` 接一个预览，
> 那是一张纯色格 + 缝的图，看得见每格在哪、缝多宽。

### 1.5 五个最常见的坑

| 坑 | 表现 | 怎么办 |
|---|---|---|
| 格数 ≠ 段数 | 采样前就报错 | 改格数，或把稿子补到同样段数，或 `init` 改 `plain` |
| 接了 `spec` 却改节点上的格数 | 画布形状没变 | **接了 `spec` 就以 `spec` 为准**，节点上的格数/长边/缝/边距不生效（`report` 第一行会写明） |
| 没接保存节点 | 跑完什么都没有 | 接 `SaveImage` |
| 配方混搭 | 一片黑 | 见 [2.3](#23-配方两档别混) |
| 链路里有 `LazyCache` | 与本页数字不可比 | `Ctrl+B` 旁路或删掉 |

### 1.6 框只是参考——能改变什么，不能改变什么

这是本包最容易被高估的地方。**要「框住哪里就精确画在哪里」，本包做不到，任何基于 MOSS 这套机制的节点也做不到。**

**框是怎么进模型的**：你画一个框，本包把它写成一句带坐标的文字，和别的描述一起进 `CLIPTextEncode`，
变成普通的文本条件。没有遮罩、没有区域条件、没有独立布局通道，采样时没有任何东西按坐标裁注意力。
MOSS 官方模板、KJ 的布局节点、本包，三者都是这一套。

**所以实际会看到**：元素画大/画小一圈、位置偏一点；两个框里的东西揉在一起；模型完全无视框、把内容全塞进一格；
框越小越容易被忽略（小字、小物体最先消失）；换 seed，遵循程度也会变。

**框能买到什么**：能改变「大致在哪、大致多大」，不能决定「精确落在哪」。
有一组只换框、不换字的对照：同一句描述，把框从画面外挪到左下角，自行车从「被裁掉」变成「完整在左下角」，
3 个 seed 都复现（共 36 张）。

**别拿框做这些**：

| 做不到 | 为什么 |
|---|---|
| 精确框住眼睛、手指、某个小物件 | 框只是文本里的坐标，模型不按坐标裁注意力 |
| 保证文字框边缘一个像素都不超出 | 框高不控字号：43px 高的框里字高约 130px，会溢出（见 [2.6](#26-已知边界)） |
| 保证两个元素不重叠 | 框之间没有互斥约束 |
| 保证跨格是同一张脸 | 身份不归框管，本包不承诺（见 [2.6](#26-已知边界)） |

**宫格模式下每格的框和裁切坐标出自同一份计算** —— 那是**几何上的精确**（裁出来的格子逐像素对齐），
不是**画面上的精确**。这两件事经常被混为一谈。

要像素级控制，得换带遮罩或区域条件的模型 / ControlNet，那不在本包范围内。
本包负责的是：把文字写对、把画布算准、把格子裁准、把改好的格子贴回去。

## 2 · 调参数

### 2.1 提示词怎么写

**三条规则**

1. 第一个 `[PANEL …]` **之前**的内容全部算**全局描述**（角色长相、场景、画风、相机）。
   写不写 `[STYLE]:` 都行——它只是便于阅读的标签，程序按位置算。
2. `[PANEL n]` 后面跟**这一格**的描述：景别 + 主体 + 动作。
3. **编号是排序键，不是格位。** 按编号升序排序，再依次与前 K 格配对：第 1 段配第 1 格，第 2 段配第 2 格……
   可以缺号、可以乱序（会先排序）；编号本身不选格（只写一个 `[PANEL 6]`，它仍然落在第 1 格）。

| 你写的 | 结果 |
|---|---|
| `[PANEL 1]: …` `[PANEL 2]: …` | 2 段描述 → 前 2 格有描述 |
| `[画面 1]: …` `[分镜 1]: …` | 一样有效（中英文标记都认） |
| 不写任何 `[PANEL]` + `init=plain` | 整段当普通提示词，**不生成布局框**（`report` 会说明）；画布仍是宫格画布 |
| 8 格只写 4 段 | **默认直接报错**，采样前就停。三条出路：补到 8 段 / 格数改 4 / `init` 改 `plain` |
| 一格写了好几行 | 合并成一段，不影响 |

**两条经验**

- 角色在不同格里不一致，**先改全局描述那一段**——它的权重最大。
- 一格只写一个镜头。写「中景 + 特写」这种复合描述，模型会自己挑一个。

### 2.2 格数 → 画布

下表是**单格 16:9、单格长边 496、缝 8、外边距 8** —— 交付示例的设置
（4 格正好 1024 宽，所以这一档有时叫「1024 档」）。
**出厂默认是单格长边 512**，比这个大两档，画布也跟着大。全文两套数都会标明属于哪一档。

| 格数 | 排列形状 | 画布 | 百万像素 | 每格 |
|---|---|---|---|---|
| 3 | **竖条**（上下 3 格） | 512 × 848 | 0.43 | 496 × 272 |
| 4 | **田字**（2 × 2） | **1024 × 576** | 0.59 | 496 × 272 |
| 6 | **横条**（2 行 × 3 列） | 1520 × 576 | 0.88 | 496 × 272 |
| 8 | **横条**（2 行 × 4 列） | 2032 × 576 | 1.17 | 496 × 272 |
| 9 | **九宫格**（3 × 3） | 1520 × 848 | 1.29 | 496 × 272 |

**每格大小不随格数变**，变的是画布。8/9 格落在 MOSS 的 1–2 百万像素训练区间；
3/4/6 格低于该区间（仍能出图，但属于外推）。

**竖构图（单格 9:16）**：整体转 90° —— 3 格变横条（848 × 512），6 格变 2 列 × 3 行（576 × 1520），
8 格变 2 列 × 4 行（576 × 2032），4 格与 9 格不变。

| 想改什么 | 调哪个 | 说明 |
|---|---|---|
| 每格大一点 | **单格长边** `panel_edge` | 128–2048，步进 16。画布自动跟着变 |
| 强行换排法 | **列数** `columns` | 填列数，`rows` 留 0 自动补齐；两者相乘必须等于格数 |
| 只要横排 3 格 | `columns = 3` | 3 格默认竖条：横排 3 个 16:9 会让画布变成 1520 × 288（约 5.3:1），超出包内 4:1 的容忍线 |

**为什么尺寸都能被 16 整除**：MOSS 的 VAE 把图缩小 16 倍，宽高不是 16 的倍数就会错位。
节点自动对齐；多出来的 0–15 像素**只加在右边和下边的外边距**（与宫格线同色，看不出来），
**绝不改动单格尺寸** —— 否则每格坐标会漂。

### 2.3 配方：两档，别混

| 你装了什么 | 步数 / cfg | 采样器 / 调度器 |
|---|---|---|
| **只用底模**（示例默认） | **50 / 3.0** | `euler` / `sgm_uniform` |
| **叠了 4 步蒸馏 LoRA** | **4–8 / 1.0** | 同上 |

- 两档**不能混**：装了 LoRA 却用 50 步 / cfg 3，或没装却用 4 步 / cfg 1.0，不报错但会变差（有时整张发黑）。
- 蒸馏 LoRA 是按 cfg 1 蒸的，调高会破坏蒸馏效果。
- `euler` 是模型卡采样器；`sgm_uniform` 来自 OpenMOSS 官方 ComfyUI 插件工作流（模型卡未指定调度器）。
  调度器清单直接读宿主 `comfy.samplers.SCHEDULER_NAMES`，宿主装了新档位这里自动出现。
- **`denoise` 留 1.0**：生成节点没有图像输入，调低不会参考任何图，只会让宿主按 `int(步数/降噪)`
  截断 sigma（等于少跑几步）；`report` 打印「名义 / 实际」，以实际值为准。
- 模型卡另写 shift 5（原生 ComfyUI 模型已内置）与 SLG 负分支层 22（需接宿主
  `SkipLayerGuidanceDiTSimple`，`single_layers` 填 `22`；本包示例未接）。ComfyUI 原生模板用
  25 步 / cfg 2.5 / er_sde（Comfy-Org 的选择），**不是**模型卡配方。

### 2.4 显存要多少

这条链路里最吃显存的一步是 **VAE 解码**，不是采样。同一个画布，宿主版本不同，解码申请的显存能差 **4 倍**。

| 画布 | 格数 | 新版宿主 | 旧版宿主 |
|---|---|---|---|
| 1024 × 576 | 4 | 约 0.6 GB | 约 2.4 GB |
| 2032 × 576 | 8 | 约 1.2 GB | 约 4.8 GB |
| 1520 × 848 | 9 | 约 1.3 GB | 约 5.2 GB |
| 2096 × 608 | 8（出厂 512 档） | 约 1.3 GB | 约 5.2 GB |

前三行是交付示例的 496 档，最后一行是出厂默认的 512 档。
**你属于哪一列**：修正提交是 `d07dff4`（2026-10-23），包含它的按「新版」，否则按「旧版」；
桌面版 / 便携包 / pip 取决于版本，**不确定按旧版留余量**。

**显存不够会怎样**：宿主先按整图解码试一次，失败后自动退回**分块解码**，分块边界会留下接缝，
位置不固定，可能正好穿过你的格子。日志里出现 `retrying with tiled VAE decoding` 就是这件事。

**怎么办**（代价从低到高）：① `git pull` 更新宿主（旧版把解码显存算成了实际的 4 倍）；
② 把 `panel_edge` 调小（边长减半 → 解码显存降到 1/4）；③ 少用几格（8 换 4，画布面积减半）。

> ⚠ 省显存那条路径要求 VAE 跑在 fp16 或 bf16。加了 `--fp32-vae`，或宿主因故把 VAE 跑成 fp32，
> 它会**静默失效**（不报错，只是变回旧版）。

**12 GB 单卡 · 整张模式实测档位**（50 步 / cfg 3.0 / euler + sgm_uniform / 16:9；
⚠ 这组**带着 4 步蒸馏 LoRA** 跑，与上面 50/3 无 LoRA 的口径不同源，只看趋势与余量。
原始数据只记了峰值显存与是否 OOM，**没有判图**；而且「4 步 LoRA + 50 步」正是易黑配法之一，
别当推荐配方。）

| 格数 × `panel_edge` | 画布 | MP | 峰值 MB |
|---|---|---|---|
| 4 × 512 | 1056×608 | 0.64 | 11359 |
| 4 × 544 | 1120×640 | 0.72 | 11176 |
| 6 × 512 | 1568×608 | 0.95 | 11250 |
| 6 × 544 | 1664×640 | 1.07 | 11267 |
| 8 × 512 | 2096×608 | 1.27 | 11269 |
| 8 × 544 | 2224×640 | 1.42 | 11298 |

> 0.64–1.42 MP 之间峰值都贴着 11.2–11.4 GB（**整张余量约 0.9 GB**）；全轮最差点是**逐格 8×544**，
> 余量 0.7–0.8 GB。所以 12 GB 能跑这些档，**但桌面已经占着显存时仍可能 OOM**（峰值本身带约 ±200 MB 噪声）。
> 别读成「12 GB 够用」。数据 [`docs/data/g1-results.json`](docs/data/g1-results.json)，
> 逐跑记录 [`docs/data/g1-report.md`](docs/data/g1-report.md)。

### 2.6 已知边界

#### 实测通过的

**每一行都标注了所用的 LoRA 与步数配置。**

| 项 | 配置 | 结论 | 抽查 |
|---|---|---|---|
| 3/4/6/8/9 格 · 横竖 · 无缝 · 粗缝 · 小画布 · `plain` | 底模 + 4 步 LoRA / **4 步** | 尺寸与理论值逐像素一致 | 16 例（端到端矩阵真跑） |
| 宫格线 | 同上 | 复绘后缝与外框纯白 | 每例 |
| 随机种子 | 同上 | 换种子 → md5 不同 | 2 次 |
| **元素框限定构图** | 底模 + 4 步 LoRA / **4 步**；底模 + 8 步 LoRA / **8 步** | 只换框：自行车从「被裁掉」变成「完整在左下角」；3 个 seed 复现 | 36 张 |
| **文字四字**（1024×576） | 底模 + 8 步 LoRA / **8 步** | 四字中文标题全对 | 2 个 seed |
| **文字四字**（2048×1152） | 底模 + 4 步 LoRA / **4 步** | 全对，笔画略软 | 2 个 seed |
| **文字四字**（2048×1152） | 底模 + 8 步 LoRA / **8 步** | 全对，笔画锐利 | 2 个 seed |
| **中英混排 / 两行 / 指定颜色** | 底模 + 8 步 LoRA / **8 步** | 全对；换行被尊重；红色生效 | 2 个 seed |

> **只用底模、不叠 LoRA**：跑过一张 2048×1152 / 30 步 / cfg 3.5 的对照（在默认值对齐官方模板之前），
> 出图正常，但**没有逐字核对文字**，所以不作为结论 —— 这一档要自己验证。

#### 文字：能到哪、到不了哪

| 项 | 结论 | 配置 |
|---|---|---|
| 分辨率 | 1024×576 已够；2048 只是笔画更锐 | 8 步 LoRA / 8 步 |
| 步数 | 4 步可用但边缘软；8 步明显更锐；16 步与 8 步接近，收益递减 | 对应 LoRA |
| 字号 | 框高到画布 1/20 仍全对（1536×864 上约 43px） | 1536×864 / 2048×1152 |
| 换行 | `text` 里的 `\n` 被尊重，两行各自成型 | 2048×1152 / 8 步 |
| 颜色 | `palette: ["#d92b2b"]` 生效 | 2048×1152 / 8 步 |
| **框高控不住字号** | 43px 高的框，实际字高约 130px，**会溢出框**。⚠ 给不出「框要多宽才够」：实测两个**尺寸完全相同**的文字框（169×60、4 个字），一个清楚、一个只剩淡痕 —— **宽度不是判据**。唯一确定的差别是**离顶边的距离**（47% vs 6%，后者贴顶被裁） | — |
| **贴边会被裁** | 框顶距边缘 5% 时，字向上溢出被画布切掉，2 个 seed 都出现 | 2048×1152 / 8 步 |

> 样本量小（每项 2 个 seed）。「四字全对」在多组配置下重复出现，但**不作保证**；
> 「贴边被裁」只在红色那组复现过，**其他颜色没测**，保守做法是一律留边。
> 预设把文字框留在 10%，**10% 是否足够安全同样没验证** —— 它只是比 5% 更保守的起点。

#### 这一版做不到的

- **生成节点没有图像输入，所以它不做图生图。** 起点恒为空 latent，`denoise` 留 1.0。
  实测过「拿模板 latent 当起点」：35 步 / 降噪 0.85 → 纯黑；12 步 / 0.6 与 4 步 / 0.5 → 模板残影。
  **要改一张已有图**，走 [3.5 裁格 → 改 → 贴回](#35-裁格--改--贴回)，
  或直接用 [3.8 换脸节点](#38-换脸--蒙版局部编辑)（它是蒙版图生图，只重画蒙版内）。
- **不承诺跨格是同一张脸。** 身份由采样决定。本包给的是**工具**：
  「🎬 故事板 · 换脸」把参考图的脸换进**一格**——一次一格、靠参考图驱动，
  **不等于**「先定一张角色卡、再逐格派生」那条链（那条链要额外的独立节点包，不在本包）。
- **每格画什么只是「大体照办」。** 框是文字建议，不是选区（[1.6](#16-框只是参考能改变什么不能改变什么)）。
  MOSS 的布局能力官方标 *experimental*，本包没做成片评分。
- **8/9 格每格偏小**：交付示例 496 档约 496×272，出厂 512 档约 512×288。小字、细纹理最先糊 ——
  这是分辨率账，不是节点 bug。

#### 硬约束

- 画布与单格的宽高必须是 **16 的倍数**（节点已强制；手改 `spec` 会被拒绝）。
- 整图超过 2 百万像素会提示，超过 4 百万像素会强提示：MOSS 训练在 1–2 百万像素，官方外推约 4 百万。
- **VAE 解码精度由 ComfyUI 决定，不由权重文件决定。** 宿主加载 VAE 时会统一转到 `fp16`
  （GPU 不支持时退 `bf16` / `fp32`），所以 `flux2-vae.safetensors`（F32）与
  `flux2-vae_BF16.safetensors`（BF16）**跑起来是同一精度**（速度没单独测）—— 文件里的 dtype
  在加载时就被归一化了，只剩磁盘占用和加载内存的差别。要真正的 fp32 解码，用宿主启动参数
  `--fp32-vae`，本包不做第二套精度逻辑（那会和宿主的 `VAEDecode` 分叉）。
  另一个绕法：「生成」节点有 `latent` 输出，接你自己的 `VAEDecode`，用什么 VAE、什么精度都随你。

## 3 · 接进自己的流程

### 3.1 七个节点

| 节点（中文界面） | 代码名 | 必需？ | 作用 |
|---|---|---|---|
| 🎬 故事板 · 生成 | `MossStoryboardSampler` | **必需**（故事板） | 模型 + 编码器 + VAE + 提示词 → 整图 + 逐格。没接 `spec` 时用自己的格数参数算几何 |
| 🎬 故事板 · 宫格几何 | `MossStoryboardLayout` | 可选（推荐） | 算尺寸与每格坐标，出 `spec`、布局 JSON、宫格模板图。**不加载模型** |
| 🎬 故事板 · 裁格 | `MossStoryboardCrop` | 可选 | 只裁格。接 `spec` 就与生成时逐像素一致 |
| 🎬 故事板 · 贴回 | `MossStoryboardPaste` | 可选 | 把改好的单格按 `spec` 贴回整图 |
| 🎬 布局编辑器 | `MossLayoutEditor` | 可选（海报 / 自由布局） | 画布上摆元素 → 布局提示词 + 采样尺寸。**不加载模型** |
| 🎬 提示词 · 草稿编译 | `MossPromptCompiler` | 可选（官方 skill 桥） | 贴官方草稿 → MOSS 提示词 + 编辑器 state。**不加载模型** |
| 🎬 故事板 · 换脸 | `MossStoryboardFaceSwap` | 可选 | 参考图的脸 → 一格（或单图）。**要加载模型** |

**最小可用只有「生成」一个** —— 它自带全套几何参数。其余六个都是可选：
「宫格几何」用来先把几何固化成一根 `spec` 给多个下游；「裁格 / 贴回」用来改单格；
「布局编辑器」做海报；「草稿编译」接官方提示词 skill；「换脸」做身份或局部重画。

### 3.2 `spec` 是唯一几何真相

`spec` 是一串文字，把格数、画布、每格坐标全带上（`MOSS-SB1 panels=4 w=1024 h=576 cols=2 …`）。

| 谁产出 | 谁消费 |
|---|---|
| 宫格几何 · `spec` | 生成 · `spec`（只吃几何，不吃提示词） |
| 生成 · `spec` | 裁格 · `spec`、贴回 · `spec` |
| 布局编辑器 · `spec`（单张模式 = 1 格） | 生成 / 裁格 / 贴回 |

**规则只有一条：接了 `spec` 就以 `spec` 为准。** 生成节点上的格数、单格长边、缝宽、外边距还在，
但**不生效**，`report` 第一行会写「几何来源：spec 接线」。这是最常踩的坑。

不接 `spec` 时，裁格 / 贴回必须手填 `columns` / `rows`（填 0 直接报错，不会瞎猜）。

### 3.3 生成节点

`MossStoryboardSampler`，输出 7 个：`grid` `panels` `latent` `spec` `prompt_used` `report` `prompts_json`。

- **`prompt_used`** —— 你填进去的原始稿，原样透传。**不是**模型看到的话。
- **`prompts_json`** —— **真的发给模型的那句话**，JSON 数组：`整张` 模式 1 条，`逐格` 模式每格 1 条。
  要复盘「词写的画面做到了没」从这里接。
- **`latent`** —— `整张` = 整张画布 latent；`逐格` = N 个单格 latent 的 batch
  （`{"samples": [N,C,h,w]}`，行主序 = 格 1..N，**不是拼版**）。接 `VAEDecode` 逐张解码。

下表是**出厂默认值**。交付示例用 **4 格 / 单格长边 496**，配方 50 步 / cfg 3 / euler / sgm_uniform。

| 参数 | 默认 | 说明 |
|---|---|---|
| 正面提示词 `positive` | 空 | 故事板稿，写法见 [2.1](#21-提示词怎么写) |
| 生成方式 `mode` | `整张` | `整张` 一次采样；`逐格` 每格独立采样再拼版，见下 |
| 格数 `panels` | 8 | 没接 `spec` 时生效 |
| 单格比例 `panel_aspect` | `16:9` | 没接 `spec` 时生效（10 种：`16:9` `3:2` `4:3` `1:1` `4:5` `3:4` `2:3` `9:16` `21:9` `2.39:1`） |
| 单格长边 `panel_edge` | 512 | 没接 `spec` 时生效 |
| 画布比例 `canvas_aspect` | `auto` | 没接 `spec` 时生效，`auto` 挑最接近的排法 |
| 缝宽 / 外边距 `gutter` / `margin` | 8 / 8 | 没接 `spec` 时生效 |
| 步数 `steps` | 50 | 模型卡值。配 4 步蒸馏 LoRA 时改 **4–8**，见 [2.3](#23-配方两档别混) |
| CFG `cfg` | 3.0 | 模型卡值（官方 Base 范围 3–6） |
| 采样器 / 调度器 | `euler` / `sgm_uniform` | 见 [2.3](#23-配方两档别混) |
| 送词方式 `init` | `auto` | `auto` / `layout` = 每格描述转布局框；`plain` = 不转布局框 |
| 降噪 `denoise` | 1.0 | **留 1.0**：没有图像输入，调低只是截断 sigma |
| 复绘宫格线 `reborder` | 开 | 解码后按坐标重画线。关掉只能指望模型把线画直 |
| 采样边长 `sample_edge` | 1024 | 只在 `逐格` 模式生效 |
| 负面提示词 `negative` | 空 | 在「高级」折叠区。**恰好** `cfg=1.0` 时不进计算图，1.01 起照常生效 |
| 随机种子 `seed` | 0 | 0–4294967295。**同种子 + 同参数**才能复现同一张图；换种子会换构图，框的遵循程度也会变 |

> `negative` 为什么收起来：它是可选输入、默认留空，收进「高级」只是不让它看起来像必填项。
> **可以用自己的负面提示词** —— 默认 `cfg=3.0` 已经 > 1，填了就生效。

**`mode`：整张 vs 逐格**

> ⚠ 两个词字面相近、含义相反：**「单张」** = 编辑器的 single 模式，一张图**不分格**（海报）；
> **「整张」** = 生成节点的 `整张`，一张画布**分 N 格**、一次采样出全部。

| 选项 | 实际做什么 | 什么时候用 |
|---|---|---|
| `整张` | **默认**。一次采样出整张宫格，快；同一张脸更稳 | 只想看个大概、格数多（8/9）时 |
| `逐格` | 每格**独立采样**再按坐标拼版，慢（每格一次采样） | 要**逐格返工**、或要每格更高像素时 |

- **同一张脸 → 整张赢。** ArcFace 余弦：整张 `0.553` > 逐格 `0.479`
  （单场景、单 seed；同一把尺子、同一批图内的相对比较）。
  ⚠ 这把尺子在**本域没通过校准**：52 对正样本里 18 对检不到脸（35%），所以**只报数，
  不当放行判据、不设阈值**；绝对阈值也不能跨域套用（本域异人之间就有 `0.52` 左右）。
- **单格细节 / 单格返工 → 逐格赢。** 每格独立采样，像素更多；一格不对可以只重做那一格。
- **其余代理指标方向随场景变**（例如「红帽在四格里的出现比例方差」：双人场景逐格更统一，
  单人场景反过来），所以不作为推荐依据。读数留在 [`docs/07`](https://github.com/ZenHG/ComfyUI-MOSS-Storyboard/blob/main/docs/07-consistency.md)。
- **口径**：以上数字来自 **50 步 / cfg 3.0** 的实测
  （[`docs/data/g2-50-3.json`](docs/data/g2-50-3.json)，2026-10-27）。旧版 8 步 / cfg 1.0 / 蒸馏 LoRA
  那组**不是当前口径、也不能横向比**，只作历史留档在 `docs/07` §二之三。
- **整张模式要模型真的分格，全局段必须声明宫格** —— 见
  [`docs/15`](https://github.com/ZenHG/ComfyUI-MOSS-Storyboard/blob/main/docs/15-recipe-contract.md)。

**`sample_edge`（逐格模式的采样长边）**

`1024` = 每格按 1024 长边采样，再缩回最终格子。给的是**绝对像素**而不是倍数，
让「画质需求」和「排版需求」互不绑架。代价是显存与耗时按像素平方涨；`整张` 模式忽略这个参数。

> 实测（4 格 / 16:9）：`496` 偏糊；`992` 明显更清楚；`1984` **反而变松**（构图变散）。
> 所以不是越大越好，`1024` 只是稳妥起点 —— ⚠ 这一轮**没测 `1024`**，样本数也没记，
> 所以它是**出厂起点、不是测出来的最优**。`docs/07` 另有一句「`1024–1408` 清楚但色调会漂」，
> 同样只当方向看。

> ⚠ **每格分到的像素会随格数变少。** MOSS 训练在 1–2MP，而 9 格 1:1 时每格只分到 **0.26MP** ——
> 整图看着正常，每格明显糊。`report` 会同时报这两个数字。格数多、比例接近 1:1 时试 `逐格`。
> `逐格` 模式下这条告警只看**单格采样画布**（`sample_edge`），不再拿最终格子的大小喊糊。

### 3.4 宫格几何

`MossStoryboardLayout`，不加载模型。输出 9 个：`width` `height` `columns` `rows` `spec` `layout_json` `template` `report` `elements`。

| 入参 | 说明 |
|---|---|
| `panels` | 1–12（常用 3 / 4 / 6 / 8 / 9；其它值自动做整数分解） |
| `panel_aspect` / `panel_edge` | 单格比例（10 种）/ 单格长边，默认 512 |
| `gutter` / `margin` | 缝宽 / 外边距 |
| `prompt` | **留空是对的**：这个节点只算尺寸。填了只影响 `layout_json` 与 `elements` |

| 输出 | 给谁 |
|---|---|
| `width` / `height` | `EmptyFlux2LatentImage` 的尺寸 |
| `columns` / `rows` | 裁格 / 贴回的同名输入（这样它们就不用接 `spec`） |
| `template` | 宫格模板图（纯色格 + 缝），肉眼核对格子位置。**不进采样器** |
| `spec` | 下游几何 |
| `layout_json` | 与宿主原生 `MOSS-Image Layout Prompt` **同格式**（`summary` + `items`，bbox 是画布中心原点的绝对像素）。接 `CLIPTextEncode` |
| `elements` | 画布**元素**格式（`{type, desc, bbox}`，bbox 是 **0–1000 归一化**、`[y0,x0,y1,x1]`） |
| `report` | 一行总结：格数、画布、像素数、提示词对齐了几段、有没有超像素警告 |

**`elements` 接宿主 `Create Bounding Boxes` 时必须接三条线**，少一条框就全错：

```
width    → Create Bounding Boxes · width
height   → Create Bounding Boxes · height
elements → Create Bounding Boxes · bboxes
```

原因：`elements` 的 bbox 是 0–1000 归一化，画布节点要用 `width`/`height` 换成像素。
画布节点默认 1024×1024；8 格横条是 2032×576 ⇒ 不接线就是**静默错框**。

⚠ **`elements` 是单向输出。** 在画布节点里改描述**不会**回到本包 —— 生成节点没有 `elements` 入参。
它的用途是「看得见格子、能改描述给人看」，采样几何仍来自 `spec` 与 `[PANEL n]`。
⚠ **两套格式不通用**：`elements` 是画布元素（归一化 0–1000），`layout_json` 是完整布局 JSON（绝对像素）。
⚠ 宫格的 `elements` **只表达格位**：每格一条 `{"type":"obj"}`，`desc` 是该格描述，不含文字元素、
不承载字号/颜色。要画面内文字，走编辑器的文字元素或草稿编译。

### 3.5 裁格 → 改 → 贴回

**裁格（`MossStoryboardCrop`）** —— 只有 `image` 必接。

| 输入 | 默认 | 说明 |
|---|---|---|
| `image` | — | **必接**。整张宫格图 |
| `spec` | 空 | 接「生成」或「宫格几何」的 `spec` ⇒ 裁切与生成时逐像素一致。不接就必须填 `columns` / `rows` |
| `columns` / `rows` | 0 / 0 | 没接 `spec` 时**必填**，填 0 直接报错 |
| `index` | -1 | `-1` = 输出全部格子；填 0 起的格号 = 只输出那一格，并把格号送到 `index` 输出 |
| `shave` | 0 | 每格四边内缩像素，吃掉溢出的缝。改了就要在「贴回」用同样的值 |
| `resize_edge` | 0 | `0` 保持原尺寸（推荐）；`>0` 把每格长边缩到该值 |
| `target_aspect` | `keep` | 保持单格原比例（零重采样）；选具体比例会中心裁切 |
| `padding_mode` | `crop` | `crop` 裁掉多余边；`pad` 补黑边（不丢画面） |
| `show_guides` | 关 | 在 `preview` 上把裁切线画成红色，用来目检 |

输出：`panels` `preview` `report` `index`。

**贴回（`MossStoryboardPaste`）** —— `grid` 与 `panel` 都必接。

| 输入 | 默认 | 说明 |
|---|---|---|
| `grid` | — | **必接**。整张宫格（「生成」的 `grid`，或上一级「贴回」的输出） |
| `panel` | — | **必接**。改好的那一格 |
| `index` | 0 | 贴到第几格，**0 起、行主序**。接了裁格的 `index` 输出就以它为准 |
| `shave` | 0 | **必须与裁格时一致** |
| `spec` | 空 | 接上才与生成时逐像素一致；不接就手填 `columns` / `rows` |
| `show_guides` | 关 | 在 `marked` 上把贴回区域框成纯红，用来目检 |

输出：`grid`（改好的整张）`marked`（调试）`report`。

- **只动目标格的内容区**：缝、外边距、其它格逐像素不变。
- **`shave` 不一致会走 bicubic 重采样**（内容被缩放、边缘多/少一圈），不是整体偏移。
  `report` 会明确写「已重采样」。
- **要逐像素一致**：裁格 `resize_edge=0`、`target_aspect=keep`、`shave` 与贴回相同。
- **改多格就串联多个「贴回」**：前一个的 `grid` 接后一个的 `grid`。

**推荐接法**（格号全程不用手打）：

```
裁格（index 填要改的那格）─panel─→ 你的编辑流程 ─→ 贴回
裁格 ──index─────────────────────────────────────→ 贴回
生成 ──grid──────────────────────────────────────→ 贴回
生成 ──spec──────────────────────────────────────→ 贴回 / 裁格
```

#### 「你的编辑流程」怎么搭（可选，本包自身不需要任何 LoRA）

本包只负责几何：裁出来、贴回去。**中间那一步用什么，随你** —— 别的节点包、外部修图、手改后重新载入都行。

想直接用 MOSS 自己的指令编辑，宿主官方节点就够，不需要第三方节点包：

```
裁格(index) ──→ Text Encode MOSS-Image Edit ──→ KSampler ──→ VAEDecode ──→ 贴回
                     ↑ 需要下面这个 LoRA
```

1. 下载社区编辑 LoRA **Moss-Image-Edit**（约 285 MB，bf16，rank 64），两个源文件相同：
   [Hugging Face](https://huggingface.co/chinoll/Moss-Image-Edit) ·
   [ModelScope](https://www.modelscope.cn/models/ChenkinLab/Moss-Image-Edit)。
2. 把 `adapter_model.safetensors` 与 `adapter_config.json` 放进
   **`models/loras/Moss-Image-Edit/`**（新建子目录，两个文件放一起）。
3. 用宿主的 **`Text Encode MOSS-Image Edit`**：`clip` 接你的 CLIPLoader（`type=moss_image`）；
   `images` 接裁出来的那一格；`edit_format` 选 `Moss-Image-Edit`；
   **`vae` 可以不接** —— 不接时参考图只进文本编码器，更省显存，也不会把参考图的空间结构强加到结果上；
   接了会额外用参考 latent，构图保持更强但更吃显存。
4. 后面接普通 `KSampler` → `VAEDecode` → 「贴回」。这条链由社区 LoRA 驱动，官方底模口径不适用：
   本机实测 **30 步**（cfg 的取值我们自己的记录前后不一致，这里不写死）；再叠 4 步蒸馏 LoRA 时用 **8 步 / cfg 1.0**。

**它能做什么、不能做什么**（实测）：改颜色、服装、光照、风格 —— 指令服从度好。
**季节没测过，不承诺。** 不接 `vae` 时构图保持更弱（**机理推断，没有单独对照**）。
**它不擅长「换个机位重新画」**，那还是得走布局提示词重新生成。

⚠ **它不是跨格一致性方案。** 定位是**单格微调**：改一格的颜色、服装、光线，改完贴回。
拿它把某一格往其它格靠，实测会让每格越来越像同一张图（景别趋同），而故事板要的是「同一角色、不同景别」。

> **许可与边界**：这个 LoRA 是第三方社区权重，**不随本包分发**，也不由本包维护。
> 其模型卡标注代码部分为 GPLv3，权重许可以模型卡为准。本包只在使用文档里指向它，
> 不复制、不修改、不分发任何权重文件。本包自身（MIT）不依赖它 —— 不下载也能完整使用故事板生成与贴回。

### 3.6 布局编辑器

`MossLayoutEditor`，不加载模型。**做海报、封面、产品图，或自由布局的故事板，从这个节点开始。**
节点上直接是一块画布：左边摆框，右边填描述。框只是参考（[1.6](#16-框只是参考能改变什么不能改变什么)）。

输出 7 个：`prompt` `width` `height` `spec` `template` `report` `negative`。

| 模式 | 预设 | 出什么 | 接到哪 |
|---|---|---|---|
| **单张** | 左右分栏 / 上下分栏 / 标题+主体+正文 / 三列 / 中心主体 / 层叠 / 自由 | 一个多元素 layout JSON，**一次采样整张** | `CLIPTextEncode.text`，再接普通 `KSampler` |
| **宫格** | 宫格 | `[STYLE]` + 逐格 `[PANEL n]` | 「生成」的 `positive` + `spec` |

> 单张模式的 `prompt` 输出**已经是布局 JSON**，直接喂 `CLIPTextEncode` 就行。
> 接「生成」也可以 —— `spec` 走 **1 格**，提示词原样送，不会再被当成段落解析。
> `width` / `height` 接 `EmptyFlux2LatentImage` 的尺寸。
> **只想出一张不分格的图**：用单张模式，或在「生成」上把 `panels` 设为 1
> （`init=plain` 只改送词方式，**不取消**宫格几何）。
> `negative` 只在单张模式 + 打开「融合成一张」时非空（几个防拼贴的词），宫格模式恒为空串。

| 入参 | 说明 |
|---|---|
| `editor_state` | **不用手填**，这是画布的存档，改画布时自动更新。手改也行，但必须是 v3 JSON，格式错了会报错并指出哪个字段 |
| `prompt` | 可选，接线。接上后接管**文字**：全局描述 + 每格描述与景别 |

**接了外接提示词之后**

- 覆盖到的格子，编辑器里的描述（包括预设文案）被替换，描述框变只读；拔掉连线恢复手编。
- 段数不足：后几格沿用编辑器描述。段数多出：多出的段丢弃。没有 `[PANEL n]`：只改全局描述。
- 没写景别的那一格不注入景别（构图交给描述）。
- **画布、格数、每格坐标永远来自编辑器** —— 外接稿改不了几何。单张模式没有分格，只接管全局描述。

**画布操作**

| 操作 | 结果 |
|---|---|
| 空白处拖 | 画一个新框（新元素） |
| 拖框 / 拖四角 | 移动 / 缩放 |
| 点框 | 右侧改类型（物体 / 人物 / 文字）、描述、坐标；宫格模式只给**景别 + 描述** |
| 宫格「景别」下拉 | 八档预设；「自定义…」写自己的镜头语言；「不指定」只发描述。**UI 显示中文，提示词里输出英文构图子句**（MOSS 语料以英文为主） |
| 画布下「最终提示词」 | 可粘贴外部故事板稿，点**应用**按 `[PANEL n]` 反解析回格位；**还原**回到编译结果。滚轮在框内滚文本，不再缩放画布 |
| 拖到接近其他框的边、画布中线、三分线 | 自动吸附 |
| `Delete` / 方向键 / `Ctrl+D` | 删除 / 微移 / 复制 |
| `Ctrl+Z` / `Ctrl+Shift+Z`（或 `Ctrl+Y`） | 撤销 / 重做 |
| 工具栏「导入 / 导出」 | 导入 elements-v1（0–1000 bbox）或 state v3；导出 elements-v1（宫格不能导出） |
| 属性面板「上移 / 下移」+ 六向对齐 | 调层级（数组顺序 = z 序）或对齐边缘/中线；尺寸不变 |
| 工具栏「排队」 | 按当前工作流排队，不改任何值 |

**「最终提示词」是原样发出去的那段文字**（宫格是 `[STYLE]` + 逐格 `[PANEL n]`，单张是原生布局 JSON）。
只读、可一键复制，改任何字段它就跟着变；与后端同一套编译口径（差分测试逐字节比对），不是「示意文字」。
如果上游是运行时才算出来的节点，它会直接说「运行时才确定」，不拿旧内容冒充。

**预设占位会提醒你**：`标题文字`、`第 3 格画面` 这类预设内容不改就排队，文字框会被**逐字渲染**、
宫格会画成一堆雷同的格子。状态栏报数量，点「排队」时若仍有预设文字会先问一次，后端 `report` 同样会写。

**文字元素有两个框，别填混**

| 字段 | 填什么 | 例子 |
|---|---|---|
| **描述** `caption` | 这个字**长什么样** | 粗体无衬线大标题，浅金色，轻微描边 |
| **文字** `text` | **实际要渲染的字** | 示例标题 |

填反了模型会去画「粗体金色」这几个字。`text` 是唯一会被逐字渲染的字段。

> ⚠ **文字框不要贴边。** 实测框顶距画布边缘 5% 时，文字向上溢出会被裁掉。
> 预设留的是 10%，但这只比 5% 保守，**不代表 10% 已验证安全**。

> 外部 planner 产出的元素 JSON 可以直接「导入」成可编辑元素；命令行校验/转换见
> [`docs/12`](https://github.com/ZenHG/ComfyUI-MOSS-Storyboard/blob/main/docs/12-interop.md)（不需要装 ComfyUI）。

### 3.7 草稿编译

`MossPromptCompiler`，不加载模型。把 OpenMOSS 的 [MOSS-Image Prompt Enhancer skill](https://github.com/OpenMOSS/MOSS-Image/tree/main/skills/moss-image-prompt-enhancer)
接到本包。贴 skill 产出的**草稿**（不是它编译后的结果）。

**入参**只有一个多行框 `draft`：**caption 草稿**（`{"caption": "…"}`）编译成纯文本提示词；
**layout 草稿**编译成单行原生布局 JSON。草稿为空直接报错，不会吐一个空提示词。

| 输出（按顺序） | 内容 |
|---|---|
| `prompt` | 可直接用的 MOSS 提示词（普通 caption，或单行原生布局 JSON） |
| `report` | 类型、画布、元素数，以及哪些字段无法带进 state |
| `state` | 布局草稿另出一份 state v3 JSON，可粘进布局编辑器的导入框 |

> 三个口按**位置**接线，拖线前先看清顺序。画布须在 64–4096 内；超出时 `prompt` 仍会输出，
> `report` 说明为什么没生成 `state`。

草稿要求（官方 schema）：`width` / `height` 是 16 的正整数倍；`bbox_coord_space="abs"`；
`bbox_format="xyxy"`；`summary.caption` 与非空 `items`。每个元素是 `object` / `character` / `text`；
文字元素必须带实际渲染的 `text`。未知字段、重复键、NaN/Infinity、越界框一律拒绝。
本包另加**最多 256 个元素**、**草稿 1 MB** 两道上限。

skill 本身是外部 Apache-2.0 内容，**不随包分发**；本节点是按官方文档独立实现的。
细节见 [`docs/13`](https://github.com/ZenHG/ComfyUI-MOSS-Storyboard/blob/main/docs/13-prompt-enhancer.md)。

### 3.8 换脸 / 蒙版局部编辑

`MossStoryboardFaceSwap`。参考图的脸 → **一格**（或一张单图）。与包内其他节点一样是 **MIT**。

| 参数 | 作用 |
|---|---|
| `ref` → vision 通道 | 决定**是谁**。`vision_megapixels` 默认 `1.05`（宿主默认 `0.147` 时参考图只值约 `0.008`，等于没给） |
| `image` + `prompt` → 图生图 | 决定**画什么**。提示词要提到参考图（`in Picture 1`），前缀由节点拼 |
| `init` | **`source`**（默认）= 吃 `image` 做图生图，有蒙版就只重画蒙版内；**`empty`** = 不吃 `image`，从空 latent 开始 —— 参考图 + 提示词 → 一张新图 |
| `spec` + `index` | 只换那一格 —— 缝、外边距、其他格逐像素不变（实测 `max&#124;Δ&#124; = 0`） |
| `auto_mask` | **默认开。** insightface 自动找脸并生成蒙版。依赖缺失**直接报错**，不静默降级 |
| `face_pick` | `largest` / `left` / `right`。一格有几个人时点名；`report` 写「几张脸、用了哪张」 |
| `mask` | 可选，手接蒙版覆盖自动结果。接了就以手接的为准 |

**为什么它不只是「图生图」。** 官方的 MOSS 编辑是 **in-context**：参考图作为干净 token 在 `t = 0`
陪跑，`x` 从纯噪声开始，所以构图只能靠提示词**求**。本节点让源图当**起点**（`vae.encode` + `denoise`），
构图是**机制上**保住的。四条条件各管一件事：提示词 = 改什么，`ref` = 像谁，`image` = 保什么，
`mask` = 改哪里。背景阅读：[`docs/18`](https://github.com/ZenHG/ComfyUI-MOSS-Storyboard/blob/main/docs/18-masked-latent-edit.md)。

**蒙版是「修图」和「重画」的分界。** 接了蒙版只重画蒙版内，蒙版外只有解码舍入
（`mean&#124;Δ&#124; 0.40/255`，可见改动 <0.01%）；既没接线、又关掉 `auto_mask` 才是整格重画，
色调必漂（`R +24 … +53`）。`report` 会写明实际走了哪条，并直接给出覆盖率与蒙版外改动。

**蒙版长什么样。** 是**羽化矩形**，不是贴脸轮廓：上沿 `eye_y + 0.30 × (nose_y − eye_y)`，
下沿 `y2 + 0.06 × h`，左右各外扩 `0.05 × w`，羽化 `max(3, 0.02 × w)`。**白 = 重画。**
给整张宫格的蒙版也行 —— 节点按 `index` 用与图像同一套整数坐标裁到目标格。

**手接蒙版怎么写。** `ImageToMask(channel="red")` → `mask`。**别用 `LoadImage` 的 `MASK` 口**：
那是 alpha，灰度图没 alpha 时返回 64×64 全零，蒙版等于没接、整格被重画，而且不报错。
样张：`assets/faceswap-mask-example.png`。

**自动蒙版：装什么、权重放哪**

| | |
|---|---|
| 安装 | `pip install insightface onnxruntime` —— 装进**跑 ComfyUI 的那个 Python** |
| 权重 | `~/.insightface/models/buffalo_l/det_10g.onnx`（19 MB） |
| 只要这一个 | 节点只加载 `detection`，`w600k_r50.onnx`（174 MB，识别用）**不需要** |
| 想放别的盘 | 设 `MOSS_INSIGHTFACE_ROOT=<根目录>`，权重放 `<根目录>/models/buffalo_l/` |
| 下载 | <https://github.com/deepinsight/insightface/releases/download/v0.7/buffalo_l.zip>（把 `buffalo_l/` 解到 `models/` 下） |
| 自查 | 节点**不会自己联网下载**：权重缺失时报错里会打印它实际找的那个路径 |

本机其他检测轮子，以及本节点为什么不用：

| 轮子 | 给什么 | 权重位置 | 本包 |
|---|---|---|---|
| insightface `buffalo_l` | 框 + 5 关键点 | `~/.insightface/models/buffalo_l/` | **用** —— 与实测过的配方同源 |
| mediapipe face mesh | 478 点轮廓 | 随包，`site-packages/mediapipe/modules/`（55 MB） | 不用 —— 轮廓更贴不是瓶颈 |
| facexlib BiSeNet | 分区解析（皮肤/眉/眼/鼻/嘴/发） | `site-packages/facexlib/weights/parsing_bisenet.pth` | 不用 —— 语义最好，但多一个依赖且增益未测 |
| SAM | 精分割，要提示点/框 | 手动下 `sam_vit_*.pth` | 不用 —— 要提示 + 权重大，增益未测 |
| ultralytics YOLO | 只有框 | 手动下载 | 不用 —— 没关键点，还得自己缩 |

**姿态与肢体动作：都能动，把 `init` 设成 `empty`。** 七档头部姿态 + 九档肢体动作，
测的是**生成**路径（空 latent + 参考图进 vision）。默认 `init=source` 时身体在蒙版外、提示词动不了它。

| 测了什么 | 结果 |
|---|---|
| 头部 yaw，参考图**正脸** | 成立。一句提示词把 yaw 从 `+0.05` 推到 `+1.48`，近正侧、低头、仰头都出来了 |
| 头部 yaw，参考图**侧脸** | 不成立。参考图 yaw `+5.20`，七档提示词全画成侧脸 ⇒ **姿态跟参考图走，不跟提示词走** |
| 肢体动作（站立 / 插兜 / 抱胸 / 走 / 前伸 / 坐 / 转身 / 手抵下颌 / 背身回看） | 九档全部生效。净损失 `−0.086 … +0.112`，**九档里七档在 ±0.05 以内**（采样地板量级） |
| 躯干转侧、头仍朝镜头 | `+0.036`，没受损 |
| 背对镜头、回头看向肩后（yaw `0.76`） | `−0.086` ⇒ 伤脸的是**连带转头**，不是身体 |

⇒ **要换姿态：参考图给正脸，`init` 设成 `empty`，姿态写在提示词里。** 参考图本身是侧脸，输出就被锁在侧脸，
提示词拉不回来。只动身体时，让头继续朝镜头。两套梯度提示词与判据：
[`docs/17`](https://github.com/ZenHG/ComfyUI-MOSS-Storyboard/blob/main/docs/17-faceswap-recipe.md) §九。
现成示例：`examples/moss-pose-generate-ui.json`（10 节点，`init=empty`，**零第三方节点**）。

**两档参数**（同一张图同一蒙版实测）：

| 档 | 步数 / cfg | 用途 |
|---|---|---|
| 快档（默认） | 8 / 1.0 | 换脸 —— 脸那个尺度上材质看不出来 |
| 编辑档 | **30 / 5** | 衣服、头发、较大区域 —— 编辑 LoRA 自己的配方，质感明显更好 |
| 编辑档 + HQ LoRA | 30 / **3** | `MOSS-Image-Edit-HQ/armV5`（rank 64/192，495 MB）。实测覆盖与过渡最好 |

**`ref` 管「像谁」——给它一张脸部特写，别给整张场景。** 实测加一把椅子：ref 给整张场景时只画出一条红条
（蒙版内改动 14%）；给脸部特写时椅子出来了（51%）。整张场景的参考图等于告诉模型「这里没有别的东西」，
把新物体压掉。

**仍然做不到的**：一格两个人（各约 68px，两张都被换、彼此散开）、连续换两次（第二次像素级空转）、
用提示词把侧脸参考图拉回正脸。本页不发布「像不像」的分数 —— 本域余弦没有分辨力。
试过哪些旋钮、为什么都留在默认值：[`docs/16`](https://github.com/ZenHG/ComfyUI-MOSS-Storyboard/blob/main/docs/16-faceswap-refactor.md)。

**适用范围**（同一张中景单人图，蒙版来自 BiSeNet 语义解析）：

| 蒙版 | 覆盖 | 内改动率 | 外**可见**改动 | 结论 |
|---|---|---|---|---|
| 头发 | 1.3% | 85% | 0.00% | 成（受蒙版精度限制） |
| 衣服 | 16.4% | 97% | **0.01%** | **成** |
| 背景 | 76.8% | 70%（内 mean 仅 12） | — | **不成**：未遮的人物会把背景拉回原样 |

> 蒙版外判据用 **>32/255**，不用 >8：VAE 解码 + latent 混合的舍入就能产生 8–16 的差异，肉眼看不见。
> 衣服那组 >8 占 5.79%，>32 只有 0.01%（p99 = 17）。`report` 会把两档都写出来。

示例：`examples/moss-faceswap-ui.json`。

### 3.9 中英切换

每个**本包节点**标题栏上有一个「**中 / EN**」按钮。点一下，七个节点的标题、参数标签、
下拉显示、悬浮提示一起切换。默认跟随 ComfyUI 的语言设置。

- **只改本包节点**，官方和别人的节点一个字段都不动。
- **只改显示，不改图**：只动标签、标题、提示、占位文字；参数名和下拉框的**值**从不改
  ⇒ 执行行为与存档的参数值不受影响。自己改过的节点标题也会保留。
- **升级后必须刷新浏览器（F5）**。重启 ComfyUI 进程不算 —— 前端是单页应用，页面开着就一直跑旧 JS。
- **不用前端也能用**：后端默认可读文案是中文，JS 加载失败只是没有中英切换和编辑器，
  节点仍能按默认值运行；API 提交（`/prompt`）本来就用不上按钮。

看不到按钮：先在浏览器控制台看有没有 `[MOSS SB] i18n: 就绪`；没有就确认 `web/` 下的前端文件
（尤其 `moss_sb_i18n_ui.js`）是否由 `/extensions/ComfyUI-MOSS-Storyboard/` 正常加载。
