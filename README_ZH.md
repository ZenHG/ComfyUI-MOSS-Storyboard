# ComfyUI-MOSS-Storyboard

🌐 [English](README.md) · **中文**

![MOSS Storyboard：可视化布局编辑器、一次生成 4 格故事板、逐格精确裁切](assets/hero-storyboard.png)

给 **MOSS-Image** 用的**布局节点包**：在画布上摆元素（人物 / 物体 / 文字），输出一张图（宫格或单张）。

> 🔴 **先说清最容易误解的一点：画布上的框只是参考，不可能「指哪打哪」。**
> 框会变成一句带坐标的文字交给模型，模型自己决定画在哪——可能画偏、画大、把两框揉在一起，也可能完全不理。
> **为什么、能到什么程度，见下面 [布局框只是参考](#布局框只是参考不可能指哪打哪)。**

**第一次用？** 装好之后直接跳到 [快速开始](#快速开始)，那里有能照抄跑通的最短路径。

两种用法，同一套机制：

- **故事板宫格** —— 一张图整齐分成 **3、4、6、8 或 9 格**，每格一段描述，同时把每格裁出来。
  （`panels` 也接受 1–12 的其它格数并自动做整数分解；3/4/6/8/9 是示例与实测覆盖的形状。）
- **海报 / 封面 / 产品图** —— 主体、文字块各占一块区域，文字直接指定要渲染的字。

> 「故事板」也常被叫作分镜图、宫格图、漫画格。本包做的是同一件事。

**本包保证的**：画布尺寸、每格坐标、裁切位置、宫格线位置——这些是算术，逐像素对齐。
**本包不保证的**：画面内容、元素落点、跨格是否同一张脸。这些由模型采样决定。

## 先看这三条，能省掉大多数误解

1. **布局框只是参考，不可能「指哪打哪」。** 框会变成一句带坐标的文字进提示词，模型自己决定画在哪，
   **没有遮罩、没有区域条件**。下一节专门讲这件事，以及「那框还有什么用」。
2. **默认一次生成整张画布；也可以选「逐格」：每格独立采样再拼版。**
   两条路各赢一半：**同一张脸更稳**是整张赢，**每格细节更清楚、能单格返工**是逐格赢。
   逐格更慢（每格一次采样），格数越多越慢——本包不是加速节点，不提供秒数。
   单格多大只由「单格长边 + 单格比例」决定，**不会因为格数变多而变小**；
   格数变多变大的是画布，以及跟着涨的显存。逐格时每格按 `sample_edge` 单独采样。
3. **默认「复绘宫格线」开：解码后按同一份坐标重画线和缝，位置与线宽确定。**
   关掉这一项才会让模型自己画线（可能歪、可能断）。

## 布局框只是参考，不可能「指哪打哪」

这一节讲的是本包最容易被高估的地方。如果你的需求是「框住哪里就精确画在哪里」，本包做不到，任何基于 MOSS 这套机制的节点也做不到。

### 框是怎么被模型看见的

你在画布上画一个框，本包把它写成**一句带坐标的文字**：

```
{"caption": "一个骑自行车的人", "bbox": [y0, x0, y1, x1]}
```

这句话和别的描述一起进 `CLIPTextEncode`，**变成普通的文本条件**。

- **没有遮罩**（mask）
- **没有区域条件**（regional conditioning）
- **没有独立的布局通道**，也没有任何东西在采样时按坐标裁剪注意力

MOSS 官方模板、KJ 的布局节点、本包，三者都是这一套。这不是本包偷工减料，是 MOSS 现在的机制就是这样。

### 所以实际会发生什么

- 元素可能**画大一圈 / 画小一圈**，位置**偏一点**；
- **两个框里的东西可能揉在一起**（比如你把人和桌子分开放，模型画成人在桌上）；
- 模型可能**完全无视框**，把内容全塞进一格；
- **框越小越容易被忽略**——小框里的字、小物体最先消失；
- 同一个提示词换不同 seed，框的遵循程度会变。

### 实测下来，框能改变什么

**能改变「大致在哪、大致多大」，不能决定「精确落在哪」。**

有一组只换框、不换字的对照：同一句描述，把框从画面外挪到左下角，自行车从「被裁掉」变成「完整在左下角」，3 个 seed 都复现（共 36 张，见 [已知边界](#已知边界报-bug-前先看这里)）。

这是**方向性的改变**：能决定「有没有」「在左边还是右边」「占大块还是小块」。它不是坐标级定位——框的边缘落在第几像素，模型并不遵守。

### 那框还有什么用

- 让多元素画面**有分区**，明显减少互相侵占；
- 保证某个元素**在**、而且**大概在**某个方位，比纯文字描述更稳；
- **宫格模式下，每格的框和裁切坐标出自同一份计算**——这是**几何上的精确**（裁出来的格子逐像素对齐），不是**画面上的精确**。这两件事经常被混为一谈。

### 别这么用

| 做不到 | 为什么 |
|---|---|
| 精确框住眼睛、手指、某个小物件的位置 | 框只是文本里的坐标，模型不按坐标裁注意力 |
| 用框保证「文字框边缘一个像素都不超出」 | 框高不控字号，实测 43px 高的框里字高约 130px，会溢出（见 [文字：能到哪](#文字能到哪到不了哪)） |
| 用框保证两个元素不重叠 | 框之间没有互斥约束，模型可能把两者画到一起 |
| 用框保证跨格是同一张脸 | 身份一致性不归框管，本包也不承诺（见 [这一版做不到的](#这一版做不到的)） |

**要像素级控制，得换带遮罩或区域条件的模型 / ControlNet，那不在本包范围内。**
本包负责的是：把文字写对、把画布算准、把格子裁准、把改好的格子贴回去。

## 比官方 MOSS 布局多什么

官方 ComfyUI 模板已经支持**单画布 bbox 布局**。本包在这之上做可复现的多面板工作流。

**先把定位说清**：本包**不卖「控制构图」**（上一节已说明框只是参考，谁都做不到）。本包卖的是
**把手工活做掉**——画布尺寸、每格坐标、裁切、拼回，这些是算术题，本包算准了；画面内容仍然由模型决定。

| | 官方 MOSS 布局 | 本包 |
|---|---|---|
| 单张图 + bbox / 文字 | ✅ 原生 | ✅ 可视化编辑器 + 8 预设 |
| 一张画布多面板故事板 | — | ✅ 3 / 4 / 6 / 8 / 9 格 |
| 每格描述 → 布局框 | 每格手画框 | ✅ `[PANEL n]` 分段 |
| 精确逐格裁切 | 手算裁切 | ✅ `spec` 驱动，逐像素对齐 |
| 可复用布局状态 | 节点字段 | ✅ v3 state + 撤销/重做 |
| 编辑器内排队 | — | ✅ 一键 |
| 外部 planner JSON | — | ✅ elements-v1 + CLI |
| 额外 pip 依赖 | — | 无（换脸的自动蒙版可选加 `insightface`） |

**不适合**只做单主体、一两个框的单图——官方模板更简单。**适合**需要可复现多面板、每格描述或逐格裁切的场景。

> **从这里开始**：[`examples/moss-layout-editor-storyboard.json`](examples/moss-layout-editor-storyboard.json)
> 是完整的 4 格故事板工作流；装好三个模型文件，打开，排队。

## 核心功能

| 能力 | 说明 |
|---|---|
| **3 / 4 / 6 / 8 / 9 格** | 格数是输入（`panels`），排法与画布尺寸自动算，宽高全部对齐 16 |
| **每格单独描述** | 提示词里按 `[PANEL 1]`…`[PANEL n]` 分段，自动转成 MOSS 原生布局框 |
| **可视化布局** | 节点内嵌画布：拖框决定每个元素**大致**占哪块区域，右侧填描述。框会变成提示词里的坐标——**只是参考，模型不保证照办**（见 [布局框只是参考](#布局框只是参考不可能指哪打哪)）。文字元素单独填「要渲染的字」 |
| **8 种布局预设** | 宫格 / 左右分栏 / 上下分栏 / 标题+主体+正文 / 三列 / 中心主体 / 层叠 / 自由（空画布），一键出起点 |
| **文字海报** | 中文、英文、中英混排、两行均有小样本实测（结论与样本量见「已知边界」） |
| **宫格线确定** | 默认 `reborder=开`；解码后按坐标重绘，白缝位置与生成时一致 |
| **逐格裁切** | 行优先输出，与整图画布逐像素对齐；`spec` 一根线传完几何，下游不会错位 |
| **官方提示词 skill 桥** | 贴 OpenMOSS MOSS-Image Prompt Enhancer skill 的草稿：出校验过的 MOSS 提示词；布局草稿另出一份 state v3，可直接导入布局编辑器 |
| **中英双语界面** | 每个本包节点上有「中 / EN」按钮，只改显示、不改存档 |
| **零 GPU 机检** | 全部离线断言（清单见 [`CONTRIBUTING.md`](CONTRIBUTING.md)） |

**七个节点，一个入口就够。仓库示例接的是完整故事板链；最小工作流只需要「生成」一个** ——
它自带全套几何参数。「布局编辑器」是另一个入口：不写提示词段落，改在画布上摆框，
适合海报、封面、产品图。「宫格几何」是可选的前置：用来先看宫格形状，或把几何固化成
一根 `spec` 传给多个下游。「提示词 · 草稿编译」是官方提示词 skill 的桥：贴官方草稿，
出 MOSS 提示词，布局草稿另出一份可导入布局编辑器的 state。

| 节点（中文界面显示） | 代码名 | 必需？ | 作用 |
|---|---|---|---|
| 🎬 布局编辑器 | `MossLayoutEditor` | 可选（做海报/自定义布局时用） | 画布上摆元素，出布局提示词 + 采样尺寸。**不加载模型**，秒出 |
| 🎬 故事板 · 生成 | `MossStoryboardSampler` | **必需**（故事板） | `模型 + 文本编码器 + VAE + 正面提示词` → 整图 + 逐格。没接 `spec` 时用**自己**的格数参数算几何 |
| 🎬 故事板 · 宫格几何 | `MossStoryboardLayout` | 可选（推荐） | 算尺寸和每格坐标，出布局提示词与宫格模板图。**不加载模型**，秒出 |
| 🎬 故事板 · 裁格 | `MossStoryboardCrop` | 可选 | 只裁格。接 `spec` 就与生成时逐像素一致，也能切已有的宫格图 |
| 🎬 故事板 · 贴回 | `MossStoryboardPaste` | 可选 | 把改好的单格按 `spec` 贴回宫格，输出改好的整图。改一格不用重跑整张 |
| 🎬 提示词 · 草稿编译 | `MossPromptCompiler` | 可选（官方 skill 桥） | 贴官方 prompt-enhancer 草稿 → MOSS 提示词 + 布局编辑器 state。**不加载模型**，秒出 |
| 🎬 故事板 · 换脸 | `MossStoryboardFaceSwap` | 可选 | 参考图的脸 → 某一格（或单图），vision 注入身份 + 图生图重画。**要加载模型** |

> 节点名在**英文界面**下按上表顺序是 `MOSS Layout Editor` / `MOSS Storyboard Sampler` /
> `MOSS Storyboard Layout` / `MOSS Storyboard Crop` / `MOSS Storyboard Paste` / `MOSS Prompt Compiler`。
> **接了 `spec` 就以 `spec` 为准**：「生成」节点上的格数、单格长边、缝宽、外边距**还在，但不生效**，
> `report` 第一行会写明「几何来源：spec 接线」。这是最常踩的坑。

## 安装

**ComfyUI Manager（推荐）**
在 Manager 里搜 **MOSS Storyboard** → 安装 → 重启 ComfyUI。

**ComfyUI CLI**（如果你的安装带 `comfy` 命令）

```bash
comfy node install moss-storyboard
```

**git**

```bash
cd <你的 ComfyUI>/custom_nodes
git clone https://github.com/ZenHG/ComfyUI-MOSS-Storyboard
```

重启 ComfyUI。节点菜单 **`moss/storyboard`** 下出现七个节点，启动日志里有一行
（`<版本号>` 为实际安装的版本）：

```
[MOSS SB] v<版本号> 已加载｜节点 7 个（出口 v3）｜3/4/6/8/9 宫格
```

**没这行 = 包没加载**，这比任何配置检查都直接。
要退回旧的 V1 接口：设环境变量 `MOSSSB_NODE_API=v1`。

## 快速开始

**最快路径——直接用现成工作流**

1. 装好本包与上面三个模型文件。
2. 把 [`examples/moss-layout-editor-storyboard.json`](examples/moss-layout-editor-storyboard.json)
   **拖进 ComfyUI 窗口**（或菜单 `Workflow → Open` 选这个文件）。拖进去就能看到连线，不用自己接。
3. 点 **Queue**（排队）。产物：**1024×576** 整张 + 4 张 **496×272** 逐格。

> **图存在哪？** 本包自己**不存图**。示例里已经接了 `SaveImage`，所以会落在 ComfyUI 根目录的
> `output/moss/storyboard/` 下：`grid_*.png`（整张）与 `panel_*.png`（逐格）。
> **没接任何保存节点 = 图只在内存里，跑完就没了**——自己接线时别忘了接一个。

**从零接线**

**① 接线**——三个加载器，各自插到「🎬 故事板 · 生成」对应的输入上：

| 加载节点 | 填哪个文件 | 它的输出插到「生成」的哪个口 |
|---|---|---|
| `UNETLoader` | `moss_image_sft_bf16.safetensors` | `model` |
| `CLIPLoader` | `qwen3.5_9b_int8_convrot.safetensors`，**`type` 必须选 `moss_image`**（宿主 < 0.42 没有这个类型） | `clip` |
| `VAELoader` | `flux2-vae.safetensors` | `vae` |

**② 选格数**：在「🎬 故事板 · 生成」上改 **格数**（`panels`）。出厂默认 **8**，
仓库里那份示例工作流设成了 **4**。画布尺寸会自动算——**不用手填宽高**。

> 🔴 **最容易踩的一步**：格数和稿子里的段落数**必须一致**。出厂默认是 8 格，而下面这段示例稿
> 只有 4 段 —— **先在节点上把格数改成 4**，否则采样前就会直接报错
> （报错原文：`提示词有 4 段 [PANEL]，但布局是 8 格`）。反过来，写了 8 段却只有 4 格也一样报错。

> 想先确认宫格形状对不对，再从「🎬 故事板 · 宫格几何」连一根 `spec` 过来：
> 它的 `template` 输出是一张预览图，看得见每格在哪、缝多宽。

**③ 写提示词**：填在「🎬 故事板 · 生成」的 **正面提示词**（`positive`）里：

```
雨夜咖啡店，单一画布分成严格对称的 4 格，细白线分隔；
苏晚：黑发低马尾、米白高领针织衫；陈屿：深灰外套、黑衬衫；
35mm 胶片、真实演员、自然皮肤纹理、浅景深

[PANEL 1]: 中景，两人对坐，她把柠檬水杯推向正中
[PANEL 2]: 特写，她的眼睫与玻璃雨痕
[PANEL 3]: 过肩，他抬眼看向窗外
[PANEL 4]: 桌面特写，两只手停在杯沿
```

**④ 接输出**。「生成」节点出两张图，都要自己接保存节点：

| 输出口 | 是什么 | 接到哪 |
|---|---|---|
| `grid` | 整张宫格 | `SaveImage`（存盘）/ `PreviewImage`（只看） |
| `panels` | 逐格，数量 = 格数 | `SaveImage`——一次存 N 张单格图 |

> 也可以直接用现成工作流：`examples/moss-storyboard-4panels-ui.json`，拖进 ComfyUI 即可
> （已分好组、带画布内说明）。
>
> 编辑器示例：`examples/moss-layout-editor-poster.json`（单张海报）与
> `examples/moss-layout-editor-storyboard.json`（4 格故事板）——拖进去即可改框。
>
> 草稿编译示例：`examples/moss-prompt-compiler.json`（**零模型、不占显存**）——
> 粘一份官方 prompt-enhancer 草稿，出提示词与可导入编辑器的 state。
> 三个输出各接一个宿主的 `PreviewAny`（界面显示为「Preview as Text」），图里没有别的东西。
>
> 换脸示例：`examples/moss-faceswap-ui.json`——4 格宫格进、换第 0 格、整张宫格出
> （要 8 步 DMD2 蒸馏 LoRA **和** Moss-Image-Edit 编辑 LoRA 两个都装）。

> ⚠ **四份带模型的示例里都有宿主的 `LazyCache` 节点**（默认 `reuse_threshold 0.2` / `start 0.15` /
> `end 0.95`），夹在 LoRA 与采样器之间。它**不是本包的节点**，是 ComfyUI 自带的
> （`comfy_extras/nodes_easycache.py`，标记为实验性，分类在 `advanced/debug`），作用是让采样器复用部分步。
> **要跟本页的数字对得上，就先 `Ctrl+B` 旁路掉或直接删掉它**——开着它，采样器跑的不是本页那些数测的那份活。
> 宿主版本太老没有这个节点时，ComfyUI 会报缺节点类型，删掉即可正常跑。
> 草稿编译示例不加载模型，没有这个节点。

**另一条路：海报 / 封面 / 产品图**

不写 `[PANEL n]` 段落，改在画布上摆：

1. 加「🎬 布局编辑器」，选一个预设（例如「标题+主体+正文」）。
2. 画布上拖框：标题一块、人物一块、副标一块。
3. 右侧填每个框的**描述**；文字框另填**要渲染的字**。
4. `prompt` 接 `CLIPTextEncode` 的 `text`，`width`/`height` 接 `EmptyFlux2LatentImage`。
5. 后面接普通 `KSampler`——MOSS-Image-SFT 模型卡口径是 50 步 / cfg 3 / euler；
   叠 4 步蒸馏 LoRA 时用 4 步 / cfg 1.0。

> **单张模式现在也给 `spec`（1 格）。** 把编辑器的 `spec` 接进「生成」节点，两边就**对应得上**：
> 画布来自编辑器、出 1 张、提示词按布局 JSON 原样送。0.3.0 之前这里给的是空串，
> 接上去等于没接——「生成」静默回退到自己的 `panels=4`，于是选了海报预设、出来的还是四宫格。
> 想走普通 `KSampler` 也行，两条路都成立。
>
> （顺带说清一个容易混的地方：**不经过编辑器**、只想出一张不分格的图时，可以只在「生成」上把
> `panels` 设为 1——那条路走的是提示词，不是 JSON，和上面这条警告不是一回事。）

## 出问题先查这里

**先对报错原文。** 下表每一行都是从源码里逐字抄的 `ValueError` 文案，`Ctrl+F` 报错里的几个字就能对上：

| 你看到的报错 | 原因 | 改法 |
|---|---|---|
| `提示词有 4 段 [PANEL]，但布局是 8 格` | 稿子的段落数 ≠ 格数 | ① 把稿子补到 8 段，并同步全局段里的计数；② 把「格数」改成 4；③ `init` 改 `plain`（原样送词，不做布局） |
| `全局段写「恰好 4 个面板」，但布局是 8 格` | 全局段里的格数与实际格数不一致 | 把那个数字改成实际格数，或删掉这句 |
| `图像 1024x576 不能被 3x3 整除` | 「裁格」没接 `spec`，只能按列×行硬除 | 接上 `spec`（推荐），或换成能整除的画布 |
| `draft 为空：请粘贴官方 prompt-enhancer 的 caption/layout 草稿 JSON。` | 「草稿编译」的输入是空的 | 贴的是**草稿**，不是编译后的结果 |
| `元素 3 没有描述（caption 不能为空）` | 画布上有框没填描述 | 给那个框填一句描述，或删掉它 |
| `label 只能是 object/character/text（收到 'xxx'）` | 手改 state / 草稿时写了别的类型 | 只用这三个值 |

**没报错但结果不对**，按这三条查：

| 现象 | 先看哪 |
|---|---|
| 一片黑 | 配方配错：装了 4 步蒸馏 LoRA 却用 50 步 / cfg 3，或没装 LoRA 却用 4 步 / cfg 1.0 |
| 格数对，内容全挤在一格 | 框只是参考，模型没照办（见 [布局框只是参考](#布局框只是参考不可能指哪打哪)）；把每格描述写短、写具体 |
| 画布形状和预览不一样 | 是不是接了 `spec`？接了就以 `spec` 为准，生成节点上的格数参数不生效 |
| 找不到节点 | 分类在 `moss/storyboard` 下；搜 `故事板` / `storyboard` / `宫格` 都行 |

完整问答（OOM、中英按钮、负面提示词等）在文末 [常见问题](#常见问题)。

## 提示词怎么写

**规则只有三条**

1. 第一个 `[PANEL …]` **之前**的内容，全部算**全局描述**（角色长相、场景、画风、相机）。
   写不写 `[STYLE]:` 都行——它只是个便于阅读的标签，程序按位置算。
2. `[PANEL n]` 后面跟**这一格**的描述：景别 + 主体 + 动作。
3. **编号是排序键，不是格位。** 程序按编号升序排序，再依次与前 K 格配对：
   第 1 段配第 1 格、第 2 段配第 2 格……可以缺号，也可以乱序（会先排序）；编号本身不选格
   （只写一个 `[PANEL 6]`，它仍然落在第 1 格）。

**合法的写法都长这样**

| 你写的 | 结果 |
|---|---|
| `[PANEL 1]: …` `[PANEL 2]: …` | 2 段描述 → 前 2 格有描述 |
| `[画面 1]: …` `[分镜 1]: …` | 一样有效（中英文标记都认） |
| 不写任何 `[PANEL]` | 整段当普通提示词，**不生成布局框**（等于纯文生图，`report` 会告诉你） |
| 8 格只写了 4 段 | **默认直接报错**（`提示词有 4 段 [PANEL]，但布局是 8 格`），采样前就停。三条出路：补到 8 段 / 把格数改成 4 / 把 `init` 改成 `plain` 原样送词 |
| 一格写了好几行 | 合并成一段，不影响 |

**两条经验**

- 角色在不同格里不一致，**先改全局描述那一段**——它的权重最大。
- 一格只写一个镜头。写"中景 + 特写"这种复合描述，模型会自己挑一个。

## 格数 → 画布尺寸

下表是**单格 16:9、单格长边 496、缝 8、外边距 8**——仓库交付工作流的设置
（4 格正好是 1024 宽，所以这一档有时被叫作「1024 档」）。

**出厂默认是单格长边 512**，比这个大两档，画布也跟着变大。全文两套数都会标明属于哪一档，别混。

| 格数 | 排列形状 | 画布 | 百万像素 | 每格大小 |
|---|---|---|---|---|
| 3 | **竖条**（上下 3 格） | 512 × 848 | 0.43 | 496 × 272 |
| 4 | **田字**（2 × 2） | **1024 × 576** | 0.59 | 496 × 272 |
| 6 | **横条**（上 2 行、每行 3 格） | 1520 × 576 | 0.88 | 496 × 272 |
| 8 | **横条**（上 2 行、每行 4 格） | 2032 × 576 | 1.17 | 496 × 272 |
| 9 | **九宫格**（3 × 3） | 1520 × 848 | 1.29 | 496 × 272 |

8/9 格落在 MOSS 的 1–2 百万像素训练区间；3/4/6 格低于该区间（仍能出图，但已超出模型的训练范围，属于外推）。

**换成竖构图（单格 9:16）**：整体转 90°——3 格变横条（848 × 512），6 格变 2 列 × 3 行（576 × 1520），
8 格变 2 列 × 4 行（576 × 2032），4 格与 9 格不变。

**三个可调项**

| 想改什么 | 调哪个 | 说明 |
|---|---|---|
| 每格大一点 | **单格长边**（`panel_edge`） | 128–2048，步进 16。画布自动跟着变，不用手算 |
| 强行换排法 | **列数**（`columns`） | 填想要的列数，行数（`rows`）留 0 自动补齐；两者相乘必须等于格数 |
| 只要横排 3 格 | **列数** = 3 | 3 格默认是竖条：横排 3 个 16:9 会让画布变成 1520 × 288（约 5.3:1），超出包内 4:1 的容忍线 |

**为什么尺寸都能被 16 整除**：MOSS 的 VAE 把图缩小 16 倍，宽高不是 16 的倍数就会错位。
节点自动对齐；多出来的 0–15 像素**只加在右边和下边的外边距**（和宫格线同色，看不出来），
**绝不改动单格尺寸**——否则每格坐标会漂。

## 显存要多少

这条链路里最吃显存的一步是 **VAE 解码**，不是采样。同一个画布，宿主版本不同，
解码时申请的显存能差 **4 倍**——旧版把预估写死成了实际的 4 倍。

| 画布 | 格数 | 新版宿主 | 旧版宿主 |
|---|---|---|---|
| 1024 × 576 | 4 | 约 0.6 GB | 约 2.4 GB |
| 2032 × 576 | 8 | 约 1.2 GB | 约 4.8 GB |
| 1520 × 848 | 9 | 约 1.3 GB | 约 5.2 GB |
| 2096 × 608 | 8（出厂 512 档） | 约 1.3 GB | 约 5.2 GB |

前三行是交付工作流的 496 档；最后一行是出厂默认的 512 档。

**你属于哪一档**：修正提交是 `d07dff4`（2026-10-23）。以宿主实际版本为准：包含它的按「新版」，否则按「旧版」。

| 你的安装方式 | 落在哪一列 |
|---|---|
| 桌面版 / 便携包 / pip | 取决于版本；**不确定按旧版** |
| `git clone` 且 2026-10-23 之后 `git pull` 过 | **新版** |
| `git clone` 但很久没 pull | **旧版** |

**显存不够会怎样**：宿主先按整图解码试一次，失败后自动退回**分块解码**。
分块会在画布上留下接缝，位置不固定，可能正好穿过你的格子。日志里出现
`retrying with tiled VAE decoding` 就说明发生了这件事。

**怎么办**（代价从低到高）：

1. `git pull` 更新宿主——旧版宿主上这是收益最大的一步
2. 把 `panel_edge` 调小：边长减半，解码显存降到 **1/4**
3. 少用几格：8 格换 4 格，画布面积减半，解码显存跟着减半

> ⚠ **VAE 精度要是 fp16 或 bf16 才走上面「新版」这一列。** 加了 `--fp32-vae`
> 或宿主因故把 VAE 跑成 fp32，省显存的那条路径会静默失效（不报错，只是变回旧版）。

## 节点与参数

### 🎬 布局编辑器（`MossLayoutEditor`，不加载模型）

**做海报、封面、产品图，或者想要自由布局的故事板，从这个节点开始。**

节点上直接是一块画布：左边摆框，右边填描述。框的位置会写进提示词，但**只是参考**——
模型可能画偏、画大，也可能完全不理（原因见 [布局框只是参考](#布局框只是参考不可能指哪打哪)）。

输出：`prompt` `width` `height` `spec` `template` `report` `negative`

> `negative` 只在**单张模式 + 打开「融合成一张」**时非空（几个防拼贴的词）；宫格模式恒为空串。
> 它的作用是不用手抄那几个词；不接也能出图。
> 单张模式下 `spec` 是 **1 格宫格**（画布 = 编辑器画布，缝与边距都是 0），可接「生成」「裁格」「贴回」；
> `template` 是一张纯色占位图。
> 宫格模式下两者都可用，`spec` 能接「裁格」「贴回」。

| 参数 | 说明 |
|---|---|
| **布局状态** `editor_state` | **不用手填**。这是画布的存档，改画布时自动更新。手改也行，但必须是 v3 JSON，格式错了会报错并指出哪个字段 |
| **外接提示词** `prompt` | 可选，接线。接上后接管**文字**：全局描述 + 每格描述与景别。详见下面一段 |

**接了外接提示词之后会怎样**

- 外接稿覆盖到的格子，编辑器里的描述（包括预设文案）被替换，描述框变只读；拔掉连线恢复手编。
- 段数不足：后几格沿用编辑器描述。段数多出：多出的段丢弃。没有 `[PANEL n]`：只改全局描述。
- 外接稿没写景别的那一格不注入景别（构图交给描述）。
- **画布、格数、每格坐标永远来自编辑器** —— 外接稿改不了几何。
- 单张模式没有分格，外接稿只接管全局描述。

节点上的「最终提示词」显示的是**合并后**的结果（就是真正发出去的那段）。
如果上游是运行时才算出来的节点，它会直接说明「运行时才确定」，不会拿旧内容冒充。

两种模式，用预设切换：

| 模式 | 预设 | 出什么 | 接到哪 |
|---|---|---|---|
| **单张** | `左右分栏` `上下分栏` `标题 + 主体 + 正文` `三列` `中心主体` `层叠` `自由` | 一个多元素 layout JSON，**一次采样整张** | `CLIPTextEncode` 的 `text`，再接普通 `KSampler` |
| **宫格** | `宫格` | `[STYLE]` + 逐格 `[PANEL n]` | 「生成」节点的 `positive` + `spec`；默认 `mode=整张`，要逐格返工或每格更高像素时切 `逐格` |

> 单张模式下 `prompt` 输出的是**已经是布局 JSON**，直接喂 `CLIPTextEncode` 就行；
> 接「生成」节点也可以——`spec` 走 1 格，提示词原样送，不会再被当成段落解析。
> `width` / `height` 接 `EmptyFlux2LatentImage` 的尺寸。

**画布怎么用**

| 操作 | 结果 |
|---|---|
| 在空白处拖 | 画一个新框（一个新元素） |
| 拖框 / 拖四角 | 移动 / 缩放 |
| 点框 | 右侧面板改**类型**（物体 / 人物 / 文字）、**描述**、**坐标**；宫格模式只给**景别 + 描述**（类型/文字/主色不参与宫格提示词，所以不显示） |
| 宫格「景别」下拉 | 八档是**预设**；选「自定义…」可写自己的镜头语言，「不指定」则只发描述。**UI 显示中文，提示词里输出英文构图子句**（MOSS 语料以英文为主） |
| 画布下方「最终提示词」 | 可直接粘贴外部故事板稿，点**应用**按 `[PANEL n]` 反解析回格位；**还原**回到编译结果。滚轮在框内滚文本，不再缩放画布 |
| 拖到接近其他框的边、画布中线、三分线 | 自动吸附 |
| `Delete` / 方向键 / `Ctrl+D` | 删除 / 微移 / 复制 |
| `Ctrl+Z` / `Ctrl+Shift+Z`（或 `Ctrl+Y`） | 撤销 / 重做（工具栏 `↶` `↷` 同效） |
| 工具栏「导入 / 导出」 | 导入 elements-v1（0–1000 bbox）或 state v3 JSON；导出 elements-v1（宫格不能导出） |
| 属性面板「上移 / 下移」+ 六向对齐 | 调层级（数组顺序 = z 序）或对齐画布边缘/中线；尺寸不变 |
| 工具栏「排队」 | 按当前工作流排队，不改任何值 |

> 外部 planner 产出的元素 JSON 可以直接「导入」成可编辑元素；命令行校验/转换见
> [`docs/12`](https://github.com/ZenHG/ComfyUI-MOSS-Storyboard/blob/main/docs/12-interop.md)（不需要装 ComfyUI）。

**画布下面有一条「最终提示词」**（状态栏与属性面板之间，不用滚动就能看到）：那是当前 state 编好后**原样发给模型**的文本 ——
宫格模式是 `[STYLE]` + 逐格 `[PANEL n]`，单张模式是原生布局 JSON。只读、可一键复制，
改任何一个字段它就跟着变；与后端同一套编译口径（差分测试逐字节比对），所以它不是"示意文字"。

**预设占位会提醒你**：`标题文字`、`第 3 格画面` 这类预设内容如果不改就排队，
文字框会被**逐字渲染**、宫格会画成一堆雷同的格子。状态栏报数量，点「排队」时若仍有预设文字会先问一次；
后端 `report` 同样会写，纯 API 用法也看得到。

**文字元素有两个框，别填混**

| 字段 | 填什么 | 例子 |
|---|---|---|
| **描述** `caption` | 这个字**长什么样** | 粗体无衬线大标题，浅金色，轻微描边 |
| **文字** `text` | **实际要渲染的字** | 示例标题 |

填反了模型会去画"粗体金色"这几个字。`text` 是唯一会被逐字渲染的字段。

> ⚠ **文字框不要贴边。** 实测：框顶距画布边缘 5% 时，文字向上溢出会被裁掉。
> 预设留的是 10%，但这只比 5% 保守，**不代表 10% 已验证安全**。

### 🎬 提示词 · 草稿编译（`MossPromptCompiler`，不加载模型）

把 OpenMOSS 的 [MOSS-Image Prompt Enhancer skill](https://github.com/OpenMOSS/MOSS-Image/tree/main/skills/moss-image-prompt-enhancer)
接到本包。贴 skill 产出的**草稿**（不是它编译后的结果），得到：

**入参** —— 只有一个多行框 `draft`。两种形态：**caption 草稿** `{"caption": "…"}` 编译成纯文本提示词；
**layout 草稿**（下面那些字段）编译成单行原生布局 JSON。草稿为空会直接报错，不会吐一个空提示词。

- **`prompt`** —— 可直接用的 MOSS 提示词（普通 caption，或单行原生布局 JSON）。
  接到 `CLIPTextEncode.text` 或「生成」节点的 `positive`。
- **`report`** —— 类型、画布、元素数，以及哪些字段无法带进 state。
- **`state`** —— 布局草稿会另出一份 state v3 JSON，可直接粘进布局编辑器的导入框。
  画布须在 64–4096 内；超出时 `prompt` 仍会输出，`report` 说明为什么没生成 `state`。

（节点的输出顺序就是 `prompt` → `report` → `state`。）

草稿要求（官方 schema）：`width` / `height` 是 16 的正整数倍；
`bbox_coord_space="abs"`；`bbox_format="xyxy"`；`summary.caption` 与非空 `items`。
每个元素是 `object` / `character` / `text`；文字元素必须带实际渲染的 `text`。
未知字段、重复键、NaN/Infinity、越界框一律拒绝。本包另加**最多 256 个元素**、
**草稿 1 MB** 两道上限。

skill 本身是外部 Apache-2.0 内容，**不随包分发**；本节点是按官方文档独立实现的。
细节、边界与离线置信度核查见
[提示词编译文档](https://github.com/ZenHG/ComfyUI-MOSS-Storyboard/blob/main/docs/13-prompt-enhancer.md)。

### 🎬 故事板 · 宫格几何（`MossStoryboardLayout`，不加载模型）

输出 9 个口：`width` `height` `columns` `rows` `spec` `layout_json` `template` `report` `elements`

**参数**

| 参数 | 说明 |
|---|---|
| **格数** `panels` | 1–12（常用 3 / 4 / 6 / 8 / 9；其它值自动做整数分解） |
| **单格比例** `panel_aspect` | 10 种：`16:9` `3:2` `4:3` `1:1` `4:5` `3:4` `2:3` `9:16` `21:9` `2.39:1` |
| **单格长边** `panel_edge` | 每格长边像素，默认 512 |
| **缝宽** `gutter` / **外边距** `margin` | 宫格线宽度 / 画布到第一格的距离 |
| **提示词** `prompt` | **留空是对的**：这个节点只算尺寸。填了也只是给 `layout_json` 和 `elements` 用 |

几个输出值得单独说：

- **`width` / `height`**（INT）：画布宽高。接 `EmptyFlux2LatentImage` 的尺寸。
- **`columns` / `rows`**（INT）：实际排法。接「裁格」/「贴回」的同名输入，这两个节点就不用再接 `spec`。
- **`template`**（IMAGE）：宫格模板图，纯色格 + 缝，用来肉眼核对格子位置。**不进采样器。**
- **`spec`**：一串文字，把格数、画布、每格坐标全带上（`MOSS-SB1 panels=4 w=1024 h=576 cols=2 …`）。
  接给下游节点，就绝不会和生成时错位。
- **`layout_json`**：和宿主原生 `MOSS-Image Layout Prompt` **同格式**
  （`summary` + `items`，bbox 是**画布中心原点的绝对像素**）。直接接 `CLIPTextEncode`。
- **`elements`**：画布的**元素**格式（`{type, desc, bbox}`，bbox 是 **0–1000 归一化**、
  `[y0, x0, y1, x1]`）。接到宿主 `Create Bounding Boxes` 的 `bboxes`（这个输入收字符串，
  也收数组 / BoundingBox），就能在画布上看格子、改每格描述。这里的坐标与格子出自同一份计算，
  所以画布上看到的就是实际格位。

  接的时候**必须接三条线**，少一条框就全错：

  ```
  width    → Create Bounding Boxes · width
  height   → Create Bounding Boxes · height
  elements → Create Bounding Boxes · bboxes
  ```

  原因：`elements` 的 bbox 是 0–1000 归一化，画布节点要用 `width`/`height` 把它换成像素。
  画布节点的默认值是 1024×1024；8 格横条画布是 2032×576 ⇒ 不接线就是**静默错框**。

  ⚠ **两套格式不通用。** `elements` 是画布元素（归一化 0–1000）；`layout_json` 是完整布局
  JSON（`summary` + `items`，绝对像素）。互相替换都不能直接读。

  ⚠ **宫格的 `elements` 输出只表达格位**：每格一条 `{"type":"obj"}`，`desc` 是该格描述；
  不含文字元素，也不承载字号/颜色。要渲染画面内文字，走编辑器的「文字元素」或
  `MossPromptCompiler` / 宿主 `MOSS-Image Layout Prompt` 那条路。

  ⚠ **在编辑器里拖框，改不了「生成」节点的出图。** 两条路的输入是分开的：宫格的框由
  「生成」节点自己的格数参数或接进来的 `spec` 算出，编辑器里拖的框只影响**编辑器自己**输出的
  `prompt`。想改出图，改提示词或改格数参数；编辑器那套 `elements` 没有回灌给生成节点的通路。
- **`report`**：给人看的一行总结——格数、画布、像素数、提示词对齐了几段、有没有超像素警告。

### 🎬 故事板 · 生成（`MossStoryboardSampler`）

输出：`grid`（整图）`panels`（逐格）`latent` `spec` `prompt_used` `report` `prompts_json` —— **7 个口**。

- **`prompt_used`**：你**填进去的原始稿**，原样透传出来。它**不是**真正发给模型的话——
  模型看到的每格文本在 `prompts_json`。两个口的分工：
  `prompt_used` 对照「我写了什么」，`prompts_json` 对照「模型看到什么」。

- **`latent`**：整张模式 = 整张画布 latent；逐格模式 = N 个单格 latent 的 batch
  （`{"samples": [N,C,h,w]}`，行主序 = 格号 1..N，**不是拼版**）。接 `VAEDecode` 按 batch 逐张解码。

- **`prompts_json`**：**真的发给模型的那句话**，JSON 数组。「整张」模式 1 条；
  「逐格」模式每格 1 条（含被清掉多格措辞后的全局段）。想复盘"词写的画面做到了没"就从这里接。

并按 **MOSS-Image-SFT 模型卡口径 50 步 / cfg 3 / euler / sgm_uniform** 交付
（装了 4 步 LoRA 时改 4 步 / cfg 1.0）。

| **格数** `panels` | 8 | 没接 `spec` 时生效 |

**`mode`（生成方式）两个选项**

> ⚠ **先分清两个词，它们字面相近、含义正好相反**：
> **「单张」**= 编辑器的 single 模式，一张图**不分格**，几个元素自由布局（海报、封面）；
> **「整张」**= 生成节点的 `整张` 选项，一张画布里**分 N 格**，一次采样出全部格子。
> 下面说的是后者。

| 选项 | 实际做什么 | 什么时候用 |
|---|---|---|
| `整张` | **默认**。一次采样出整张宫格，快 | 只想看个大概、格数多（8/9 格）时 |
| `逐格` | 每格**独立采样**再按坐标拼版，**更慢**（每格一次采样，格数越多越慢） | 要**逐格返工**、或要每格更高像素时 |

> **两条路线各赢一半，别用「谁更一致」一句话推荐**
>
> - **同一张脸 → 整张赢。** ArcFace 余弦：整张 `0.553` > 逐格 `0.479`
>   （单场景、单 seed；同一把尺子、同一批图内的相对比较）。
>   ⚠ 这把尺子在**本域没通过校准**：52 对正样本里 18 对检不到脸（35%），所以**只报数，
>   不当放行判据、不设阈值**。另外**绝对阈值不能跨域套用**：同一批模型画出来的亚洲女性
>   之间互相就有 `0.52` 左右，「>0.5 算同一人」这条经验在这里两个方向都会错。
>   所以本页只给相对高低，不给「多少分算及格」。
> - **单格细节 / 单格返工 → 逐格赢。** 每格独立采样，每格分到的像素更多；
>   一格不对时可以只重做那一格。
> - **其余代理指标方向随场景变，所以不作为推荐依据。** 例如「红帽在四格里的出现比例方差」：
>   双人场景里逐格更统一，换到单人场景方向反过来。这些读数留在
>   [`docs/07`](https://github.com/ZenHG/ComfyUI-MOSS-Storyboard/blob/main/docs/07-consistency.md)，
>   本页不拿它们推荐路线。
> - **速度**：逐格更慢（每格一次采样），格数越多越慢；本包不出秒数。
>
> 机理（**推断，非实测结论**）：整张是一次采样，模型倾向复用同一张脸；逐格是 N 次独立采样，
> 每格像素多，但每次都会重新抽一次脸。所以「一次成型」用整张，「要逐格改稿」用逐格。
>
> ⚠ **口径**：以上数字来自当前默认 **50 步 / cfg 3.0** 的实测
> （[`docs/data/g2-50-3.json`](docs/data/g2-50-3.json)，2026-10-27）。旧版 8 步 / cfg 1.0 / 蒸馏 LoRA 那组
> **不是当前口径、也不能横向比**，只作历史留档在 `docs/07` §二之三。
> 另外：**整张模式要模型真的分格，全局段必须声明宫格** —— 见
> [`docs/15`](https://github.com/ZenHG/ComfyUI-MOSS-Storyboard/blob/main/docs/15-recipe-contract.md)。

**`sample_edge`（采样边长）**

逐格模式最大的优势在这里：单格的**采样**分辨率不受整张宫格尺寸约束。
`1024` = 每格按 1024 长边采样，再缩回最终格子 ⇒ 每格更清晰。

给的是**绝对像素**而不是倍数，与宿主 `Empty Flux 2 Latent` 的心智一致；
也让「画质需求」（采样多大）和「排版需求」（格子多大）互不绑架。

> 实测（4 格 / 16:9）：`496` 偏糊；`992` 明显更清楚；`1984` **反而变松**（构图变散）。
> 所以不是越大越好——**没有单一最优值**，`1024` 只是个稳妥起点。
> ⚠ 这一轮**没测 `1024`**，样本数也没记，所以 `1024` 是**出厂起点、不是测出来的最优**；
> [`docs/07`](https://github.com/ZenHG/ComfyUI-MOSS-Storyboard/blob/main/docs/07-consistency.md)
> 另有一句「`1024–1408` 清楚但色调会漂」，同样只当方向看。

代价是显存与耗时按像素平方涨。`整张` 模式忽略这个参数。

> ⚠ **每格分到的像素会随格数变少**。MOSS 训练在 1–2MP，而 9 格 1:1 时每格只分到
> **0.26MP**——整图看着正常，每格却明显糊。节点的 `report` 会同时报这两个数字。
> 格数多、比例接近 1:1 时，可以试 `逐格` 模式。
> `逐格` 模式下这条告警只看**单格采样画布**（`sample_edge`），不再拿最终格子的大小喊糊——
> 拼版后的整张从不进模型。

**`init`（送提示词的方式）三个选项**

| 选项 | 界面显示 | 实际做什么 |
|---|---|---|
| `auto` | 自动（纯布局） | **默认**。把每格描述转成布局框，纯生成。等价于 `layout` |
| `layout` | 纯布局 | 同上，显式写法 |
| `plain` | 纯提示词 | **整张模式**：整段提示词直接送模型，不转布局框（仍按宫格画布生成）。**逐格模式**：每格发「清掉多格措辞的全局段 + 本格描述」，不是原样整段——为的是保住角色/风格锚点 |

> **本包不做图生图。** 起点恒为空 latent，`denoise` 留 1.0。
> 实测过「拿模板 latent 当起点」这条路：35 步 / 降噪 0.85 → 纯黑；12 步 / 0.6 与 4 步 / 0.5 → 模板残影。
> **为什么，我们没有单独测**（只测到这三个现象）。模板图只作为 `MossStoryboardLayout` 的一路
> `IMAGE` 输出，用来肉眼核对格子位置，不进采样器。
> 想改一张**已有图**的内容，看后面的「🎬 故事板 · 贴回」——那条路是通的，而且不用重跑整张。

> 为什么 `negative` 收起来：它是**可选**输入，默认留空；MOSS-Image-SFT 模型卡的 `cfg=3 > 1`，
> 填了就会进负面分支。收进「高级」只是不让它看起来像必填项。
> 只有把 `cfg` 降到 `1.0` 时，ComfyUI 才会**直接跳过负面分支**（那段不进计算图）。

### 🎬 故事板 · 裁格（`MossStoryboardCrop`）

**输入**（只有 `image` 必接，其余能留默认）：

| 输入 | 默认 | 说明 |
|---|---|---|
| `image` | — | **必接**。整张宫格图（`KSampler → VAEDecode` 的结果） |
| `spec` | 空 | 接「生成」或「宫格几何」的 `spec` ⇒ 裁切位置与生成时逐像素一致。**不接就得手填 `columns`/`rows`** |
| `columns` / `rows` | 0 / 0 | 没接 `spec` 时**必填**；填 0 会直接报错，不会瞎猜 |
| `index` | -1 | `-1` = 输出全部格子；填 0 起的格号 = 只输出那一格，并把格号送到 `index` 输出 |
| `shave` | 0 | 每格四边内缩像素，吃掉溢出的缝。改了就要在「贴回」用同样的值 |
| `resize_edge` | 0 | `0` = 保持原尺寸（推荐）；`>0` = 把每格长边缩到该值 |
| `target_aspect` | `keep` | 保持单格原比例（零重采样）；选具体比例会做中心裁切 |
| `padding_mode` | `crop` | `crop` = 裁掉多余边；`pad` = 补黑边（不丢画面） |
| `show_guides` | 关 | 高级项。在 `preview` 上把裁切线画成红色，用来目检 |

**输出**：`panels`（逐格 `IMAGE`）`preview`（整图原样）`report`（切了几格、每格坐标）`index`（格号）

- 接 `spec` ⇒ 与生成时逐像素一致。
- 不接 `spec` ⇒ 按**列数 × 行数**整除图像；除不尽**直接报错**，不会凑出差 1 像素的格子。
- **`index` 填 -1（默认）= 输出全部格子**。填 0 起的格号 = 只输出那一格，
  同时把格号送到 `index` 输出上 —— 接给「贴回」节点就不用手打格号。

### 🎬 故事板 · 贴回（`MossStoryboardPaste`）

**输入**：

| 输入 | 默认 | 说明 |
|---|---|---|
| `grid` | — | **必接**。整张宫格图（「生成」的 `grid`，或上一级「贴回」的输出） |
| `panel` | — | **必接**。改好的那一格（单张）。接「裁格」只取一格后的输出最稳 |
| `index` | 0 | 贴到第几格，**0 起、行主序**。接了「裁格」的 `index` 输出就以它为准，不会错位 |
| `shave` | 0 | **必须与裁格时一致**，见下 |
| `spec` | 空 | 接上才与生成时逐像素一致；不接就得手填 `columns`/`rows` |
| `columns` / `rows` | 0 / 0 | 没接 `spec` 时必填 |
| `show_guides` | 关 | 高级项。在 `marked` 上把贴回区域框成纯红，用来目检贴进了哪一格 |

**输出**：`grid`（改好的整张宫格）`marked`（调试用，把贴回区域框红）`report`

**用途：只改一格，不重跑整张。** 某一格不对时，重跑整张会把**所有格的种子**一起动掉。
正确的做法是：把那一格裁出来 → 用你习惯的编辑方式改好 → 用本节点
按 `spec` 的坐标贴回去。

- **`index` 从 0 起、行主序**（从左到右、从上到下）。接了裁格的 `index` 输出就以它为准，
  不会和"裁的是哪一格"对不上。
- **只动目标格的内容区**：缝和外边距一个像素都不碰，宫格线保持原样，其它格完全不变。
- **`shave` 必须与裁格时一致**。裁格和贴回都会把格子四边各内缩 `shave` 像素；
  不一致时源图尺寸与目标矩形不符，会走 **bicubic 重采样**（内容被缩放、边缘多/少一圈），
  不是「整体偏移 s 像素」。`report` 会明确写「已重采样」，请照它对账。
- **输入尺寸和格子不一致时会重采样**，并在 report 里出声。要逐像素一致：
  裁格的 `resize_edge=0`、`target_aspect=keep`、`shave` 与本节点相同。
- **想改多格就串联多个本节点**：第一个的输出 `grid` 接第二个的输入 `grid`，各改各的格。

> 现成工作流：`examples/moss-storyboard-4panels-edit.json`（需要 `Moss-Image-Edit` LoRA / 编辑节点；节点内有说明）。

**推荐接法**（格号全程不用手打）：

```
裁格（index 填要改的那格）─panel─→ 你的编辑流程 ─→ 贴回
裁格 ──index──────────────────────────────→ 贴回
生成 ──grid────────────────────────────────→ 贴回
生成 ──spec────────────────────────────────→ 贴回 / 裁格
```

#### 「你的编辑流程」怎么搭（可选，本包自身不需要任何 LoRA）

本包只负责几何：裁出来、贴回去。**中间那一步编辑用什么，随你**——可以用任何你熟悉的
工具（其它节点包、外部修图、甚至手改后重新载入）。

如果你想直接用 MOSS 自己的指令编辑，宿主的官方节点就能做，不需要装第三方节点包：

```
裁格(index) ──→ Text Encode MOSS-Image Edit ──→ KSampler ──→ VAEDecode ──→ 贴回
                     ↑ 需要下面这个 LoRA
```

做法：

1. 下载社区编辑 LoRA **Moss-Image-Edit**（约 285 MB，bf16，rank 64）——
   两个源任选，文件相同：
   - Hugging Face：<https://huggingface.co/chinoll/Moss-Image-Edit>
   - 魔搭 ModelScope：<https://www.modelscope.cn/models/ChenkinLab/Moss-Image-Edit>
2. 把 `adapter_model.safetensors` 和 `adapter_config.json` 放到
   **`models/loras/Moss-Image-Edit/`**（新建这个子目录，两个文件放一起）。
3. 工作流里用宿主的 **`Text Encode MOSS-Image Edit`** 节点：
   - `clip` 接你的 CLIPLoader（`type=moss_image`）
   - `images` 接裁出来的那一格
   - `edit_format` 选 `Moss-Image-Edit`
   - **`vae` 可以不接**：不接时参考图只进文本编码器，更省显存，也不会把参考图的空间结构
     强加到结果上。接了就会额外用参考 latent，构图保持更强但更吃显存。
4. 后面接普通 `KSampler` → `VAEDecode` → 本包的「贴回」。这条链由社区编辑 LoRA 驱动，
   官方底模默认口径不适用：本机实测 **30 步**（cfg 的取值我们自己的记录前后不一致，
   这里不写死）；再叠 4 步蒸馏 LoRA 时用 **8 步 / cfg 1.0**。

**它能做什么、不能做什么**（实测）：改颜色、服装、光照、风格——这些指令服从度好。
**季节没测过，不承诺。** 不接 `vae` 时参考图只进文本编码器，构图保持会更弱
（**机理推断，没有单独做对照**）。**它不擅长"换个机位重新画"**，那还是得走布局提示词重新生成。

⚠ **它不是跨格一致性方案，本包也不承诺跨格一致性。** 它的定位是**单格微调**：
改一格的颜色、服装、光线，改完贴回。拿它把某一格往其它格靠，实测会让每格越来越像同一张图
（景别趋同），而故事板要的是「同一角色、不同景别」。

> **许可与边界**：这个 LoRA 是第三方社区权重，**不随本包分发**，也不由本包维护。
> 其模型卡标注代码部分为 GPLv3，权重许可以模型卡为准。本包只在使用文档里指向它，
> 不复制、不修改、不分发任何权重文件。本包自身（MIT）不依赖它——不下载也能完整使用
> 故事板生成与贴回。

### 🎬 故事板 · 换脸（`MossStoryboardFaceSwap`）

参考图的脸 → **一格**（或一张单图）。与包内其他节点一样是 **MIT**。

| | |
|---|---|
| `ref` → vision 通道 | 决定**是谁**。`vision_megapixels` 默认 `1.05`（宿主默认 `0.147` 时参考图只值约 `0.008`，等于没给） |
| `image` + `prompt` → 图生图 | 决定**画什么**。提示词要提到参考图（`in Picture 1`），前缀由节点拼 |
| `spec` + `index` | 只换那一格——缝、外边距、其他格逐像素不变（实测 `max&#124;Δ&#124; = 0`） |
| `auto_mask` | **默认开。** insightface 自动找脸并生成蒙版。依赖缺失**直接报错**，不静默降级 |
| `face_pick` | `largest` / `left` / `right`。一格有几个人时点名；`report` 写「几张脸、用了哪张」 |
| `mask` | 可选，手接蒙版覆盖自动结果。接了就以手接的为准 |
| `init` | **`source`**（默认）= 吃 `image` 做图生图，有蒙版就只重画蒙版内；**`empty`** = 不吃 `image`，从空 latent 开始——参考图 + 提示词 → 一张新图 |

**蒙版是「修图」和「重画」的分界。** 接了蒙版只重画蒙版内，蒙版外逐像素保留（实测 `mean&#124;Δ&#124; 0.40/255`）；既没接线、又关掉 `auto_mask` 才是整格重画，色调必漂（`R +24 … +53`）。`report` 会写明实际走了哪条。

**蒙版长什么样。** 是**羽化矩形**，不是贴脸轮廓：上沿 `eye_y + 0.30 × (nose_y − eye_y)`，下沿 `y2 + 0.06 × h`，左右各外扩 `0.05 × w`，羽化 `max(3, 0.02 × w)`。**白 = 重画。** 给整张宫格的蒙版也行——节点按 `index` 用与图像同一套整数坐标裁到目标格。

**手接蒙版怎么写。** `ImageToMask(channel="red")` → `mask`。**别用 `LoadImage` 的 `MASK` 口**：那是 alpha，灰度图没 alpha 时返回 64×64 全零，蒙版等于没接、整格被重画，而且不报错。样张：`assets/faceswap-mask-example.png`。

**自动蒙版：装什么、权重放哪**

| | |
|---|---|
| 安装 | `pip install insightface onnxruntime` —— 装进**跑 ComfyUI 的那个 Python** |
| 权重 | `~/.insightface/models/buffalo_l/det_10g.onnx`（19 MB） |
| 只要这一个 | 节点只加载 `detection`，`w600k_r50.onnx`（174 MB，识别用）**不需要** |
| 想放别的盘 | 设 `MOSS_INSIGHTFACE_ROOT=<根目录>`，权重放 `<根目录>/models/buffalo_l/` |
| 下载 | <https://github.com/deepinsight/insightface/releases/download/v0.7/buffalo_l.zip>（把 `buffalo_l/` 解到 `models/` 下） |
| 自查 | 节点**不会自己联网下载**：权重缺失时报错里会打印它实际找的那个路径 |

本机其他检测轮子，以及本节点为什么不用：

| 轮子 | 给什么 | 权重位置 | 本包 |
|---|---|---|---|
| insightface `buffalo_l` | 框 + 5 关键点 | `~/.insightface/models/buffalo_l/` | **用**——与实测过的 E26 配方同源 |
| mediapipe face mesh | 478 点轮廓 | 随包，在 `site-packages/mediapipe/modules/`（55 MB） | 不用——轮廓更贴不是瓶颈 |
| facexlib BiSeNet | 分区解析（皮肤/眉/眼/鼻/嘴/发） | `site-packages/facexlib/weights/parsing_bisenet.pth` | 不用——语义最好，但多一个依赖且增益未测 |
| SAM | 精分割，要提示点/框 | 手动下 `sam_vit_*.pth` | 不用——要提示 + 权重大，增益未测 |
| ultralytics YOLO | 只有框 | 手动下载 | 不用——没关键点，还得自己缩 |

**姿态与肢体动作：都能动，把 `init` 设成 `empty`。** 七档头部姿态 + 九档肢体动作，测的是**生成**路径（空 latent + 参考图进 vision）。默认 `init=source` 时本节点是蒙版后的图生图，身体在蒙版外、提示词动不了它。每次只改一个变量：

| 测了什么 | 结果 |
|---|---|
| 头部 yaw，参考图**正脸** | 成立。一句提示词把 yaw 从 `+0.05` 推到 `+1.48`，近正侧、低头、仰头都出来了 |
| 头部 yaw，参考图**侧脸** | 不成立。参考图 yaw `+5.20`，七档提示词全画成侧脸 ⇒ **姿态跟参考图走，不跟提示词走** |
| 肢体动作（站立 / 插兜 / 抱胸 / 走 / 前伸 / 坐 / 转身 / 手抵下颌 / 背身回看） | 九档全部生效。净损失 `−0.086 … +0.112`，**九档里七档在 ±0.05 以内**（采样地板量级） |
| 躯干转侧、头仍朝镜头 | `+0.036`，没受损 |
| 背对镜头、回头看向肩后（yaw `0.76`） | `−0.086` ⇒ 伤脸的是**连带转头**，不是身体 |

⇒ **要换姿态：参考图给正脸，`init` 设成 `empty`，姿态写在提示词里。** 参考图本身是侧脸，输出就被锁在侧脸，提示词拉不回来。只动身体时，让头继续朝镜头。两套梯度提示词与判据：[`docs/17`](https://github.com/ZenHG/ComfyUI-MOSS-Storyboard/blob/main/docs/17-faceswap-recipe.md) §九。现成示例：`examples/moss-pose-generate-ui.json`（9 个节点，`init=empty`，**不依赖任何第三方节点**）。

配方：先 8 步 DMD2 LoRA、再 Moss-Image-Edit LoRA · 8 步 / cfg 1.0 / euler + simple · 参考图**只给一张**（双视角实测更差）。完整配方与判据：[`docs/17`](https://github.com/ZenHG/ComfyUI-MOSS-Storyboard/blob/main/docs/17-faceswap-recipe.md)。

**仍然做不到的**：一格两个人（各约 68px，两张都被换、彼此散开）、连续换两次（第二次像素级空转）、用提示词把侧脸参考图拉回正脸。本页不发布「像不像」的分数——本域余弦没有分辨力。试过哪些旋钮、为什么都留在默认值：[`docs/16`](https://github.com/ZenHG/ComfyUI-MOSS-Storyboard/blob/main/docs/16-faceswap-refactor.md)。

示例：`examples/moss-faceswap-ui.json`。

### 实测通过的

**下表每一行都标注了所用的 LoRA 与步数配置。** 官方底模的推荐口径见文末说明。

| 项 | 配置 | 结论 | 抽查 |
|---|---|---|---|
| 3/4/6/8/9 格 · 横竖 · 无缝 · 粗缝 · 小画布 · `plain` | 官方底模 + 4 步 LoRA / **4 步** | 尺寸与理论值逐像素一致 | 16 例（端到端矩阵真跑） |
| 宫格线 | 同上 | 复绘后缝与外框纯白 | 每例 |
| 随机种子 | 同上 | 换种子 → md5 不同 | 2 次 |
| **元素框限定构图** | 官方底模 + 4 步 LoRA / **4 步**；官方底模 + 8 步 LoRA / **8 步** | 只换框：自行车从"被裁掉"变成"完整在左下角"；3 个 seed 复现 | 36 张 |
| **文字四字**（1024×576） | 官方底模 + 8 步 LoRA / **8 步** | 四字中文标题全对 | 2 个 seed |
| **文字四字**（2048×1152） | 官方底模 + 4 步 LoRA / **4 步** | 全对，笔画略软 | 2 个 seed |
| **文字四字**（2048×1152） | 官方底模 + 8 步 LoRA / **8 步** | 全对，笔画锐利 | 2 个 seed |
| **中英混排 / 两行 / 指定颜色** | 官方底模 + 8 步 LoRA / **8 步** | 全对；换行被尊重；红色生效 | 2 个 seed |

> **只用官方底模、不叠 LoRA 的配置**：跑过一张 2048×1152 / 30 步 / cfg 3.5 的对照
> （在默认值对齐官方模板之前），出图正常，但**没有逐字核对文字**，所以不作为结论。这一档需要你自己验证。

### 文字：能到哪、到不了哪

| 项 | 结论 | 配置 |
|---|---|---|
| 分辨率 | 1024×576 已够；2048 只是笔画更锐 | 8 步 LoRA / 8 步 |
| 步数 | 4 步可用但边缘软；8 步明显更锐；16 步与 8 步接近，收益递减 | 对应 LoRA |
| 字号 | 框高到画布 1/20 仍全对（1536×864 上约 43px，2048×1152 上约 58px） | 1536×864 与 2048×1152 |
| 换行 | `text` 里的 `\n` 被尊重，两行各自成型 | 2048×1152 / 8 步 |
| 颜色 | `palette: ["#d92b2b"]` 生效 | 2048×1152 / 8 步 |
| **框高控不住字号** | 43px 高的框，实际字高约 130px，**字会溢出框**。⚠ 我们没法给出「框要多宽才够」的阈值：实测里两个**尺寸完全相同**的文字框（169×60、4 个字、每字约 42px），一个清楚、一个只剩淡痕 —— 所以**宽度不是判据**。唯一确定的差别是**离顶边的距离**（47% vs 6%，后者贴顶被裁）。可行的做法：留足上边距，按实测调文案长度 | — |
| **贴边会被裁** | 框顶距边缘 5% 时，字向上溢出被画布切掉，2 个 seed 都出现 | 2048×1152 / 8 步 |

> 样本量很小（每项 2 个 seed）。「四字全对」在多组配置下重复出现，但**不作保证**；
> 「贴边被裁」只在红色那组复现过，**其他颜色没测**，保守做法是一律留边。
> 预设把文字框留在 10%，**10% 是否足够安全同样没验证** —— 它只是比 5% 更保守的起点。

### 这一版做不到的

- 🔴 **不做图生图。** 本包只从空白画布生成。要拿参考图改已有画面，用宿主的
  `Text Encode MOSS-Image Edit`（见「🎬 故事板 · 贴回」一节），那是另一条链路。
- ⚠ **步数与 cfg 按加载的 checkpoint 的官方模型卡配。**
  SFT（本包交付的 checkpoint）与 Base 的模型卡都是 **50 步 / cfg 3 / euler**
  （SFT：[ModelScope 模型卡](https://www.modelscope.cn/models/openmoss/MOSS-Image-SFT)；
  Base 官方 CFG 范围 3–6）。模型卡另写 shift 5（原生 ComfyUI 模型已内置）与
  SLG 负分支层 22（需接宿主 `SkipLayerGuidanceDiTSimple`，`single_layers` 填 `22`；
  本包示例未接）。ComfyUI 原生模板另用 25 步 / cfg 2.5 / er_sde（Comfy-Org 的选择），
  不是模型卡配方。叠加 4 步蒸馏 LoRA 时用 **4–8 步 / cfg 1.0**——蒸馏 LoRA 就是按 cfg 1 蒸的，
  调高会破坏蒸馏效果。把蒸馏 LoRA 和底模配方混搭（例如叠了 LoRA 却用 50 步 / cfg 3）
  不会报错，只是白跑一次（有时整张发黑）。
- ⚠ **`denoise` 请留 1.0。** 它没有任何图像可参考，调低只会截断 sigma（少跑几步）；
  `report` 会打印「名义 / 实际」，以实际值为准。
- **每格画什么只是「大体照办」。** 布局框是文字建议，不是选区——见 [布局框只是参考](#布局框只是参考不可能指哪打哪)。
  MOSS 的布局能力官方标 *experimental*，本包没做成片评分。
- **不承诺人物身份一致性。给的是换脸工具，不是保证。** 跨格是不是同一张脸仍由模型采样决定，
  本包不承诺。本包提供的是一个**工具**：「🎬 故事板 · 换脸」把参考图的脸换进**一格**
  （见该节点章节）——一次一格、靠参考图驱动，**不等于**「先定一张角色卡、再逐格派生」那条链；
  那条链仍要额外的独立节点包，不在本包，也不随本包安装。
- **8/9 格每格偏小**：交付工作流的 496 档约 496×272，出厂 512 档约 512×288。
  小字、细纹理最先糊——这是分辨率账，不是节点 bug。

### 硬约束

- 画布与单格的宽高必须是 **16 的倍数**（节点已强制；手改 `spec` 会被拒绝）。
- 整图超过 2 百万像素会提示，超过 4 百万像素会强提示：MOSS 训练在 1–2 百万像素，官方外推约 4 百万。
- **VAE 的解码精度由 ComfyUI 决定，不由权重文件决定。** 宿主加载 VAE 时会把它统一转到
  `fp16`（或你的 GPU 不支持时退到 `bf16`/`fp32`），所以 `flux2-vae.safetensors`（F32）
  和 `flux2-vae_BF16.safetensors`（BF16）**跑起来是同一精度**（速度我们没有单独测过）——
  文件里的 dtype 在加载时就被归一化了，只剩磁盘占用和加载内存的差别。想要真正的 fp32 解码，
  用宿主的启动参数 `--fp32-vae`，本包不做第二套精度逻辑（那会和宿主的 `VAEDecode` 行为分叉）。
  另外一个通用的绕法：本包「生成」节点有 `latent` 输出，接你自己的 `VAEDecode` 节点，
  用什么 VAE、什么精度都随你。

## 常见问题

> 报错原文对照表在 [出问题先查这里](#出问题先查这里)，先去看那张表。下面是其余问答。

**Q：跑到 VAE 解码就 OOM，或者出图有淡淡的横向接缝。**
两者是同一件事：显存不够 → 宿主退回分块解码 → 分块边界留下接缝。先看日志有没有
`retrying with tiled VAE decoding`。有的话按 [显存要多少](#显存要多少) 处理；
最省事的一步是 `git pull` 更新宿主（旧版把 VAE 解码显存算成了实际的 4 倍）。

**Q：跑出来一片黑。**
先看 `report` 的「降噪 名义/实际」和步数。最常见的原因是**配方配错了**：装了 4 步蒸馏 LoRA
却用了 50 步 / cfg 3，或者没装 LoRA 却用了 4 步 / cfg 1.0。按「这一版做不到的」里的配方说明配。

**Q：格子数量对，但内容串了 / 全挤在一格里。**
布局框只是参考，模型可能不照办（见 [布局框只是参考](#布局框只是参考不可能指哪打哪)）。
先把每格描述写短、写具体（一个镜头一句话），
再检查 `report` 里"解析了几段面板描述"是否等于格数。

**Q：生成出来的图和预览的宫格形状不一样。**
检查是否同时接了「宫格几何」的 `spec`；接了就以 `spec` 为准，采样器上的格数参数会被忽略。

**Q：找不到节点。**
节点在 `moss/storyboard` 分类下。搜索框打 `故事板`、`storyboard`、`宫格` 都能找到
（本包注册了中英搜索别名）。还是找不到，先看启动日志有没有 `[MOSS SB]` 那行。

**Q：没有「中 / EN」按钮。**
① 刷新浏览器（F5）；② 确认只有本包节点上才有按钮，官方节点不会有；
③ 控制台看有没有 `[MOSS SB] i18n: 就绪`，没有就确认前端文件是否正常加载。

**Q：能不能用我自己的负面提示词？**
能。默认 `cfg=3.0` 已经 >1，展开「高级」填写即可；只有把 `cfg` 调到 `1.0` 时它才不进计算图。

**Q：能不能只生成一张普通图，不分格？**
用「布局编辑器」的单张模式（推荐），或在「生成」上把 `panels` 设为 1。
`init=plain` 只改提示词送法，不取消宫格几何。
